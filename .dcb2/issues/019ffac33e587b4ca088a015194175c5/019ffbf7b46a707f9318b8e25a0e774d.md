# Design brief

## Problem

At compiler HEAD 51093e0a8e31fe45a9aa79a317fbefd6b74fbcc3, native programs lack the CLI capabilities exposed by darklang/dark 04fbe9dcc995c6188757d583e273cbd30a3e2d3d: process execution and management, host and system discovery, and structured keyboard input.

## Goals

- Match the interpreter’s public observable behavior across the complete requested CLI scope.
- Provide typed, composable results for process lifecycle, output, failures, platform identity, system data, and keyboard events.
- Record exact revisions and current source or same-source probe evidence for every parity finding.
- Classify unsupported hosts, compiler-only extensions, and intentional divergences explicitly.

## Proposed solution

Introduce one coherent platform-services family with shared public models, native macOS and Linux adapters, and higher-level composition for command execution, process lifecycle, pipelines, environment and working-directory control, timeouts, host and system queries, and keyboard input. Treat the pinned interpreter revision as the behavioral contract, preserving observable output, exit status, failure, termination, and input behavior while representing unavailable or platform-specific behavior explicitly rather than guessing. Maintain a revision-pinned parity record linking each retained gap to current source evidence and focused probes where practical.

## Success criteria

- Same-source programs can use the entire requested capability family on supported native targets.
- Observable results match the pinned interpreter baseline for successful execution, failures, process state transitions, discovery values, and keyboard input.
- Every comparison identifies compiler HEAD 51093e0a8e31fe45a9aa79a317fbefd6b74fbcc3 and darklang/dark revision 04fbe9dcc995c6188757d583e273cbd30a3e2d3d.
- All compiler-only behavior, unsupported environments, and intentional differences are documented as explicit classifications.
- The full compiler test suite passes without changing unrelated language behavior.

## Open questions

- Should interpreter-visible host variants beyond the compiler’s current macOS and Linux targets remain representable with explicit unsupported behavior, or be omitted until those targets exist?
