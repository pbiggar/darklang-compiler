# Trial result

Retained conservative join-local scalar PRE reduces the redundant path from two generated adds to one while preserving the non-redundant path and all tested barriers. Canonical routine benchmark: equal.

## Evidence

## Important changes

- **Added join-local scalar PRE to MIR CSE** — **Reason:** dominator-only CSE could not reuse expressions available on only one predecessor.
- **Restricted PRE to typed integer and Boolean binary expressions on dedicated acyclic edges** — **Reason:** this provides explicit type and dominance safety without speculative execution.
- **Excluded floating point and effect boundaries** — **Reason:** preserve IEEE-754 evaluation behavior and prevent motion across calls, allocation, memory, reference-count, or exceptional operations.
- **Added focused MIR and LIR regressions** — **Reason:** prove partial redundancy removal, generated-add reduction, non-redundancy, and barrier behavior.
- **Documented retained and neutral evidence** — **Reason:** record that the direct MIR fixture improves while a structured source probe was already optimized earlier in the pipeline.

## How it works

The pinned baseline confirmed that dominator-tree CSE retained an add in the join when the same expression was available on only one predecessor. A structured source-level probe was neutral because existing earlier cleanup already optimized that form, so it was not claimed as benchmark coverage. The retained transformation handles the direct MIR opportunity conservatively: all predecessors must be dedicated jumps, operands must dominate every insertion point, the join must be acyclic, and availability must be genuinely partial. Floating-point expressions were rejected instead of risking NaN, exception, or operand-order changes. The pass processes one candidate per CSE fixed-point iteration. Its main residual risk is additional phi live-range or copy pressure, although the focused LIR proof confirms the targeted arithmetic work decreases.

## Algorithm

1. Build predecessor, immediate-dominator, and SSA-definition maps.
2. Examine the first non-phi instruction of each join for an eligible typed binary expression.
3. Require at least two dedicated, acyclic jump predecessors and prove both operands dominate every predecessor.
4. Scan predecessor exports, clearing availability at calls, allocation, memory, ownership, runtime-error, and other barriers.
5. Continue only when the expression is available on at least one but not all predecessors.
6. Insert the expression with its original operand order on missing predecessors.
7. Replace the join computation with a correctly typed phi selecting existing or inserted values.
8. Let the existing optimization fixed point perform copy propagation, dead-code elimination, and CFG cleanup.
