# Design brief

## Problem

At compiler 51093e0a8e31fe45a9aa79a317fbefd6b74fbcc3, UUIDs are strings, canonical parsing is absent, and the parse error shape diverges from interpreter 04fbe9dcc995c6188757d583e273cbd30a3e2d3d.

## Goals

- Match the recorded interpreter’s public UUID behavior.
- Provide canonical parsing with only BadFormat failures.
- Preserve UUID as a distinct runtime value through parsing, generation, and string conversion.
- Classify retained compiler-only extensions and intentional divergences explicitly.

## Proposed solution

Introduce a dedicated UUID runtime representation and align canonical parsing, generation, conversion, and error behavior with interpreter 04fbe9dcc995c6188757d583e273cbd30a3e2d3d. Treat the existing versioned parsing surface as a compiler-only extension if retained, never as the parity implementation, and remove the additional error case from the canonical contract.

## Success criteria

- The same valid and invalid inputs produce equivalent observable parsing results in both recorded revisions.
- Malformed input can produce only BadFormat.
- Parsed and generated UUIDs remain distinct from strings until explicitly converted.
- Generation and textual conversion match interpreter-visible behavior.
- Any remaining compiler-only UUID behavior is documented as an extension or intentional divergence.
