# Design brief

## Problem

At compiler HEAD 51093e0a8e31fe45a9aa79a317fbefd6b74fbcc3, compared with interpreter baseline 04fbe9dcc995c6188757d583e273cbd30a3e2d3d, UUIDs are String-backed, canonical parsing is absent, and parsing exposes an additional error case beyond BadFormat.

## Goals

- Match the recorded interpreter’s public UUID behavior.
- Provide canonical parsing whose only failure is BadFormat.
- Preserve UUID as a distinct runtime value through parsing, generation, and explicit string conversion.
- Classify any retained compiler-only behavior as an extension or intentional divergence.

## Proposed solution

Reuse the interpreter’s UUID type and implementation where compatible; otherwise introduce an appropriate dedicated 128-bit runtime representation, preferably UInt128. Align parsing, generation, and canonical textual conversion with the interpreter baseline, while keeping any legacy parsing surface separate from the parity contract.

## Success criteria

- The same valid and invalid inputs have equivalent observable parsing results at the recorded revisions.
- Malformed input can produce only BadFormat.
- Parsed and generated UUIDs remain distinct from strings until explicitly converted.
- Generation and textual conversion match interpreter-visible behavior.
- Any remaining compiler-only UUID behavior is explicitly documented as an extension or intentional divergence.
