# Trial result

The specialization correctly eliminates quicksort’s targeted closure allocations and indirect predicate calls, but its deterministic quicksort gain is only 0.63%, so it is retained as a coherent optional candidate rather than a material improvement.

## Evidence

## What changed

Added bounded ANF pass 2.4.4 for known higher-order specialization, integrated it after ANF inlining, exposed reusable ANF temp-use predicates, documented the pass, added a recursive pass-level optimization fixture proving direct calls and generic-path retention, and added a captured List.filter E2E regression.

## How it works

Profiling the canonical 5,000-element workload showed 2,772 partitions, 8,316 pivot-capturing closure allocations, and 205,467 indirect predicate calls. The existing capture-free devirtualizer could not handle captures, and the inliner excludes closure-containing functions. The retained pass clones only statically known ClosureAlloc targets, validates capture shape and helper use, bounds clone size and pair count, and preserves the original generic helper. A trial that reran the general inliner after specialization produced exactly the same instruction count and was reverted. A focused captured-filter test caught a capture/value argument-order mistake before final validation. Residual risk is broader compiler exposure from a general ANF transformation, mitigated by conservative validation, bounded cloning, retained generic paths, and focused closure tests; repository-wide validation was intentionally stopped because the measured quicksort gain was not material.

## Algorithm

1. After inlining, track locally allocated closures by temporary ID, recording their target and capture atoms. 2. For each direct helper call receiving such a closure, validate that the helper and target are present, the closure tuple types match the captures, the target only reads captures, the helper uses the function parameter only for closure calls or recursive propagation, arities match, and body sizes are within bounds. 3. Deduplicate requests by helper, target, and argument index; reject name collisions and limit the program to 16 specialized pairs. 4. Clone each closure target without its hidden closure parameter, adding typed capture parameters before value parameters and replacing closure-tuple accesses with capture parameters. 5. Clone each helper without its function parameter, appending capture parameters; replace ClosureCall with a direct call to the specialized target and recursive helper calls with calls to the specialized helper. 6. Rewrite known call sites to pass captures directly, dropping a closure allocation only when no remaining expression uses it. 7. Leave the original helper, target, and unknown-closure calling convention intact.
