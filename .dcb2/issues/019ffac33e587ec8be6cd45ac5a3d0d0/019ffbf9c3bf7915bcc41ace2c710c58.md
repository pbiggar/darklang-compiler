# Design brief

## Problem

At compiler revision 51093e0a8e31fe45a9aa79a317fbefd6b74fbcc3, the CLI presentation family is absent, while darklang/dark revision 04fbe9dcc995c6188757d583e273cbd30a3e2d3d provides the parity baseline for logging, styling, progress, prompts, spinners, and tables.

## Goals

- Make scoped CLI presentation programs portable between the interpreter and native compiler.
- Match the interpreter’s public signatures, return values, input handling, output streams, emitted terminal sequences, formatting, and cleanup behavior.
- Explicitly classify any compiler-only extension or intentional divergence.

## Proposed solution

Deliver one coherent CLI presentation family backed by shared terminal input, output, styling, cursor-control, and timing capabilities. Reproduce the baseline’s observable behavior across all scoped presentation features, keeping related API and behavioral differences together and introducing native-specific behavior only when explicitly classified.

## Success criteria

- The complete scoped family is available from native-compiled programs.
- For identical source, input, and terminal conditions, compiler and interpreter runs produce equivalent observable output and results.
- Interactive and animated operations terminate cleanly and leave the terminal in the baseline state.
- Every retained difference is identified as parity, a compiler-only extension, or an intentional divergence against the recorded revisions.

## Open questions

- Must redirected or non-interactive execution match the baseline byte-for-byte, or should terminal detection and cleanup differences be intentional native divergences?
