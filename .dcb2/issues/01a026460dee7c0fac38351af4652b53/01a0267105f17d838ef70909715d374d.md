# Design brief

## Problem

The compiler exposes two independently maintained parsers and syntax modes, allowing grammar drift from the interpreter.

## Goals

- Use `InterpreterParser` as the sole source-to-AST parser.
- Remove compiler-syntax selection from public APIs, CLI, runners, formatters, and tests.
- Preserve compiler functionality by migrating repository-owned sources and fixtures to interpreter syntax.
- Make interpreter syntax parity the only supported parsing contract.

## Proposed solution

Delete the legacy `Parser` module and collapse `CompilerLibrary.SourceSyntax` to one interpreter-compatible path. Remove CLI syntax-selection flags and compiler-only pretty-printing. Convert or retire compiler-syntax fixtures, E2E inputs, formatting tests, and documentation so every supported source is parsed and rendered through interpreter syntax. Retain and strengthen upstream/interpreter corpus coverage as the regression boundary.

## Success criteria

- `passes/1_Parser.fs` is no longer compiled or referenced.
- There is one public parse entry path, backed by `InterpreterParser`.
- The CLI no longer accepts or advertises compiler syntax.
- All checked-in language sources and test fixtures use the remaining syntax.
- The full test suite passes with no compiler-syntax mode or parser references remaining.
- Upstream/interpreter E2E and syntax corpus coverage remains green.
