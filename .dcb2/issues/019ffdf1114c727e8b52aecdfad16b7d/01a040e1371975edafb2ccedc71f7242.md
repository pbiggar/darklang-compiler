## Problems

Avoid preserving caller-saved values that are dead after the recursive nqueenSolve call.

## Solution

Post-call liveness retains only the recursive result and accumulator in callee-saved registers; X1/X2 are dead after the call and require no preservation. Argument parallel moves and recursive-call ABI operands remain unchanged. Because baseline and candidate are the same commit, no focused performance gain can be attributed to this trial.

## Implementation

- No files changed; the preserved candidate already emits empty `SaveRegs([], [])` and `RestoreRegs([], [])` around the hot recursive `nqueenSolve` call.
- Accounted for both batched work items without attributing an unexpected standalone item.

### Algorithm

1. Allocate loop-carried nqueen state to callee-saved X21–X26.
2. Form recursive arguments in X0–X5 with ArgMoves.
3. Emit an empty caller-save bracket because no caller-saved value is live after the call.
4. Receive the result in X0, copy it to X19, add it to X26, and continue the loop.

### Example

Allocated nqueen LIR changes from the historical `SaveRegs([X1, X2], []) ... RestoreRegs([X1, X2], [])` shape to `SaveRegs([], [])`; `ArgMoves` still supplies X1/X2, then `X19 <- Call(...)`, `X19 <- Mov(Reg X0)`, and `X26 <- Add(X26, Reg X19)`, demonstrating X1/X2 are argument-only and dead in the continuation.
