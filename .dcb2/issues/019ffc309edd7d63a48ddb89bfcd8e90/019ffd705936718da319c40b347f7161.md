# Design brief

## Problem

At compiler b2e1f3d1e4ce0338d4c4662db9a1326f2e2cb899, the remaining public callable surface is not demonstrably aligned with interpreter 04fbe9dcc995c6188757d583e273cbd30a3e2d3d, risking missing contracts, behavioral incompatibilities, and unintended compiler-only exposure.

## Goals

- Match all in-scope interpreter names, signatures, arities, type restrictions, results, evaluation order, and language-visible failures.
- Preserve behaviorally equivalent compiler Dark and native implementations.
- Remove accidental public extensions while preserving unreachable internal helpers.
- Document intentional or unavoidable divergences explicitly.
- Exclude operators, List, Dict, and performance-only differences.

## Proposed solution

Create one revision-pinned parity inventory derived from interpreter registrations and package behavior, then compare it with the compiler’s public exposure, typing, lowering, runtime behavior, and language-level results. Revalidate prior findings with exact source evidence and focused same-source probes where practical. Contain related differences by module, organize platform services as independently testable module sections, preserve equivalent implementations, and remove unsupported public aliases or extensions without compatibility accommodations.

## Success criteria

- Every in-scope interpreter contract has equivalent compiler behavior across the complete observable contract.
- Every retained finding records both pinned revisions, exact source evidence, and behavioral evidence where feasible.
- Compiler-only public exposure is removed or documented as an intentional divergence, while internal-only facilities remain unreachable.
- Any unavoidable mismatch is explicitly classified and documented.
- Excluded surfaces and performance-only behavior remain outside the delivery.

## Open questions

- Which contracts, if any, cannot achieve exact parity, and what explicit divergence should each expose?
