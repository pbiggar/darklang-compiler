# Design brief

## Problem

The compiler’s remaining public builtin and package callable surface is not yet systematically aligned with the interpreter’s observable contracts, leaving possible omissions, incompatible behavior, and unintended compiler-only exposure.

## Goals

- Define parity from the interpreter’s registered public behavior at the pinned revisions.
- Match names, signatures, arities, type restrictions, results, evaluation order, and language-visible failures.
- Preserve behaviorally equivalent Dark and compiler-native implementations.
- Separate intentional divergences and unreachable runtime helpers from accidental public extensions.

## Proposed solution

Maintain one revision-pinned parity inventory for the in-scope scalar, text, numeric, option/result, conversion, package, and platform surfaces. Derive the baseline from interpreter registration and library behavior, compare it with the compiler’s public registration, typing, lowering, runtime, and language-level behavior, and retain only findings supported by current source evidence and practical same-source probes. Treat related differences as contained module-level changes, preserve equivalent implementation routes, and remove public compiler-only callables unless explicitly designated as intentional divergences.

## Success criteria

- Every in-scope interpreter callable at revision 04fbe9dcc995c6188757d583e273cbd30a3e2d3d has an equivalent compiler contract at HEAD b2e1f3d1e4ce0338d4c4662db9a1326f2e2cb899.
- Observable behavior agrees across names, signatures, arities, accepted types, results, evaluation order, and language-visible failures.
- Every retained difference has revision-pinned source evidence and practical behavioral evidence where feasible.
- Compiler-only public exposure is eliminated or explicitly classified as an intentional divergence, while non-public helpers remain unaffected.
- Operators, List, Dict, and non-observable performance differences remain outside this delivery.

## Open questions

- Which, if any, compiler-only public contracts should be retained as intentional divergences?
- What compatibility policy should govern removing compiler-only callables that existing compiler users may already depend on?
