# Design brief

## Problem

At compiler b2e1f3d1e4ce0338d4c4662db9a1326f2e2cb899, the remaining public callable surface is not yet demonstrably aligned with interpreter 04fbe9dcc995c6188757d583e273cbd30a3e2d3d, risking missing contracts, observable incompatibilities, and unintended compiler-only exposure.

## Goals

- Match the interpreter’s registered public behavior for all in-scope scalar, text, numeric, option/result, conversion, package, and platform contracts.
- Preserve behaviorally equivalent Dark and compiler-native implementations regardless of implementation route.
- Remove accidental compiler-only public extensions while preserving unreachable internal helpers.
- Explicitly document intentional or technically unavoidable divergences.
- Keep operators, List, Dict, and non-observable performance differences out of scope.

## Proposed solution

Create one revision-pinned parity inventory derived from interpreter registration and library behavior, then compare it with the compiler’s public exposure, typing, lowering, runtime behavior, and language-level results. Revalidate prior findings with exact source locations and focused same-source probes where practical. Contain related differences at module level, organize platform services by independently testable public module, preserve equivalent implementations, and remove unsupported public aliases or extensions without compatibility accommodations because there are no external compiler users.

## Success criteria

- Every in-scope interpreter contract at the pinned revision has equivalent compiler behavior for name, signature, arity, accepted types, results, evaluation order, and language-visible failures.
- Every retained difference has revision-pinned source evidence and practical behavioral evidence where feasible.
- Compiler-only public exposure is removed or explicitly documented as an intentional divergence, while non-public helpers remain unaffected.
- Any contract that cannot achieve exact parity is clearly identified with its observable divergence documented.
- Excluded surfaces and performance-only differences remain unchanged.

## Open questions

- Which contracts, if any, are technically unable to achieve exact parity, and what explicit divergence should each expose?
