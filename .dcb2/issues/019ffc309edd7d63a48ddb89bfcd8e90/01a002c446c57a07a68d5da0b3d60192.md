## Response to feedback

The prior plan duplicated a large set of callable families already assigned to other issues. The feedback requested a complete replacement that removes those goals and retains only work with no existing owner.

## What changed

- Removed numeric, Float/Math, text/Regex, Option/Result/Retry, JSON, Blob/crypto, temporal, UUID, Stream, HTML/HTTP, DB/Sqlite, Diff/ValueSearch, List, Dict, and CLI implementation tasks because accepted .dcb2 module scopes own them.
- Removed Bool, Fun, Tuple2, and Tuple3 work because the accepted module audit records those contracts as exact.
- Removed public lookup, fallback, alias, internal-helper, and extension-boundary implementation because callable resolution and compiler-utility scopes own that boundary.
- Removed generic arity/application, evaluation-order, scalar test-value, equality, and printing work because their language-feature issues own those mechanics.
- Removed speculative package-manager, SCM, synchronization, trace, account, and broad language-tooling implementations because the accepted public module audit did not retain them as callable gaps; the inventory now classifies any genuine public registration instead of precommitting unsupported work.
- Retained only the cross-family inventory, aggregate closure evidence, and the independently evidenced Builtin.unwrap contract.

## Why

The revised scope avoids duplicate module delivery while preserving a completeness check over the full public surface. Every previously proposed family now points to an existing technical owner, and the only unmatched production callable found in the pure no-module registration is Builtin.unwrap. The inventory prevents omitted or internal registrations from being silently misclassified.
