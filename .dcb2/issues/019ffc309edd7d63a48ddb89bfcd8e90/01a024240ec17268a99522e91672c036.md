Pinned interpreter source confirms the legacy names are not alternate implementations of the baseline contract.

At `04fbe9dcc995c6188757d583e273cbd30a3e2d3d`, the package defines `Darklang.Stdlib.Cli.File` and `Darklang.Stdlib.Cli.Path`, not `Stdlib.File` or legacy `Stdlib.Path`; file operations return `Result<_, Posix.Error>`, while the compiler legacy intrinsics return `Result<_, String>`. The interpreter Path API also uses `join(parts: List<String>)` and result-bearing resolution, unlike compiler `Path.combine` and `tempDir`. [Pinned CLI file/path source](https://github.com/darklang/dark/blob/04fbe9dcc995c6188757d583e273cbd30a3e2d3d/packages/darklang/stdlib/cli/file.dark)

This directly validates the removal classification for legacy File/Path rather than documenting them as parity. The earlier scope should also preserve the already-integrated canonical `Stdlib.Cli.File`/`Stdlib.Cli.Path` behavior and its `Posix.Error` result type while removing only the legacy identities. No pinned interpreter Random module was found in the repository tree, supporting its treatment as a compiler-only public extension rather than a missing canonical alias.
