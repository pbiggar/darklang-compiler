# Design brief

## Problem

Contributor guidance states the principle but applies it inconsistently, allowing optional fields, workarounds, and incomplete migrations to preserve invalid or ambiguous states.

## Goals

- Make invalid states unrepresentable the shared default
- Treat optionality as a semantic choice, not a convenience
- Finish migrations and remove superseded paths
- Prevent workarounds from becoming maintained behavior

## Proposed solution

Unify coding guidance around precise domain types: model distinct states explicitly, reserve optional values for genuine absence, keep related data structurally consistent, and fail clearly when unsupported states cannot yet be modeled. Require migrations to converge on one representation and remove obsolete code and compatibility scaffolding. Treat compatibility as intentional supported behavior rather than an implicit workaround.

## Success criteria

- Contributor guidance consistently explains how to identify and eliminate representable invalid states
- New or changed optional fields require a genuine semantic absence case
- Completed migrations leave one authoritative representation with no obsolete path
- Unsupported behavior is exposed directly instead of hidden by defaults, shims, or special cases

## Open questions

- Should intentional external compatibility behavior be documented as an explicit exception, or always modeled as first-class supported behavior?
