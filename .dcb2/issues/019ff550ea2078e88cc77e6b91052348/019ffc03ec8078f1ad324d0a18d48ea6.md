# Design brief

## Problem

Compile-time measurements are too sensitive to runtime noise to reliably attribute performance changes to compiler-pass optimizations.

## Goals

- Produce repeatable compile-only measurements
- Expose total and per-pass compiler cost
- Enable trustworthy comparisons against a baseline

## Proposed solution

Add a canonical benchmark mode that compiles a fixed representative corpus under a controlled configuration, separates setup and input/output from compilation, records per-pass and end-to-end cost, and compares repeated samples using a stable aggregation and explicit noise threshold. Preserve raw results in a machine-readable form so changes can be reproduced and diagnosed.

## Success criteria

- Unchanged revisions produce results within the defined variance threshold across repeated runs
- Intentional compiler slowdowns and improvements are detected consistently
- Results identify which pass accounts for a measured change
- The benchmark can compare a candidate revision with a baseline using the same corpus and configuration

## Open questions

- Should the canonical comparison use controlled wall-clock time, a deterministic proxy such as retired instructions, or both?
- Which target architectures and representative programs must define the canonical corpus?
