# Design brief

## Problem

Wall-clock compile timing and managed-runtime activity are too noisy to evaluate small compiler-pass performance changes reliably.

## Goals

- Select a deterministic proxy for compiler work
- Reliably distinguish corpus-level changes of 1% or greater
- Compare identical baseline and candidate workloads in a pinned environment
- Report one reproducible corpus-level ratio and classification

## Proposed solution

Use dynamic user-mode instruction count over the compiler-owned source-to-binary interval as the preferred metric. Broadly qualify software instrumentation, deterministic emulation or simulation, hardware retired-instruction counters, record/replay, managed-runtime counters, and compiler-level cost models. Prefer the simplest compatible software-counting backend with a behavior-equivalent NativeAOT compiler artifact; retain managed execution or deterministic emulation as fallbacks. Pin the complete Linux environment and corpus, sum baseline and candidate counts into one ratio, apply a predeclared deadband comfortably below 1%, and report wall-clock time only as supporting context.

## Success criteria

- The selected mechanism demonstrates compiler compatibility and materially better repeatability than wall-clock, including under competing host load
- Unchanged revisions produce identical counts or bounded variation comfortably below the 1% detection threshold
- Known corpus-level work changes of 1% are consistently detected in the expected direction
- Every comparison uses identical pinned inputs and reports one faster, slower, or unchanged ratio
- The chosen execution mode preserves compiler outputs and comparative performance conclusions

## Open questions

- Can NativeAOT preserve current compiler behavior and performance rankings, or is JIT-aware instrumentation required?
- Should input reading and binary writing be inside the canonical compiler-work boundary?
- How should instruction-count improvements be interpreted when memory behavior or instruction latency moves in the opposite direction?
