# Implementation plan

The existing Cachegrind suite deterministically measures generated programs, while compile-time evidence remains Stopwatch-based. Add a separate pinned Linux/x86_64 NativeAOT harness around the in-memory compiler API, with Valgrind instruction counting as the primary qualified backend and managed or emulated execution retained only when they satisfy the same gates.

## Work item 01a000a3930e75928ba93cbc9e957a12

Title: Pin a representative compile corpus

Category: other

Evidence: benchmarks/profiles/routine.txt names 19 workloads; PARITY.json already pins each quick.dark source and expected output.

Outcome:

Define an ordered compile-time corpus from the routine profile's 19 hash-pinned Dark quick programs, including expected-output hashes, compiler syntax, internal-name policy, target, compiler options, stdlib-source manifest, and one corpus digest shared by both artifacts.

## Work item 01a000a3930e7e05b2d67dad4e299bfb

Title: Make stdlib inputs explicit

Category: type

Evidence: CompilerLibrary.loadStdlib currently reads a private fixed file list using Assembly.Location and Environment.CurrentDirectory, preventing explicit identical-input enforcement.

Outcome:

Introduce a typed stdlib-source bundle and a buildStdlibFromSources entry point so the benchmark can preload one immutable stdlib snapshot for both artifacts; retain buildStdlib as the normal filesystem-loading wrapper.

## Work item 01a000a3930e7511907bf85fcfe574bc

Title: Establish the counted compiler boundary

Category: function

Evidence: CompilerLibrary.compile is documented as in-memory with no file I/O, while Program.fs performs source reading and binary writing around it.

Outcome:

Add a no-inline benchmark function whose counted interval accepts preloaded source strings, builds the stdlib once, compiles every corpus program in declared order through CompilerLibrary.compile, and returns binary byte arrays; source reads, output writes, hashing, execution, and report formatting remain outside the interval.

## Work item 01a000a3930e7f04a941b0f929ff55a0

Title: Create a behavior-equivalent benchmark driver

Category: behavior

Evidence: DarkCompiler.fsproj is currently the only compiler executable; CompileRequest already exposes target-independent source, context, syntax, options, and verbosity inputs.

Outcome:

Add a functional F# executable referencing DarkCompiler that validates its manifest, invokes the canonical boundary for LinuxX86_64 with fixed default options, emits structured results, and represents failures with Result and explicit discriminated unions rather than flags, exceptions, or sentinels.

## Work item 01a000a3930e7e09ab68d239538e9604

Title: Publish a deterministic NativeAOT artifact

Category: behavior

Outcome:

Add a Release linux-x64 NativeAOT publish profile with stable symbols for boundary selection, fixed globalization and garbage-collector configuration, deterministic build properties, and all compiler assets required to run outside a repository checkout.

## Work item 01a000a3930e7b5a8c821537049572b8

Outcome:

Run the NativeAOT driver under Valgrind Callgrind with collection disabled outside the stable compiler-work function, parse dynamic user-mode Ir totals, and reject missing, ambiguous, truncated, or nonzero-exit measurements.
