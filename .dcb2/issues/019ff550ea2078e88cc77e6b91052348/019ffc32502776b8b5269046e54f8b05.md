# Design brief

## Problem

No stable benchmark shows whether a compiler change makes compilation faster or slower.

## Goals

- Compare compile-time performance between baseline and candidate revisions
- Minimize noise enough to identify meaningful regressions and improvements

## Proposed solution

Benchmark the same fixed representative programs on baseline and candidate builds in one controlled environment, with warm-up and repeated interleaved runs. Report a single compile-time ratio using a robust aggregate; treat differences within a documented noise threshold as unchanged.

## Success criteria

- Unchanged revisions consistently report no meaningful difference
- Deliberate compile-time regressions and improvements are detected reliably
- Each result clearly states whether the candidate is faster, slower, or unchanged relative to baseline

## Open questions

- Which representative programs should form the canonical compile-time workload?
- What measured noise threshold should count as unchanged?
