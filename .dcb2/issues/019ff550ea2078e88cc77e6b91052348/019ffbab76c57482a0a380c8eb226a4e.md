# Design brief

## Problem

Current wall-clock compiler timings are noisy, while deterministic benchmarks measure generated programs rather than compiler passes, making compile-time optimizations difficult to evaluate reliably.

## Goals

- Produce repeatable compile-time measurements for individual passes and overall compilation.
- Attribute performance changes to fixed, representative compiler workloads.
- Detect compile-time regressions independently of generated-program performance.

## Proposed solution

Introduce an isolated compile-time benchmark using a versioned source corpus and stable phase identities. Measure cold and warm compilation workloads with a pinned ahead-of-time compiler and deterministic instruction counting, excluding startup, source I/O, binary writes, and execution. Emit machine-readable results keyed by measurement environment, compare them with dedicated baselines, and retain controlled wall-clock medians to validate that instruction-count changes predict real elapsed-time changes.

## Success criteria

- Repeated runs of the same build and workload produce identical per-phase and total instruction counts.
- A pass optimization produces a stable, attributable delta without changing unrelated workload results.
- Missing, unexpected, or changed workloads and phases are reported deterministically.
- The benchmark demonstrates whether count improvements correlate with lower wall-clock compile time.

## Open questions

- Which host and target architecture combinations should define the canonical baselines?
- Which secondary metrics are needed when equal instruction counts conceal allocation or cache-behavior changes?
