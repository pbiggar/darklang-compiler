# Design brief

## Problem

At compiler b2e1f3d1e4ce0338d4c4662db9a1326f2e2cb899, identifier and qualified-name parsing diverges from darklang/dark 04fbe9dcc995c6188757d583e273cbd30a3e2d3d across contexts, keywords, capitalization, escaping, and ambiguous boundaries.

## Goals

- Adopt the pinned interpreter’s lexical acceptance and parse structure for every name-bearing context.
- Preserve qualified-name segments and syntactic ambiguity for later resolution without performing semantic lookup.
- Remove repository-authored keyword aliases, capitalization exceptions, and legacy identifier forms.
- Document any retained compiler-only syntax or intentional divergence explicitly.

## Proposed solution

Establish one interpreter-derived name grammar shared across compiler parsing surfaces. Represent blank, escaped, simple, and qualified names without flattening segments; apply contextual capitalization and token-boundary rules consistently; defer value, callable, constructor, type, module, and package lookup to resolution. Migrate repository-authored Dark source to the canonical grammar and treat unsupported legacy spellings as non-parity syntax rather than implicit aliases.

## Success criteria

- Focused same-source evidence shows matching acceptance, rejection, and parse shape across all named contexts at the pinned revisions.
- Reserved words, escaped names, capitalization, qualification-versus-field boundaries, type-variable boundaries, and glued-token boundaries match interpreter behavior.
- Repository-authored Dark source contains no removed aliases, casing exceptions, or legacy identifier forms.
- The parity record cites exact pinned source evidence and classifies every remaining compiler-only or intentional divergence.
- Callable and namespace resolution behavior remains outside this delivery boundary.
