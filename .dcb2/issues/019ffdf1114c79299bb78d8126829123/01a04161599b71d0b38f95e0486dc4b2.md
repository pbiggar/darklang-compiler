## Problems

Remove boxed Option construction from matmul's successful HAMT lookups.

## Solution

`__getOrDefault` already uses a direct HAMT traversal that returns the stored value or fallback without constructing an Option, while retaining generic key equality, missing-key behavior, and managed-value ownership. Both supplied revisions are the same commit, so a measured difference cannot be retained as an optimization; the verifier rejected it as a same-revision control. The current RESULTS.md snapshot reports 2.90x, but it belongs to compiler commit `a3a3c17e…`, not this trial; no routine profile or full suite was run, as assigned to DCB.

## Implementation

- None; the candidate checkpoint was preserved untouched at `78f9c99e37a3cbd5db26d5a841766de4678d2407`.
- The existing direct-default HAMT lookup implementation, canonical Dict matmul, and materialized result remain unchanged.

### Algorithm

1. Hash the key and traverse the immutable HAMT.
2. Return the stored value immediately on a matching leaf or collision entry using generic `__key_eq`.
3. Recurse through internal nodes with the supplied fallback.
4. Return the fallback directly for null nodes, absent bitmap bits, or missing collisions.
5. Preserve the Option-returning lookup separately for callers that require absence information.

### Example

For `__getOrDefault(d, "key", "fallback")`, where `d` stores `"key" -> "stored"`, the helper returns `"stored"`; for `"missing"`, it returns `"fallback"`. The full matmul source still calls this helper for every matrix cell and prints `222793267`. Generated normalized MIR, post-register-allocation LIR, executable bytes, and runtime output are equal between the identically pinned revisions, demonstrating no trial delta.
