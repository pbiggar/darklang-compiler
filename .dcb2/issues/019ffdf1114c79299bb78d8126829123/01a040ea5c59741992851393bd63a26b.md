# Trial result

The preserved identical candidate cannot demonstrate an attributable matmul improvement, so the focused same-revision control is rejected despite passing all focused correctness checks. No established-suite improvement was proven; overall multiplier: 1×.

## Evidence

## Problems

Remove boxed Option construction from matmul's successful HAMT lookups.

## Solution

The retained implementation directly returns a found HAMT value or fallback, preserving generic equality and managed ownership, but baseline and candidate are the same commit; therefore no focused performance gain can be attributed to this trial. Current `RESULTS.md` reports a 2.90x ratio; the investigation’s 2.75x note is historical and was not refreshed because DCB owns the routine gate.

## Implementation

- No files were edited, replaced, discarded, or integrated.
- The preserved `__getOrDefault` direct-default HAMT traversal remains unchanged.

### Algorithm

1. Hash the key and traverse HAMT nodes.
2. Compare keys using the existing generic equality path.
3. Return the stored value on success, or the supplied fallback on absence.
4. Recurse tail-call-style for internal nodes without constructing an Option.

### Example

`__getOrDefault(dict, "key", "fallback")` returns the stored managed value for `"key"` and returns `"fallback"` for a missing key; generated post-register-allocation LIR contains the direct helper tail call and no `HeapAlloc(16)` in its helper body.
