# Design brief

## Problem

At compiler revision b2e1f3d1e4ce0338d4c4662db9a1326f2e2cb899 versus darklang/dark 04fbe9dcc995c6188757d583e273cbd30a3e2d3d, string-based, multi-stage lookup can silently rewrite names, overwrite collisions, or coerce values and callables, producing identities and errors that differ from the interpreter.

## Goals

- Match interpreter precedence for lexical, module, package, builtin, constructor, value, function, and type references.
- Consume structured qualified names and preserve explicit semantic identities through compilation.
- Make unresolved and ambiguous outcomes deterministic while documenting AOT error timing and compiler-only extensions.

## Proposed solution

Establish one pure resolution boundary after parsing. Build an explicit inventory of typed symbol identities and resolve each structured qualified name according to its reference context and the interpreter’s lexical, kind, namespace, version, and module-search precedence. Preserve the original spelling, deduplicate aliases of one identity, and report distinct candidates tied at the winning precedence as ambiguity. Attach the resolved identity before type checking and lowering, which must perform exact identity lookup only. Remove implicit namespace qualification, spelling and suffix retries except explicitly registered public aliases, qualified-to-unqualified fallback, nullary auto-invocation, and callable/value coercion. Treat registered compiler intrinsics as classified extensions and early closed-world failures as an intentional AOT divergence.

## Success criteria

- Same-source references select the same semantic identity and precedence as the pinned interpreter wherever both program models represent the reference.
- Collisions never depend on declaration or map order; unresolved and ambiguous references produce stable, context-specific outcomes that retain the written name.
- Qualified names and builtin versions resolve only through explicit registrations, with no hidden namespace insertion or later spelling recovery.
- No downstream phase changes a resolved name’s kind, retries resolution, or implicitly invokes a function used as a value.
- Every remaining compiler-only intrinsic or package-model limitation is explicitly classified.

## Open questions

- Should this issue include content-addressed package loading, or define and validate the package identity boundary against imported inventories while dependency loading remains part of the broader package model?
