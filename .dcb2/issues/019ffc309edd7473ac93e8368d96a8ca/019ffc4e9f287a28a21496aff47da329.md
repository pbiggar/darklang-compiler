# Design brief

## Problem

At compiler b2e1f3d1e4ce0338d4c4662db9a1326f2e2cb899 versus interpreter 04fbe9dcc995c6188757d583e273cbd30a3e2d3d, name resolution is not represented as one explicit semantic operation, allowing compiler-only qualification, lookup, and callable/value fallbacks to produce different bindings or failures.

## Goals

- Match interpreter precedence and ambiguity behavior for local values, functions, constructors, user types, modules, packages, and builtins.
- Consume lexically parsed qualified names and represent every resolvable name kind explicitly.
- Treat the interpreter as the parity baseline while clearly classifying intentional divergences and compiler-only extensions.
- Produce deterministic unresolved and ambiguous-reference diagnostics without spelling-based recovery.

## Proposed solution

Introduce a single context-aware resolution boundary that maps parsed qualified names to typed symbol identities. It should gather candidates from lexical scope, declared namespaces, packages, constructors, user types, and explicitly registered builtins, then apply interpreter-derived precedence and ambiguity rules for value, callable, constructor, and type contexts. Later compiler stages consume only resolved identities and cannot retry lookup, infer qualification, or coerce between callable and value categories. Implicit builtin qualification, compiler-only lookup shortcuts, and callable/value coercion are classified as parity defects and removed; any retained divergence must be explicitly represented and documented against the pinned revisions.

## Success criteria

- The same source selects the same binding as the interpreter across all supported name kinds and collision combinations.
- Qualified module, package, builtin, constructor, value, function, and type references resolve without spelling-based fallbacks.
- Unresolved and ambiguous references fail with the same semantic classification as the interpreter.
- Comparison evidence records compiler b2e1f3d1e4ce0338d4c4662db9a1326f2e2cb899 and interpreter 04fbe9dcc995c6188757d583e273cbd30a3e2d3d, with every retained difference classified.
