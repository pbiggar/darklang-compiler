# Design brief

## Problem

At compiler HEAD b2e1f3d1e4ce0338d4c4662db9a1326f2e2cb899, source typing diverges from darklang/dark 04fbe9dcc995c6188757d583e273cbd30a3e2d3d in generic syntax, implicit type parameters, polymorphic reuse, annotation enforcement, inference failures, and error phase; unresolved types can also leak into compiler heuristics and specialization.

## Goals

- Make the pinned interpreter revision the source-visible typing baseline across bindings, functions, recursion, user types, constructors, annotations, and constrained uses.
- Match fresh inference, repeated-variable constraints, occurs checks, polymorphic reuse, and any observable generalization or value restriction.
- Remove compiler-only generic syntax and silent type fallbacks while explicitly classifying unavoidable AOT divergences.
- Keep monomorphization and specialization entirely unobservable.

## Proposed solution

Adopt one interpreter-aligned source typing contract: parse the public type-variable and annotation forms, represent unknowns as constraints rather than defaults, generalize only where interpreter behavior permits polymorphic reuse, instantiate every polymorphic use freshly, and solve annotations, constructors, recursive references, repeated variables, and cyclic constraints consistently. Preserve interpreter acceptance and observable results while translating suitable runtime checks into static reasoning; explicitly document any remaining error-phase divergence. Perform specialization only after source typing is resolved. Treat DCB1 commit 8a402797 and existing parity documents as historical inventories, with all retained findings revalidated against the pinned revisions.

## Success criteria

- Every comparison identifies compiler b2e1f3d1e4ce0338d4c4662db9a1326f2e2cb899 and interpreter 04fbe9dcc995c6188757d583e273cbd30a3e2d3d.
- Same-source programs agree on acceptance, results, type relationships, rejection conditions, and classified error phase across the owned generic behaviors.
- Polymorphic bindings and calls instantiate independently, repeated variables constrain consistently, recursive or infinite constraints fail deliberately, and no unobserved value restriction is introduced.
- Compiler-only generic syntax and implicit type fallbacks are absent, and specialization causes no language-visible difference.

## Open questions

- Where the interpreter defers annotation or type failures until evaluation, which cases may the AOT compiler intentionally reject earlier?
- Must diagnostics match exact wording and source spans, or only meaning and phase?
