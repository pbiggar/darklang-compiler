## Evidence

## Problems

Determine whether one-iteration peeling exposes profitable existing MIR simplifications in canonical scalar loops.

## Solution

Existing factor-two unrolling already turns the canonical scalar loop into two bodies per header check. A semantics-preserving peel needs an entry guard for zero-trip correctness and would prevent the residual loop from matching that strict two-block unroller shape, while parameter phi inputs expose no first-iteration constants. The candidate therefore retains no implementation change; residual risk is limited to unmeasured alternative loop shapes outside the bounded contract.

## Implementation

- Preserved candidate `ded3cd1b0d19406f395b59c784606ba6ffe45519` adds only the canonical scalar loop-peeling trial outcome to `docs/classic-optimizations.md`.
- No compiler or test source differs from baseline; the disposable `peel-probe.dark` was removed.

### Algorithm

1. Preserve the guarded header to retain zero-trip behavior.
2. Existing MIR factor-two unrolling executes a first latch body, guards a second body, and uses a remainder exit for odd trips.
3. The probe confirms header phi inputs originate from parameters and the two square-add bodies remain dynamic.
4. A peeled entry guard/body would add CFG structure and remove the residual loop from existing two-block unroll eligibility.
5. Retain the current unrolled behavior because no simplification or focused timing win is exposed.

### Example

For `loop(i, limit, sum) = if i >= limit then sum else loop(i + 1, limit, sum + i * i)`, MIR contains `loop_L1_unroll_second`: the first body computes `sum + i*i`, then the second computes the next square-add before returning to the header. LIR lowers each to sequential `Madd`; `i`, `limit`, and `sum` are parameter-derived phi values, so peeling cannot fold the first square.
