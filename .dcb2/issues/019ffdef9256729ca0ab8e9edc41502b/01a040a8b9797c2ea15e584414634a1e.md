# Trial result

The pinned identical-revision control showed no attributable quicksort improvement, so the preserved candidate remains unintegrated. No established-suite improvement was proven; overall multiplier: 1×.

## Evidence

## Problems

Turn known local closure calls into direct calls and remove avoidable closure allocation.

## Solution

The transformation replaces eligible local closure calls with calls to the lifted function and supplies Unit for its hidden environment argument, avoiding allocation only when no closure value can escape. This preserves capture evaluation and reference-count ownership by conservatively retaining every captured or potentially escaping closure. The issue-specific measurement is an identical-revision control, so its apparent timing difference is environmental variance rather than evidence for a candidate win.

## Implementation

- Preserved candidate devirtualizes capture-free closures whose complete lexical use set consists only of direct closure calls.
- Captured, escaping, stored, returned, forwarded, and unknown-use closures retain allocation.
- Existing ANF, MIR, LIR, and generated-code coverage covers capture-free, captured, escaping, and reused closures.

### Algorithm

1. Run ordinary ANF optimization and copy propagation.
2. Identify zero-capture ClosureAlloc bindings.
3. Require one or more uses and require every use to be ClosureCall or ClosureTailCall.
4. Reject all escaping, stored, returned, forwarded, captured, or unknown uses.
5. Rewrite accepted calls to lifted direct calls with Unit as the hidden environment.
6. Remove the now-unneeded closure allocation.

### Example

Before: `let increment = fun x -> x + 1 in increment(41)` allocates a zero-capture closure and dispatches through it. After: the call targets the lifted increment function directly with Unit as its hidden environment, producing 42 without allocation. By contrast, `let make() = let increment = fun x -> x + 1 in increment` retains allocation because the closure is returned.
