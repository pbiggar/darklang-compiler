# Trial result

The refreshed capture-free devirtualization remains justified, passes all checks, and is committed cleanly atop the requested target without integration.

## Evidence

## What changed

Moved conservative closure devirtualization after ordinary ANF optimization so public-syntax aliases are removed first; zero-capture, non-escaping calls become direct lifted calls with Unit as the hidden environment argument. Updated ANF/MIR/LIR/native tests for current syntax, added escaping and reused generated-code coverage, and refreshed the optimization backlog and measurements.

## How it works

The rebase exposed an administrative alias that caused the original pre-pass to miss eligible closures. Running the existing fixed point first fixes this without adding alias analysis. Closures with captures, escaping uses, storage, returns, or unknown callees remain allocated, preserving capture evaluation and reference ownership. The analysis is linear per candidate closure and conservatively O(n²) with many nested allocations. Scalar-capture specialization was rejected because it does not benefit quicksort or another routine workload; interprocedural List.filter specialization remains the follow-up.

## Algorithm

1. Run ordinary ANF optimization and copy propagation. 2. Find ClosureAlloc bindings with no captures. 3. Traverse the complete lexical use set and require at least one use, with every use an exact ClosureCall or ClosureTailCall. 4. Reject returns, storage, forwarding, unknown uses, and captured closures. 5. Rewrite accepted uses to Call or TailCall of the lifted target, passing Unit in its existing hidden environment slot. 6. Remove the now-unneeded allocation.
