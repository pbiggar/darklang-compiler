## How it works

The first concrete failure was LICM hoist loss in `licm_hoist_loop_constant`. `Add_shifted` had correct use/liveness handling but was omitted from LICM’s pure-instruction classification, preventing any hoist in loops containing it. Adding that classification preserves the fused one-instruction ARM64 lowering while restoring LICM behavior. The two LIR snapshot differences were stale two-source renderings, and the x64 failure was a test expectation using the wrong physical-register mapping. The transformation remains O(n) per basic block for its existing candidate/use analysis. Residual risk is limited to worker-owned full-suite and routine-benchmark validation.

## Algorithm

1. Recognize a dead constant register used for eligible `2^k + 1` Int64 multiplication.
2. Replace the constant materialization and multiply with unary `Add_shifted(destination, source, k)`.
3. Treat the source as both operands of ARM64 shifted ADD.
4. Treat `Add_shifted` as a pure arithmetic instruction for LICM.
5. Lower on x64 to wrapping `IMUL` by `2^k + 1`.
