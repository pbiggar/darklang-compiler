# Design brief

## Problem

The module-parity inventory is stale and mixes API presence, behavioral parity, compiler extensions, and resolved gaps, so it cannot reliably scope current work.

## Goals

- Establish a complete revision-pinned inventory of public module differences.
- Create non-overlapping, independently deliverable module or coherent-family scopes.
- Classify compiler-only extensions, intentional divergences, and out-of-scope performance differences explicitly.

## Proposed solution

Re-audit compiler 51093e0a8e31fe45a9aa79a317fbefd6b74fbcc3 against darklang/dark 04fbe9dcc995c6188757d583e273cbd30a3e2d3d. Rebuild the comparison from each implementation’s current public surface and observable contracts, using DCB1 report commit 8a402797ccccda0ca47b516b356ae1de4d670038 and current parity documents only as leads. Revalidate every retained difference through current source locations and, where practical, focused same-source evidence. Produce one child per module or coherent family, with a compact public type/function delta, classification, and evidence structured for later leaf-level splitting.

## Success criteria

- Every interpreter public module is covered and every current difference appears exactly once or is explicitly classified.
- Every child records both exact revisions and current supporting source locations.
- Behavioral claims have focused same-source evidence wherever practical.
- Resolved historical findings are omitted, while extensions and intentional divergences are clearly separated from missing parity.
- Each child can be split into individual leaf gaps without repeating the inventory audit.

## Open questions

- What policy determines whether compiler-only public extensions remain part of a distinct compiler surface or are excluded from the long-term public parity surface?
