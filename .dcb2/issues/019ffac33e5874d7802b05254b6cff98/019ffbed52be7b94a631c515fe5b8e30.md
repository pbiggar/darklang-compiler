# Design brief

## Problem

The integer families expose inconsistent operations, conversions, error shapes, and 128-bit support, leaving parity gaps and unclear compiler-only behavior.

## Goals

- Define one complete conversion and behavior matrix across arbitrary, fixed-width, signed, unsigned, and 128-bit integers.
- Use revision-pinned interpreter behavior as the parity baseline, with source or focused-probe evidence for every matrix decision.
- Standardize parsing, arithmetic-result, conversion, and error behavior while explicitly separating extensions and intentional divergences.
- Restore canonical 128-bit behavior without expanding into performance work.

## Proposed solution

Deliver a single revision-stamped parity matrix and implement it as one coherent integer-family completion. Each comparison records the exact compiler and interpreter revisions and is traceable to current source or a focused same-source probe. Interpreter-declared behavior remains canonical; arithmetic compatibility aliases, parity-absent predicates, generic equality or ordering helpers, and unsigned signedness operations are classified as compiler extensions. Intentional error-shape and result-behavior differences are documented explicitly. Related surface and conversion gaps remain contained sections of the same issue unless resolving canonical 128-bit arithmetic proves to require a distinct compiler or runtime boundary.

## Success criteria

- Every requested operation and conversion cell is present and classified as parity behavior, compiler extension, or intentional divergence.
- Parsing exposes only the canonical bad-format error and returns working typed results where required.
- Signed and unsigned conversions across all supported widths have observable behavior matching the pinned interpreter baseline.
- Canonical 128-bit arithmetic, conversion, aggregation, comparison, formatting, parsing, bitwise, and shift behavior works through the public compiler surface.
- No retained finding relies solely on the earlier report or parity documents; every finding is revalidated against the recorded revisions.

## Open questions

- Does the unresolved canonical signed 128-bit arithmetic path require a new compiler or runtime design boundary, or can it be completed within the existing integer representation? ​
