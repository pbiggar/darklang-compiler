# Trial result

The candidate preserved correctness and reduced synthetic spill traffic, but edigits Register Allocation improved only 1.9 ms—well below both noise thresholds—so there is no repeatable focused win. No established-suite improvement was proven; overall multiplier: 1×.

## Evidence

## Problems

Reduce hot-loop spill traffic only when split allocation yields a repeatable measured gain.

## Solution

The candidate moves repeated hot-loop reloads to the loop-entry edge while ordinary allocation continues enforcing SSA edge semantics, ABI constraints, call clobbers, stack alignment, and interference-checked coalescing. Synthetic fixtures confirm a deterministic stack-traffic reduction, but the named existing workload produced identical normalized LIR and executable bytes and no clear Register Allocation timing gain. The narrow eligibility rules limit correctness risk but also mean existing edigits quick does not retain a split; broader loop shapes remain unsupported. The candidate checkpoint was preserved without integration or source edits.

## Implementation

- Detects canonical four-block, single-backedge loops.
- Splits eligible spilled, literal-defined, non-owning Int64 live ranges through a typed header phi.
- Rejects call-containing, ownership-sensitive, interfering, or noncanonical cases.
- Retains splitting only when hot-loop and total stack traffic both decrease.
- Adds allocated-LIR, ARM64 generated-code, exclusion, ABI, and coalescing tests plus documentation.

### Algorithm

1. Allocate the original function and identify spilled non-owning Int64 candidates. 2. Require a canonical preheader/header/latch/exit CFG with one backedge. 3. Reject calls, unsupported uses, redefinitions, ownership-sensitive operations, and noncanonical interference. 4. Create a fresh loop-local virtual register. 5. Insert a header phi receiving the original value from the preheader and itself from the latch. 6. Rewrite dominated loop and exit uses to the local segment. 7. Reallocate the transformed function. 8. Retain it only when both loop-local and whole-function stack-access counts decrease; otherwise retain the original allocation.

### Example

In the focused fixture, spilled v99 was read by 15 hot additions, causing 17 loop and 20 total stack accesses. The candidate inserts `vSplit = Phi([(v99, preheader), (vSplit, latch)])` and rewrites hot uses to vSplit, reducing traffic to 4 loop and 6 total accesses. This demonstrates the intended transformation, although edigits quick produced identical allocated LIR at both pinned revisions.
