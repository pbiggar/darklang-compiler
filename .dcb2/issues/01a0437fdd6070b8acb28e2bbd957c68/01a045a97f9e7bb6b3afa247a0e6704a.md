# Trial result

The candidate produced no clear focused win: Register Allocation median increased from 19.3 ms to 20.4 ms, within the 2.7 ms noise threshold. No established-suite improvement was proven; overall multiplier: 1×.

## Evidence

## Problems

Reduce hot-loop spill traffic only when split allocation yields a repeatable measured gain.

## Solution

The candidate attempts to move repeated spill reloads from a hot loop to its entry edge while leaving normal allocation responsible for interference, ABI constraints, call clobbers, coalescing, and stack alignment. Its focused fixtures demonstrate substantially lower deterministic stack traffic, and MIR, executable, and output equality passed on edigits. However, the required existing-workload measurement did not show a repeatable performance gain: the candidate median was slower and the difference was below the clear-win threshold. The candidate therefore remains available at its checkpoint but is classified no-improvement. Residual risk includes the narrow supported loop shape and the fact that edigits produced identical allocated LIR, so that existing workload did not activate the split transformation.

## Implementation

- Preserved candidate adds measured loop-boundary splitting for literal-defined, non-owning Int64 live ranges in canonical single-backedge loops.
- It inserts a typed header phi, reallocates both forms, and retains splitting only when loop and total stack traffic decrease.
- It rejects call-containing, unsupported, noncanonical, and non-improving cases.
- Added allocated-LIR and ARM64 generated-code coverage and documentation; no trial files were edited or integrated during measurement.

### Algorithm

1. Allocate the original function and identify spilled, literal-defined, non-owning Int64 candidates.
2. Require a canonical four-block loop with one preheader, header, latch backedge, and return exit.
3. Reject calls, ownership-sensitive or unsupported uses, redefinitions, and noncanonical control flow.
4. Create a fresh loop-local virtual register and a typed header phi whose entry input is the original value and whose backedge input is the loop-local value.
5. Rewrite dominated loop and supported exit uses to the loop-local segment.
6. Reallocate the transformed function using the existing allocator constraints and coalescing.
7. Retain the transformation only when both hot-loop and whole-function stack-access counts decrease; otherwise preserve the original allocation.

### Example

In the focused pressure fixture, the original spilled value is read by 15 hot additions, causing 17 loop and 20 whole-function stack accesses. The candidate inserts `vSplit = Phi([(vOriginal, preheader), (vSplit, latch)])`, rewrites hot uses to `vSplit`, and reduces traffic to 4 loop and 6 whole-function accesses. This demonstrates the intended cold-entry reload, although edigits itself had identical normalized allocated LIR across revisions.
