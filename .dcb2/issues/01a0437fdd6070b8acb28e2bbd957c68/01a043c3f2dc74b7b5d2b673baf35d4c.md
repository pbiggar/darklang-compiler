# Trial result

Retained a guarded loop-boundary Int64 split that reduces focused ARM64 stack traffic from 20 accesses to 6. No established-suite improvement was proven; overall multiplier: 1×.

## Evidence

## Problems

Reduce hot-loop spill traffic only when split allocation yields a repeatable measured gain.

## Solution

The split moves repeated spill reloads from the hot loop to its entry edge. Existing phi resolution preserves SSA edge semantics, while normal allocation continues to enforce ABI constraints, call clobbers, stack alignment, and coalescing. The narrow eligibility rules limit risk and the measured-profitability gate preserves the original allocation when splitting is neutral. Residual risk is limited coverage of broader loop shapes; repository-wide validation remains assigned to the worker.

## Implementation

- Detect canonical four-block, single-backedge loops.
- Split eligible spilled, literal-defined, non-owning Int64 values through a typed header phi.
- Reallocate both forms and retain the split only when loop and total stack traffic decrease.
- Reject call-containing loops, unsupported uses, redefinitions, and noncanonical CFGs.
- Added allocated-LIR and ARM64 code-generation regressions plus documentation.

### Algorithm

1. Allocate the original function and identify spilled Int64 candidates.
2. Require a four-block CFG containing one preheader, header, latch backedge, and return exit.
3. Reject loops containing calls or candidate uses outside supported non-owning integer operations.
4. Create a fresh loop-local virtual register.
5. Insert a typed header phi receiving the original value on entry and itself on the backedge.
6. Rewrite dominated header, latch, and exit uses to the loop-local segment.
7. Reallocate the transformed function.
8. Retain it only if both hot-loop and whole-function stack-access counts decrease.

### Example

Before, spilled v99 is read directly by 15 hot additions, producing 17 loop stack accesses and 20 overall. After, the header contains `vSplit = Phi([(v99, preheader), (vSplit, latch)])`; hot additions use vSplit, moving the original spill reload to the entry edge and reducing traffic to 4 loop accesses and 6 overall.
