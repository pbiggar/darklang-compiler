## How it works

The allocator previously emitted stack stores and reloads for spilled immutable Int64 immediates. The candidate conservatively rematerializes only single-definition constants in the shared 0..4095 directly encodable range and only at immediate-capable uses. A broader arbitrary-Int64 alternative was rejected because ARM64 may require multiple instructions and repeated rematerialization can become unprofitable. Post-coloring rewriting was retained because it leaves interference, call-clobbering, ABI allocation, and stack alignment unchanged. The transformation’s focused cross-call and negative tests passed, but the existing nqueen workload generated identical MIR and executable bytes and showed a neutral 0.0 ms pass-time delta. Complexity is linear in instructions and uses aside from persistent Map/Set operations. Residual risk is conservative under-optimization; no focused performance win was demonstrated.

## Algorithm

1. Complete liveness, interference construction, coloring, call handling, and phi resolution unchanged. 2. Find stack-assigned virtual registers with exactly one `Mov (Virtual, Imm Int64)` definition. 3. Retain only constants in the shared directly encodable range 0..4095. 4. Require every use to be a move source or the immediate-capable right operand of Add, Sub, or Cmp; reject terminator, multiplication, out-of-range, and other register-only uses. 5. Remove accepted defining stores and substitute the literal at eligible uses. 6. Apply the original allocation and normal target-specific code generation.
