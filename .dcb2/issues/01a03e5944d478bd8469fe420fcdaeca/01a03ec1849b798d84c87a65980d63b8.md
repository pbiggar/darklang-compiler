## How it works

The allocator previously represented every spill as a stack slot, including immutable Int64 immediates that could be recreated directly at all uses. The preserved candidate performs conservative post-coloring rematerialization, so allocation interference, call-clobber handling, ABI assignments, and stack alignment remain unchanged. A broader arbitrary-Int64 alternative had been rejected because ARM64 may require multiple instructions, making repeated rematerialization unprofitable. The retained 0..4095 shared range guarantees one-instruction materialization on both targets and rejects register-only or otherwise unsupported uses. Its scan is linear in instructions and uses aside from persistent Map/Set costs. Focused correctness tests passed, but the existing nqueen benchmark generated byte-identical executables and the measured 0.8 ms pass-time reduction was below the 1.0 ms clear-win threshold. Residual risk is conservative under-optimization and the absence of a clear existing-workload performance gain.

## Algorithm

1. Complete liveness, interference construction, coloring, call handling, and phi resolution unchanged. 2. Find stack-assigned virtual registers having exactly one immediate Int64 move definition. 3. Keep only values in the shared directly encodable range 0..4095. 4. Require every use to be a move source or the immediate-capable right operand of Add, Sub, or Cmp; reject terminator, multiplication, out-of-range, and other register-only uses. 5. Remove accepted defining stores and substitute the literal at eligible uses. 6. Apply the original allocation and normal target-specific code generation.
