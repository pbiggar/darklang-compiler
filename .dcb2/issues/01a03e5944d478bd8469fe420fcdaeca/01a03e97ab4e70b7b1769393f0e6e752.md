# Trial result

Retained and committed a conservative post-coloring rematerialization pass that eliminates profitable constant spill traffic on both targets. Canonical routine benchmark: equal.

## Evidence

## Important changes

- **Added post-coloring Int64 immediate rematerialization** — **Reason:** Removes stores and reloads for spilled immutable constants without changing interference, call-clobbering, ABI assignments, or stack alignment.
- **Restricted candidates to single-definition values in the shared 0..4095 immediate range and immediate-capable operand positions** — **Reason:** Guarantees profitable one-instruction materialization on ARM64 and x86-64 while respecting instruction-specific ranges.
- **Added cross-call allocated-LIR and generated-code regression coverage for both targets** — **Reason:** Proves the optimization fires across calls and reduces targeted instructions.
- **Added register-only and out-of-range negative coverage** — **Reason:** Ensures multiplication operands and unsupported immediates remain conventionally spilled.
- **Updated docs/classic-optimizations.md** — **Reason:** Records the retained algorithm, constraints, and focused measurements.

## How it works

The allocator colored immediate-defined virtual registers normally but always represented spills as stack slots, producing a defining store and a reload at each use. The retained solution performs rematerialization only after coloring and phi resolution, preserving all allocation decisions. An initially broader arbitrary-Int64 approach was rejected because multi-instruction ARM64 materialization can become unprofitable with repeated uses. The final common-range restriction guarantees each replacement is directly encodable. The scan is linear in instructions and observed uses aside from persistent Map/Set operations. Residual risk is limited by conservative rejection; stack-frame size is intentionally unchanged because retaining the original allocation is what preserves allocator behavior exactly.

## Algorithm

1. Complete liveness, interference construction, coloring, call handling, and phi resolution unchanged.
2. Find virtual registers with exactly one `Mov (Virtual, Imm)` definition that received a stack slot.
3. Retain only constants in `0..4095`.
4. Count every use and accept a value only when every occurrence is a `Mov` source or the right operand of `Add`, `Sub`, or `Cmp`; reject terminator and register-only uses.
5. Remove accepted immediate definitions and substitute the literal at every eligible use.
6. Apply the original allocation and normal target code generation.
