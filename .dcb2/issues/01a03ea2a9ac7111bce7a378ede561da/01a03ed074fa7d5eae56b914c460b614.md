# Trial result

Retained an optional quotient-reuse checkpoint with strong generated-code reduction, but the bounded edigits quick runtime sample regressed 0.13%. Canonical routine benchmarks regressed.

## Evidence

## Important changes

- **Adjacent signed Int64 div/rem fusion** — **Reason:** reuse one truncating quotient for an immediately following identical-operand `%` reconstruction.
- **LIR and E2E regression coverage** — **Reason:** prove one `Sdiv`/one `Msub` in both operand orders and preserve Euclidean behavior for negative dividends.
- **edigits investigation measurement record** — **Reason:** document the codegen win, conflicting bounded runtime result, and close the completed candidate.

## How it works

Baseline edigits lowering emitted a separate signed divide for `/` and `%`. The candidate fuses only adjacent signed Int64 pairs with structurally identical operands, preserving the existing Euclidean correction and divisor-error ordering. Full edigits generated code removed 50 post-allocation LIR SDIVs and 25 ARM64 SDIVs, but the existing quick edigits runtime sample was slightly regressive, so this is retained only as an optional checkpoint.

## Algorithm

1. Match adjacent `/` then `%`, or `%` then `/`, with identical signed Int64 operands.
2. Materialize operands once and emit one `SDIV` into the quotient destination.
3. Reconstruct the remainder with `MSUB quotient * divisor`.
4. Apply the existing Euclidean remainder adjustment.
5. Preserve the existing negative-divisor branch placement for each source ordering; leave standalone lowering unchanged.
