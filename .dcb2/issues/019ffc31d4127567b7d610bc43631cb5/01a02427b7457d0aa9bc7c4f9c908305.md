# Implementation plan

Revalidated at compiler C@8040d9201cfe91a298aea0deeadb8234dc523896 against interpreter I@04fbe9dcc995c6188757d583e273cbd30a3e2d3d. The revised direction is an ordinary Dark single-case type, `type Uuid = UUID(UInt128)`: no AST primitive, ownership shape, native intrinsic, backend lowering, or UUID-specific runtime support.

## Response to feedback

The feedback rejects all dedicated compiler and native UUID machinery: UUID must be represented and implemented entirely with existing Dark language features.

## What changed

- Removed the proposed AST.TUuid primitive, UUID runtime scalar, ownership changes, private UUID intrinsics, MIR/LIR instructions, runtime routines, and ARM64/x64 lowering.
- Replaced the representation with the ordinary Dark newtype `type Uuid = UUID(UInt128)`, relying on existing sum-type and UInt128 behavior.
- Rewrote parsing, formatting, generation, equality, rendering, and JSON scope around standard-Dark functions and codecs.
- Added an explicit exclusion for new UUID-specific compiler support.

## Why

A single-case `UUID(UInt128)` sum provides a distinct value at the language and runtime level using already-supported ordinary data structures. Its payload supplies stable structural equality, while parse, generation, and canonical text conversion can be expressed in the standard library without extending the compiler pipeline.
