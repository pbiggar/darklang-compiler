# Implementation plan

Revalidated at current compiler C@6d6aa2ade9053d4e2bc6e852ca7291609027f720, accepted compiler baseline C@1ee3513aeded5eee6c4bac5779ee1aae9632f86b, retained source-evidence revision C@51093e0a8e31fe45a9aa79a317fbefd6b74fbcc3, and interpreter I@04fbe9dcc995c6188757d583e273cbd30a3e2d3d. DCB1 report 8a402797 was used only as starting evidence. The current UUID implementation still matches the pinned compiler finding; only unrelated work has advanced HEAD.

## Work item 01a0100dd31e72b7b04063844017567e

Title: Distinct semantic Uuid type

Category: behavior

Evidence: C@6d6aa2 stdlib/Types.dark:3 declares `type Uuid = String`; ANF.fs:390,536-538 maps Uuid to DynamicString; parser primitive handling is adjacent to DateTime at 1_Parser.fs:603 and 1_InterpreterParser.fs:773. I@04fb exposes TUuid in Pure/Libs/Uuid.fs:27-35,55-59.

Outcome:

Introduce primitive AST.TUuid, recognize `Uuid` in both compiler and interpreter syntax modes, remove the `Uuid = String` alias and every `TRecord("Uuid")` special case, and preserve TUuid through name resolution, type checking, monomorphization, ANF, MIR, LIR, and register allocation. Reject implicit Uuid/String conversion during ahead-of-time type checking.

## Work item 01a0100dd31e72178178fca0df625a83

Title: Dedicated 128-bit runtime representation

Category: behavior

Evidence: C@6d6aa2 ANF.fs:390,536-538 explicitly gives Uuid String ownership; current Binary.fs:126-129 UUID is only an unrelated Mach-O load-command payload. I@04fb stores runtime UUIDs as DUuid(System.Guid) in Pure/Libs/Uuid.fs:46 and Random/Libs/Uuid.fs:18.

Outcome:

Represent Uuid as a dedicated two-word, 128-bit value with explicit construction, high/low word access, equality, ownership planning, and ARM64 plus x64 code generation. Preserve exact UUID bits through calls, results, tuples, lists, records, Result payloads, and closures; never reuse the dynamic-String buffer representation or String pointer identity.

## Work item 01a0100dd31e76a193a3290dbd5115ff

Title: Canonical public Uuid API

Category: behavior

Evidence: C@51093 and C@6d6aa2 stdlib/Uuid.dark:10-91 expose String-typed helpers and versioned names; I@04fb packages/darklang/stdlib/uuid.dark:4-16 contains exactly the canonical API and single BadFormat case.

Outcome:

Copy the pinned interpreter package surface into Stdlib.Uuid: `generate():Uuid`, `parse(String):Result<Uuid,Uuid.ParseError>`, and `toString(Uuid):String`, with `ParseError` containing only `BadFormat`. Map the interpreter's underlying host operations to private compiler intrinsics without exposing additional Builtin UUID functions publicly.

## Work item 01a0100dd31e79ffa2934ae7739b2871

Title: Delete all legacy UUID behavior

Category: behavior

Evidence: C@6d6aa2 Uuid.dark:10,14-91 defines the legacy surface; 1.7_JsonPlanning.fs:728-733 calls parse_v0. Current UUID callers translated to parse_v0 include upstream stdlib/uuid.dark, json.dark, nomodule.dark, cli/scm-partial-commit.dark, and language/big.dark. I@04fb has none of these UUID compatibility names.

Outcome:

Remove `parse_v0`, `toString_v0`, `UnsupportedUuidParseError`, the fixed-hyphen parser, and the old hex helper surface. Update every compiler, JSON, and test caller to canonical `Uuid.parse` and `Uuid.toString`; retain no compatibility wrapper, alternate error type, or compiler-only formatter.

## Work item 01a0100dd31e7b828e60d02c47c8b2c1

Title: Guid.TryParse parity

Category: behavior

Evidence: C@6d6aa2 Uuid.dark:21-38 accepts only one fixed 36-byte hyphenated spelling and returns the original String. I@04fb Pure/Libs/Uuid.fs:44-47 delegates to System.Guid.TryParse and maps every failure to BadFormat. A same-host .NET 10.0.203 probe confirmed N/D/B/P/X and uppercase inputs normalize to canonical D output while wrong lengths and separators fail.

Outcome:

Implement the exact public parse behavior of the pinned interpreter: successful N, D, braced B, parenthesized P, and hexadecimal X forms normalize to one UUID; uppercase hex is accepted; malformed separators, wrong lengths, Unicode text, and every other invalid spelling return `Error(ParseError.BadFormat)`. Cover outer whitespace and the exact whitespace permitted inside X-format components with focused tests derived from the interpreter host behavior.

## Work item 01a0100dd31e76f3a8e6c95623f3cc71

Title: Canonical formatting and result rendering

Category: behavior

Evidence: C@6d6aa2 Uuid.dark:12 is a String identity function; ValueRendering.fs:526-531 and PrintInsertion.fs:91-101 special-case DateTime but let the String-backed Uuid follow generic String rendering. I@04fb Pure/Libs/Uuid.fs:55-64 returns `DString(string uuid)`, and packages/darklang/stdlib/uuid.dark:15-16 specifies the canonical format.

Outcome:

Format every Uuid as lowercase 8-4-4-4-12 hyphenated text. Use this formatter for public toString, implicit final-value rendering, and nested value rendering, while explicit print and String APIs require an explicit Uuid.toString conversion.

## Work item 01a0100dd31e7b29a5451e9603f12ae3

Title: Version-4 generation

Category: behavior

Evidence: C@6d6aa2 Uuid.dark:56-91 builds a String from two Random.int64 calls; Runtime.fs:2382-2432 implements the existing secure-random primitive. I@04fb packages/darklang/stdlib/uuid.dark:6-7 and Random/Libs/Uuid.fs:11-25 return `DUuid(System.Guid.NewGuid())`.

Outcome:

Generate distinct RFC-4122 version-4 Uuid values with the version nibble set to 4 and variant bits set to 10xx. Generation consumes the native secure random source and constructs the dedicated 128-bit value directly; it never exposes or stores an intermediate UUID String.

## Work item 01a0100dd31e78eb95a0e701420436c2

Title: UUID equality

Category: behavior

Evidence: C@6d6aa2 currently inherits String specialization from the String alias; comparison-parity.md explicitly records this as an extension. I@04fb Pure/Libs/NoModule.fs:58-60 compares DUuid structurally and lines 135-162 rejects mixed value categories.

Outcome:

Define direct equality and Stdlib.equals<Uuid> by comparing both 128-bit payload words, including values nested in tuples, lists, records, Results, and other generated structural equality helpers. Equivalent accepted spellings are equal, distinct UUIDs are unequal, and mixed Uuid/String operands are rejected ahead of time rather than falling back to String comparison.

## Work item 01a0100dd31e7a76be9b2355bd72d273

Title: Canonical JSON round-trip

Remove the TRecord("Uuid") JSON special cases in favor of TUuid.
