# Implementation plan

Revalidated at current compiler C@5ea20b4410d1642b6fc808fc530ee8718366606b, accepted compiler baseline C@1ee3513aeded5eee6c4bac5779ee1aae9632f86b, retained source-evidence compiler C@51093e0a8e31fe45a9aa79a317fbefd6b74fbcc3, and interpreter I@04fbe9dcc995c6188757d583e273cbd30a3e2d3d. DCB1 report 8a402797 was starting evidence only. Current UUID source is unchanged from the accepted finding; only unrelated commits advanced HEAD.

## Work item 01a0102f85f97b40858d713e21e95e39

Title: Distinct semantic Uuid type

Category: behavior

Evidence: C@5ea20 stdlib/Types.dark:3 declares `type Uuid = String`; ANF.fs:390,536-538 maps it to DynamicString. I@04fb uses TUuid and DUuid in Pure/Libs/Uuid.fs:27-35,55-59.

Outcome:

Introduce primitive AST.TUuid in both syntax modes, remove `Uuid = String` and all `TRecord("Uuid")` cases, and preserve TUuid through resolution, type checking, specialization, ANF, MIR, LIR, and register allocation. Reject implicit Uuid/String conversion ahead of time.

## Work item 01a0102f85f9723ebcb3afb8fd78ee46

Title: Dedicated 128-bit runtime value

Category: behavior

Evidence: C@5ea20 ANF.fs:390,536-538 explicitly assigns Uuid the DynamicString ownership shape. I@04fb carries DUuid(System.Guid) at Pure/Libs/Uuid.fs:46 and Random/Libs/Uuid.fs:18.

Outcome:

Represent Uuid as one dedicated handle to an immutable fixed 16-byte UUID payload, with an explicit textual-order high/low word encoding, construction and word-access primitives, ownership planning, and ARM64 plus x64 lowering. Never reuse String storage or pointer identity, and preserve exact bits across calls, containers, Results, records, tuples, and closures.

## Work item 01a0102f85f97337a8e7562765bbc494

Title: Canonical public API

Category: behavior

Evidence: C@51093 and C@5ea20 stdlib/Uuid.dark:10-91 expose String-backed and versioned helpers. I@04fb packages/darklang/stdlib/uuid.dark:4-16 is the exact canonical three-function surface.

Outcome:

Match the interpreter package surface exactly: `generate():Uuid`, `parse(String):Result<Uuid,Stdlib.Uuid.ParseError>`, and `toString(Uuid):String`, with `ParseError` containing only `BadFormat`. Implement host operations as private compiler intrinsics rather than adding public Builtin UUID functions.

## Work item 01a0102f85f976688d231efc34e9f1bc

Title: Remove legacy UUID behavior

Category: behavior

Evidence: C@5ea20 Uuid.dark:10,14-91 defines the legacy surface; 1.7_JsonPlanning.fs:731 and upstream UUID tests call parse_v0. I@04fb has no UUID versioned API or unsupported-error case.

Outcome:

Delete `parse_v0`, `toString_v0`, `UnsupportedUuidParseError`, the fixed-hyphen parser, and old hex-conversion helpers. Update every UUID call site in compiler passes and tests to canonical names, and ensure removed names no longer resolve.

## Work item 01a0102f85f97c70b6442374b887293d

Title: Interpreter parsing parity

Category: behavior

Evidence: C@5ea20 Uuid.dark:21-38 accepts only a 36-byte hyphenated form and preserves its input. I@04fb Pure/Libs/Uuid.fs:44-47 uses System.Guid.TryParse. A .NET 10.0.203 same-source probe confirmed N/D/B/P/X and uppercase inputs normalize to canonical D output while malformed forms fail.

Outcome:

Accept exactly the interpreter host grammar: case-insensitive N, D, braced B, parenthesized P, and hexadecimal X forms, including host-permitted leading/trailing and X-component whitespace. Normalize every accepted spelling to the same UUID and return only `Error(BadFormat)` for malformed separators, wrong lengths, Unicode text, or any other rejected input.

## Work item 01a0102f85f97b60809dbec9e6aa9162

Title: Canonical formatting and rendering

Category: behavior

Evidence: C@5ea20 Uuid.dark:12 is String identity, while ValueRendering and PrintInsertion have DateTime-specific rendering but no distinct Uuid case. I@04fb Pure/Libs/Uuid.fs:55-64 returns `string uuid`; packages/darklang/stdlib/uuid.dark:15-16 specifies canonical output.

Outcome:

Format Uuid as lowercase 8-4-4-4-12 hyphenated text. Use that formatter for public toString, implicit final-result rendering, and nested display, while explicit print and String operations require explicit conversion.

## Work item 01a0102f85f9757ab6b7d156bd06ef0a

Title: Version-4 generation

Category: behavior

Evidence: C@5ea20 Uuid.dark:56-91 generates a String from two Random.int64 values; Runtime.fs:2382-2432 supplies secure native randomness. I@04fb packages/darklang/stdlib/uuid.dark:6-7 and Random/Libs/Uuid.fs:11-25 use DUuid(Guid.NewGuid()).

Outcome:

Generate distinct RFC-4122 version-4 UUID values directly in the dedicated representation: random bits, version nibble 4, and variant bits 10xx. No generated UUID may pass through a String intermediate.

## Work item 01a0102f85f97d0da86e918830340e24

Title: Payload equality

Category: behavior

Evidence: C@5ea20 inherits String equality from the alias; docs/comparison-parity.md records that extension. I@04fb Pure/Libs/NoModule.fs:58-60 compares DUuid structurally and lines 135-162 rejects mixed categories.

Outcome:

Compare direct `==`, `!=`, and Stdlib.equals<Uuid> by both UUID words, including nested structural equality. Equivalent accepted spellings are equal, different UUIDs are unequal, and mixed Uuid/String operands are statically rejected rather than compared as Strings.

## Work item 01a0102f85f971b08d15cf31552f8715
