## Response to feedback

The feedback requires replacing the former String-backed storage proposal with an explicit opaque `UUID(UInt128)` runtime value, while retaining the accepted interpreter-parity scope as one contained implementation.

## What changed

- Replaced the prior dedicated heap-handle/String-ownership framing with a UUID(UInt128) scalar work item and two-word ABI/storage scope.
- Merged primitive typing, runtime representation, ownership, and cross-container transport around the UUID(UInt128) boundary.
- Reframed parse_v0 and UnsupportedUuidParseError as an isolated compatibility extension rather than canonical API behavior.
- Retained the canonical parsing, generation, formatting, equality, JSON, tests, documentation, and dual-backend validation work within one implementation result.

## Why

A UInt128-backed opaque UUID directly prevents String substitution while preserving all 128 bits through compiler IR and native lowering. Separating compatibility behavior keeps canonical interpreter parity unambiguous without leaving compiler passes dependent on legacy names.
