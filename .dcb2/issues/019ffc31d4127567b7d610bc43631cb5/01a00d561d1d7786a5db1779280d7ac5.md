# Implementation plan

Revalidated interpreter I@04fbe9dcc995c6188757d583e273cbd30a3e2d3d against accepted compiler baseline C@1ee3513aeded5eee6c4bac5779ee1aae9632f86b, retained source evidence C@51093e0a8e31fe45a9aa79a317fbefd6b74fbcc3, and worktree C@46465ea5336d174128329105a8052aea05f091fc. The canonical Stdlib.Uuid contract will contain only ParseError.BadFormat; parse_v0 and UnsupportedUuidParseError are isolated legacy compatibility extensions and are never used by canonical parsing, formatting, JSON, equality, or parity tests.

## Work item 01a00d561d1d710a8e4c302082e108e1

Title: Distinct source and runtime Uuid type

Category: type

Evidence: C@51093 stdlib/Types.dark:3 declares Uuid = String; current ANF.fs:390,536-538 maps TRecord("Uuid") to DynamicString, while I@04fb exposes TUuid and DUuid in Pure/Libs/Uuid.fs:27-35,55-59.

Outcome:

Replace the String alias with a nominal primitive AST.TUuid, parse Uuid directly in both syntax modes, preserve TUuid through type checking, monomorphization, ANF, MIR, LIR, and register allocation, and reject implicit Uuid/String conversion.

## Work item 01a00d561d1d77ebb1501b905ae18280

Title: Dedicated 128-bit runtime representation

Category: type

Evidence: C current ANF RcShape routes Uuid through DynamicString at ANF.fs:390,536-538; Runtime.fs currently has UUID only for unrelated Mach-O load commands at Binary.fs:126-129. I@04fb uses DUuid(System.Guid) at Pure/Libs/Uuid.fs:46 and Random/Libs/Uuid.fs:18.

Outcome:

Represent Uuid as a dedicated fixed 128-bit high/low value rather than a String, with explicit construction and word access, ownership metadata, retain/release planning, and ARM64 plus x64 code generation; preserve exact bits across calls, containers, closures, and results.

## Work item 01a00d561d1d7a54b8b231485e34a72b

Title: Canonical public Uuid API

Category: function

Evidence: C@51093 stdlib/Uuid.dark:8-38 exposes String-backed parse_v0 and error extensions; I@04fb packages/darklang/stdlib/uuid.dark:4-16 is the exact canonical surface, with only BadFormat at line 4.

Outcome:

Expose exactly the interpreter's canonical API: generate():Uuid, parse(String):Result<Uuid,Uuid.ParseError>, and toString(Uuid):String, with ParseError containing only BadFormat; remove toString_v0 and old String-typed internals from the canonical module.

## Work item 01a00d561d1d7acb9cccd7672608edec

Title: Guid.TryParse parity and normalization

Category: behavior

Evidence: C@51093 Uuid.dark:21-38 accepts only a fixed 36-byte hyphenated spelling; I@04fb Pure/Libs/Uuid.fs:44-47 delegates to System.Guid.TryParse. A .NET 10.0.203 same-source probe confirmed N/D/B/P/X, uppercase input, and outer whitespace normalize to the same canonical D output while malformed lengths and separators fail.

Outcome:

Implement canonical parsing with the pinned interpreter's accepted grammar: case-insensitive D, N, braced B, parenthesized P, and X forms, including permitted surrounding/internal parser whitespace; normalize all accepted spellings to one 128-bit Uuid and return BadFormat for every malformed, wrong-length, non-ASCII-hex, or Unicode input.

## Work item 01a00d561d1d7e6582ed80a67301792f

Title: Canonical formatting and boundary rendering

Category: behavior

Evidence: C@51093 Uuid.dark:12 is an identity String function and parse_v0 returns its input at lines 31-38; I@04fb Pure/Libs/Uuid.fs:63 uses Guid.ToString(), and packages/darklang/stdlib/uuid.dark:15-16 specifies the canonical textual form.

Outcome:

Format Uuid as lowercase 8-4-4-4-12 hyphenated text; use this formatter for explicit toString and implicit final-value rendering, while explicit print and String APIs require toString first.

## Work item 01a00d561d1d7e0390fd9941d01d7c9f

Title: Version-4 generation returns Uuid

Category: behavior

Evidence: C@51093 Uuid.dark:56-91 constructs only a formatted String from Random.int64; I@04fb packages/darklang/stdlib/uuid.dark:6-7 and Random/Libs/Uuid.fs:11-25 return DUuid(System.Guid.NewGuid()).

Outcome:

Generate distinct RFC-4122 version-4 Uuid values with exactly 128 random-notation bits, version nibble 4, and variant 10xx; retain existing OS randomness but make generation and all intermediate values non-String and verify two generations differ.

## Work item 01a00d561d1d7009b6630f970aea6d9e

Title: Value equality by 128 bits

Category: behavior

Evidence: C current docs/comparison-parity.md:92-97 records String-backed UUID equality as an extension; I@04fb Pure/Libs/NoModule.fs:58-60,153 compares distinct DUuid values structurally and rejects mixed categories.

Outcome:

Define direct and generic equality on the two UUID words, make equivalent accepted spellings equal and different UUIDs unequal, support Uuid nested in tuples/lists/results/records, and statically reject mixed Uuid/String operands rather than falling back to String equality.

## Work item 01a00d561d1d70dd8ec5b4fd190fa4d7

Title: Canonical JSON serialization and deserialization

Category: behavior

Evidence: C current 1.7_JsonPlanning.fs:328 quotes the current String value and lines 728-733 call parse_v0; I@04fb Pure/Libs/Json.fs:128 serializes string uuid and lines 525-529 constructs DUuid from a JSON string; interpreter JSON UUID tests are at backend/testfiles/execution/stdlib/json.dark:891-918.

## Work item 01a00d561d1d7d47b3c2018126292dcb
