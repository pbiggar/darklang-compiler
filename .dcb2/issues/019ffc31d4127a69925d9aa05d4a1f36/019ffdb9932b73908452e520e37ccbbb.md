# Design brief

## Problem

At compiler 21ab0c873bcee2f83c95f7e7b319787c2b866128, the CLI presentation surface provided by darklang/dark 04fbe9dcc995c6188757d583e273cbd30a3e2d3d remains unavailable, preventing same-source programs from matching observable terminal behavior.

## Goals

- Match interpreter logging, styling, progress, prompting, spinner, and table behavior.
- Preserve output destination, formatting, newline, TTY, redirected-input, and interruption semantics.
- Classify compiler-only extensions and intentional AOT divergences explicitly.

## Proposed solution

Deliver one compatibility slice that copies the interpreter’s portable ANSI and rendering behavior as directly as practical, backed by native runtime primitives for terminal input/output, cursor control, timing, TTY detection, and interruption handling. Treat the pinned interpreter revision as authoritative, use historical reports only to locate candidates, and exclude non-observable performance differences.

## Success criteria

- Same-source programs match visible output, destination, formatting, and newline behavior at the pinned revisions.
- Interactive and redirected execution have deterministic baseline-compatible behavior.
- Interrupted operations leave deterministic, baseline-compatible observable output and terminal state.
- Every remaining difference is evidence-backed and classified as a compiler extension or intentional divergence.
