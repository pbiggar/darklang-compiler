# Design brief

## Problem

At compiler C@51093e0a8e31fe45a9aa79a317fbefd6b74fbcc3, CLI presentation behavior available in interpreter I@04fbe9dcc995c6188757d583e273cbd30a3e2d3d is absent, preventing presentation-oriented programs from behaving consistently across execution modes.

## Goals

- Match interpreter-observable logging, ANSI styling, progress, prompt, spinner, and table behavior.
- Preserve output destinations, formatting, newline, terminal, non-terminal, and interruption semantics.
- Explicitly classify any compiler-only extensions or intentional divergences against the pinned revisions.

## Proposed solution

Deliver one coherent compatibility slice that reproduces the interpreter’s public rendering and ANSI behavior while expressing terminal output, input, cursor control, timing, TTY detection, and interruption through explicit runtime capabilities. Treat the pinned interpreter revision as the baseline, retain findings from DCB1 report 8a402797 and current parity documents only when revalidated, and record exact revisions with every comparison.

## Success criteria

- Equivalent same-source programs produce matching visible output, destinations, formatting, and newline behavior on the pinned compiler and interpreter revisions.
- Interactive presentation behaves consistently on terminals, while redirected execution and interrupted operations have deterministic observable outcomes.
- All requested presentation capabilities are available without relying on hidden host behavior.
- Current source evidence and focused comparisons support each retained gap, with extensions and divergences clearly classified.
