# Design brief

## Problem

At compiler C@51093e0a8e31fe45a9aa79a317fbefd6b74fbcc3, CLI presentation capabilities present in interpreter I@04fbe9dcc995c6188757d583e273cbd30a3e2d3d are absent, preventing equivalent programs from producing consistent observable behavior.

## Goals

- Match interpreter-observable logging, styling, progress, prompting, spinner, and table behavior.
- Preserve output destination, formatting, newline, TTY, non-TTY, and interruption semantics.
- Explicitly classify compiler-only extensions and intentional divergences against the pinned revisions.
- Support retained gaps with current source evidence and focused same-source probes where practical.

## Proposed solution

Deliver one compatibility slice using interpreter I@04fbe9dcc995c6188757d583e273cbd30a3e2d3d as the public-behavior baseline for compiler C@51093e0a8e31fe45a9aa79a317fbefd6b74fbcc3. Copy the interpreter’s presentation and ANSI rendering logic as directly as practical, while expressing input, output, cursor control, timing, TTY detection, and interruption through explicit compiler runtime primitives. Revalidate earlier reports and parity documents rather than treating them as authoritative.

## Success criteria

- Equivalent same-source programs match visible output, destination, formatting, and newline behavior at the pinned revisions.
- Interactive terminal behavior is compatible, while redirected execution and interrupted operations have deterministic observable outcomes.
- All requested presentation capability families are available without hidden host dependencies.
- Every retained difference is evidence-backed and classified as a parity gap, compiler-only extension, or intentional divergence.
