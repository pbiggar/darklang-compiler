# Implementation plan

Prepared on live worktree ebb164bfb7c408fcb64dfc9594ba4a90e204956a. Every parity comparison is anchored to compiler HEAD b2e1f3d1e4ce0338d4c4662db9a1326f2e2cb899 and interpreter 04fbe9dcc995c6188757d583e273cbd30a3e2d3d; DCB1 report 8a402797 was used only as an inventory. The live compiler still retains the identified generic public boundary, so this remains one contained Dict delivery.

## Work item 019ffdf84c1a7dca95a5288b4f4c03a9

Title: Expose single-parameter string-keyed Dict typing

Category: type

Evidence: Current AST.fs:57 stores TDict(key,value); 1_Parser.fs:558-575 accepts both Dict<K,V> and Dict<V>; 1.5_TypeChecking.fs:97,1392-1401 propagates both types. Interpreter ProgramTypes has one-argument TDict and its parser accepts one inner type: [ProgramTypes.fs](https://github.com/darklang/dark/blob/04fbe9dcc995c6188757d583e273cbd30a3e2d3d/backend/src/LibExecution/ProgramTypes.fs#L363-L368), [Parser.fs](https://github.com/darklang/dark/blob/04fbe9dcc995c6188757d583e273cbd30a3e2d3d/backend/src/LibParser/Parser.fs#L2536-L2540).

Outcome:

Make public source syntax, pretty-printing, inference, unification, and diagnostics expose only Dict<'value>, lowering it internally to the existing String-key HAMT specialization. Reject Dict<K,V>, non-String public keys, and invalid explicit type applications statically while retaining the two-component internal representation needed by native helpers.

## Work item 019ffdf84c1a74e1996f4b21ed6053c3

Title: Keep generic HAMT operations behind the public boundary

Category: other

Evidence: Stdlib.fs:150-166 registers generic Dict/key intrinsics; stdlib/__HAMT.dark contains the generic implementation; stdlib/String.dark:292-302 and unicode_data.dark use Int64-keyed dictionaries. stdlib_internals.e2e already proves __HAMT names are inaccessible to user code.

Outcome:

Preserve generic TDict nodes, monomorphized hashing/equality intrinsics, collision handling, structural sharing, and typed retain/release plans as private implementation machinery. Route compiler-owned Int64 and other generic-key consumers through internal helpers instead of the public Dict module, and retain internal coverage for those specializations.

## Work item 019ffdf84c1a7fdc9f17698524893834

Title: Add interpreter-compatible Dict literals

Category: behavior

Evidence: AST.fs has no Dict expression case; 1_Parser.fs:1766-1769 and 1913-1915 treat uppercase names followed by braces as records; TestRunner.fs:190-192 explicitly excludes edict.dark for this reason. Interpreter defines EDict and a dedicated parser: [ProgramTypes.fs](https://github.com/darklang/dark/blob/04fbe9dcc995c6188757d583e273cbd30a3e2d3d/backend/src/LibExecution/ProgramTypes.fs#L451-L456), [Parser.fs](https://github.com/darklang/dark/blob/04fbe9dcc995c6188757d583e273cbd30a3e2d3d/backend/src/LibParser/Parser.fs#L2292-L2338).

Outcome:

Represent and parse Dict { key = value; ... } distinctly from records in both source parsers, including empty literals, escaped keys, and the interpreter's ___ spelling for the empty-string key. Infer one value type, preserve source evaluation order, lower entries into the private HAMT, and reject duplicate literal keys and incompatible value types at the appropriate AOT boundary.

## Work item 019ffdf84c1a7b6786b229c9e11a430d

The pinned public definitions are in [packages/darklang/stdlib/dict.dark](https://github.com/darklang/dark/blob/04fbe9dcc995c6188757d583e273cbd30a3e2d3d/packages/darklang/stdlib/dict.dark).

Return Int from size. Remove entries, fold, and getOrDefault from the public registry while retaining any needed implementations privately.

## Work item 019ffdf84c1a7a14b4f2bff9919a10b6

Title: Separate rejecting and overwriting construction paths

Category: behavior

Evidence: Current stdlib/Dict.dark:25-30 sends both set variants to the same overwriting helper; lines 75-79 return Dict directly from merge/fromList. The interpreter implements ThrowIfDuplicate versus ReplaceValue and the two constructor result shapes in [Dict.fs](https://github.com/darklang/dark/blob/04fbe9dcc995c6188757d583e273cbd30a3e2d3d/backend/src/Builtins/Builtins.Pure/Libs/Dict.fs) and [TypeChecker.fs](https://github.com/darklang/dark/blob/04fbe9dcc995c6188757d583e273cbd30a3e2d3d/backend/src/LibExecution/TypeChecker.fs#L764-L781).

Outcome:

Make set reject an existing key, make setOverridingDuplicates replace it, make fromList return Option<Dict<'a>> with None for any duplicate, and make fromListOverwritingDuplicates return Dict<'a> with the last occurrence winning. Preserve right-biased merge, absent-key remove as a no-op, and Some/None lookup behavior for present and missing keys.

## Work item 019ffdf84c1a7af79a6278643da18235

Title: Carry dynamic Dict failures through native code

Category: behavior

Evidence: AST.RuntimeError and LIR.RuntimeError carry only static strings; 2_AST_to_ANF.fs:4379 substitutes <runtime error> when a message is dynamic; arm64/6_CodeGen.fs:4367-4378, x64/6_CodeGen.fs:2824-2845, and Runtime.fs:950 only emit fixed bytes. Interpreter duplicate insertion raises an error containing the actual key in [TypeChecker.fs](https://github.com/darklang/dark/blob/04fbe9dcc995c6188757d583e273cbd30a3e2d3d/backend/src/LibExecution/TypeChecker.fs#L764-L781).

Outcome:

Preserve the runtime key in duplicate-set failures so both architectures emit the interpreter-compatible Cannot add two dictionary entries message for dynamic keys. Extend the runtime-error lowering only as far as needed to print a dynamic String safely, while keeping statically knowable key, value, generic, arity, and callback-shape failures as AOT diagnostics.

## Work item 019ffdf84c1a7e2487ea89de849780f1

Title: Match higher-order Dict operations

Category: function

Evidence: Current stdlib/Dict.dark:69-73 uses tuple-style generic-key callbacks and has no iter/filterMap. stdlib/__HAMT.dark:676-720 also drops collision nodes from filter and merge branches. The pinned Dark implementations are directly reusable from [packages/darklang/stdlib/dict.dark](https://github.com/darklang/dark/blob/04fbe9dcc995c6188757d583e273cbd30a3e2d3d/packages/darklang/stdlib/dict.dark).

Outcome:

Implement map, iter, filter, and filterMap with callbacks receiving String then value, matching the pinned return shapes: Dict<'b>, Unit, Dict<'a>, and Dict<'b> from Option<'b>. Base the public definitions on toList and the overwriting constructor where practical so callback order, error propagation, filtering, and collision-node behavior follow one path.

## Work item 019ffdf84c1a743e816daa3f8c8c1ded

Title: Align traversal results and callback order

Category: behavior

Evidence: Current __HAMT.dark:590-614 traverses bitmap/collision storage order. The interpreter stores DDict entries in a string Map and keys/values/toList enumerate that Map: [RuntimeTypes.fs](https://github.com/darklang/dark/blob/04fbe9dcc995c6188757d583e273cbd30a3e2d3d/backend/src/LibExecution/RuntimeTypes.fs#L970-L978), [Dict.fs](https://github.com/darklang/dark/blob/04fbe9dcc995c6188757d583e273cbd30a3e2d3d/backend/src/Builtins/Builtins.Pure/Libs/Dict.fs). The pinned stdlib test observes a,b,c from toList.

Outcome:

Use one String-key traversal compatible with the pinned F# Map ordering for keys, values, toList, rendering, equality, and higher-order callbacks. Keep key/value association intact and avoid exposing HAMT bitmap shape, insertion history, or collision layout as observable ordering.

## Work item 019ffdf84c1a7076977096350d0fb0da

Title: Implement content-based Dict equality

Category: behavior

Evidence: 1.5_TypeChecking.fs:1037-1049 does not classify TDict as needing an equality helper, so buildEqExprForType falls through to pointer equality at lines 1095-1111. The interpreter's DDict contains a value type and structural Map entries: [RuntimeTypes.fs](https://github.com/darklang/dark/blob/04fbe9dcc995c6188757d583e273cbd30a3e2d3d/backend/src/LibExecution/RuntimeTypes.fs#L940-L978).

Outcome:

Dispatch == and != for Dict values to type-directed content equality: compare entry counts, require identical String key sets, and compare corresponding values using the existing equality semantics for the concrete value type. Results must be independent of allocation identity, insertion order, structural sharing, and HAMT node shape.
