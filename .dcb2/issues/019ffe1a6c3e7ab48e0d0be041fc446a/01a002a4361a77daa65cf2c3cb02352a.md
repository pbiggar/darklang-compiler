# Trial result

The rebased candidate retained a 24.9% aggregate Code Generation improvement, but failed the strict integration gate because ackermann total median regressed by 1.9%.

## Evidence

## What changed

Resolved the rebase conflict by regenerating the family partition from the target-side convertInstr implementation. The exhaustive dispatcher now routes scalar, composite-print, call, primitive-print, float, heap/refcount, string/blob, raw/system, and platform instructions to independent helpers while retaining new Blob, stdin/stdout effect, and native CLI cases. No tests or benchmark sources changed. Temporary measurement and symbolic-dump instrumentation was removed, the commit message was expanded with current rationale and evidence, and the worktree is clean.

## How it works

The monolithic convertInstr forces each fresh compiler process to JIT the entire ARM64 selector, creating a substantial fixed Code Generation cost. Family helpers reduce that boundary while preserving each original lowering branch. Narrow cold-case outlining was previously ineffective; this design was retained because it partitions material instruction groups and keeps one exhaustive dispatch point. The refreshed batch was heavily contended: the regression fit was weak and estimated the fixed intercept at 52.77ms before versus 37.11ms after, but the per-instruction slope moved from 0.006978 to 0.008043ms. Aggregate results remained strong, yet ackermann total median rose 2.05ms. Under the issue's no-total-regression rule, that single regression prevents integration. Residual risk is timing instability on the shared host, not generated-code correctness.

## Algorithm

1. Exhaustively match every LIR instruction in convertInstr. 2. Classify it into one of nine semantic families. 3. Pass the unchanged instruction and CodeGenContext to that family's independently compiled helper. 4. Run the original lowering branch without changing diagnostics or instruction order. 5. Crash explicitly if an impossible dispatcher/helper mismatch occurs. 6. Concatenate returned symbolic instructions exactly as before.
