# Implementation plan

`Stdlib.Html.voidElements` is an accidental compiler-only public value: it is registered in `Stdlib.fs` and special-cased twice in AST→ANF lowering solely to supply the list used by `Stdlib.Html.nodeToString`. The pinned interpreter does not expose it.

## Work item 01a0310883507370bf588dbad20fc02f

Title: Replace the public void-element value

Category: other

Evidence: The only consumer in the Html module is `nodeToString`; no public interpreter API requires `Html.voidElements`.

Outcome:

Keep void-tag detection internal to `Html.dark` through ordinary functions, while preserving HTML serialization behavior.

## Work item 01a03108835079398b74c736ee72d9d6

Title: Remove compiler-specific Html handling

Category: other

Evidence: Those branches exist exclusively to materialize `Stdlib.Html.voidElements`.

Outcome:

Delete the Html entry from the compiler-visible value registry and both AST→ANF literal-materialization branches.

## Work item 01a031088350743ba2f9c1063bb4c6de

Title: Update coverage and parity documentation

Category: other

Evidence: `html_http.e2e` currently asserts the value, and the parity documentation inconsistently calls `Html.s` the sole extension.

Outcome:

Remove the public-value assertion and correct documentation so it no longer describes `Html.voidElements` as part of the active surface.
