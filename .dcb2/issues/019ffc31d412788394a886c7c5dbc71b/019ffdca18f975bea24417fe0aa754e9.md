# Design brief

## Problem

The compiler’s collection surface diverges from the interpreter in availability, Int-based contracts, call shape, bounds and error behavior, and validated sorting semantics.

## Goals

- Match observable interpreter behavior using compiler 3514213a33a0a67562d33f9aa16478863ad9c11c and darklang/dark 04fbe9dcc995c6188757d583e273cbd30a3e2d3d as the exact comparison pair.
- Complete the collection surface while explicitly classifying retained compiler extensions and intentional ahead-of-time type-checking divergences.

## Proposed solution

Port the interpreter’s collection and merge-sort algorithms, standardize public counts and indices on Int with canonical currying and argument order, reproduce ordering, bounds, comparator validation, and structured errors, and add only the minimal primitives needed for generic ordering and random selection. Retain the specified compiler extensions as documented additions while preserving appropriate static rejection of type-invalid programs.

## Success criteria

- Equivalent collection programs produce matching values, ordering, options, results, and errors.
- Index, count, range, chunking, and empty-input behavior matches the interpreter contract.
- Sorting uses the canonical algorithm and rejects invalid comparator values with the canonical error.
- Random selection preserves the interpreter’s empty and non-empty guarantees.
- Compiler-only extensions and intentional static phase differences are clearly documented against the pinned revisions.
