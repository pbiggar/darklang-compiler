# Design brief

## Problem

Compiled programs do not yet match the interpreter’s observable floating-point and mathematics behavior across parsing, formatting, rounding, classification, and transcendental operations.

## Goals

- Match the interpreter’s public behavior at compiler revision 51093e0a8e31fe45a9aa79a317fbefd6b74fbcc3 and interpreter revision 04fbe9dcc995c6188757d583e273cbd30a3e2d3d.
- Complete the parity surface while retaining and explicitly classifying compiler-only extensions.
- Produce shortest-roundtrip decimal output with interpreter-compatible nonfinite values and preserved negative zero.

## Proposed solution

Treat floating-point and mathematics parity as one coherent compatibility change. Derive semantics from current interpreter behavior using revision-pinned source evidence and focused same-source comparisons, then align the compiler’s public surface, typed parse failures, IEEE classifications, directed and nearest rounding, bounds handling, exponentiation, and transcendental behavior. Replace capped decimal generation with deterministic shortest-roundtrip formatting and document retained extensions or intentional divergences explicitly.

## Success criteria

- Equivalent source programs produce matching values or typed failures across the parity surface at the recorded revisions.
- Finite values format to a shortest representation that round-trips identically; negative zero and nonfinite spellings match the interpreter.
- Rounding boundaries, NaN propagation, infinities, signed zero, invalid transcendental domains, and parsing edge cases exhibit interpreter-compatible behavior.
- Compiler-only capabilities remain available and are clearly distinguished from parity behavior.
- Every retained finding is traceable to current source evidence or a focused behavioral comparison rather than the earlier report alone.

## Open questions

- What ceiling behavior should be canonical where the current interpreter implementation and its observed public behavior remain ambiguous?
- Which exact spelling and notation choices should govern formatting cases where multiple shortest-roundtrip representations are valid or existing interpreter coverage is incomplete?
