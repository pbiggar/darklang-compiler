# Design brief

## Problem

At compiler b2e1f3d1e4ce0338d4c4662db9a1326f2e2cb899, non-recursive binding syntax and scope behavior do not consistently match interpreter 04fbe9dcc995c6188757d583e273cbd30a3e2d3d.

## Goals

- Match interpreter-visible syntax, destructuring, annotations, lexical visibility, shadowing, duplicate-name handling, and use-before-binding behavior.
- Prevent bindings from leaking across failed, skipped, or unselected expressions and branches.
- Remove compiler-only binding forms, migrate repository-authored source, and explicitly document any intentional divergence.
- Keep recursive binding semantics outside this delivery.

## Proposed solution

Adopt the pinned interpreter's public behavior as the binding contract. Represent each non-recursive binding as an atomic lexical scope transition: evaluate its value in the prior environment, validate and destructure the pattern according to interpreter rules, then expose the resulting names only to the subsequent expression region. Apply this consistently through nested expressions, sequencing, conditionals, matches, and lambdas. Align syntax and annotation placement, remove compiler-specific forms, and contain necessary adjacent function or type changes within the same coherent delivery. DCB1 report commit 8a402797 and parity documents serve only as leads; retained conclusions must be re-established against the pinned revisions with same-source behavioral comparisons where practical.

## Success criteria

- Programs accepted by both revisions have matching binding visibility, results, and observable failures.
- Pattern bindings are atomic, and names never escape failed destructuring, skipped expressions, unselected branches, or their lexical region.
- Nested shadowing and duplicate-bound names behave exactly like the interpreter baseline.
- Use-before-binding and annotation placement match interpreter acceptance and diagnostics.
- Compiler-only binding syntax is absent and repository-authored programs use the parity syntax.
- Each claimed parity result records compiler b2e1f3d1e4ce0338d4c4662db9a1326f2e2cb899 and interpreter 04fbe9dcc995c6188757d583e273cbd30a3e2d3d; any remaining divergence is explicitly classified.
