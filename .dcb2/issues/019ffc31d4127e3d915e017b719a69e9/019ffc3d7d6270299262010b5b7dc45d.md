# Design brief

## Problem

At compiler revision 51093e0a8e31fe45a9aa79a317fbefd6b74fbcc3, line-oriented value diffing and typed runtime-value search available in interpreter revision 04fbe9dcc995c6188757d583e273cbd30a3e2d3d are absent, leaving an observable parity gap.

## Goals

- Match current interpreter behavior for diff classification and output ordering.
- Match canonical namespace, path, and type semantics for runtime-value search.
- Record exact revisions for every comparison and explicitly classify intentional divergences or compiler-only extensions.

## Proposed solution

Port the two interpreter modules into the compiler standard library while preserving their public data shapes and observable algorithms. Revalidate prior parity findings against the pinned source revisions and focused same-source comparisons. Use the existing compiler value and type representation for search, introducing a minimal native reflection capability only if equivalent traversal or type identity cannot be expressed directly.

## Success criteria

- Equivalent inputs produce the same ordered diff classifications on both implementations.
- Typed searches produce equivalent matches with canonical namespace, location path, and type handling.
- Every parity claim identifies compiler revision 51093e0a8e31fe45a9aa79a317fbefd6b74fbcc3 and interpreter revision 04fbe9dcc995c6188757d583e273cbd30a3e2d3d, with any divergence explicitly categorized.
- The utilities are available through the compiler standard library without changing unrelated observable behavior.

## Open questions

- Does the compiler’s existing runtime value and type representation expose enough information to reproduce interpreter search semantics without a native reflection capability?
