The two regressions have a common, concrete cause: the candidate adds an explicit mask before every dynamic fixed-width shift in `4_MIR_to_LIR.fs:605-607,624-629`. That is one extra executed `AND` per shift, needed to implement the interpreter’s machine-width shift-count semantics rather than relying on target behavior.

- `merkletrees` (+0.85%, 386,659,268 → 389,935,368 instructions) executes a dynamic left shift at `benchmarks/problems/merkletrees/dark/main.dark:33`: `1 << (depth - 1)`. It runs once for every non-leaf node while building and verifying 100 depth-15 trees, so the added mask is on a very hot path.

- `matmul` (+0.95%, 1,947,578,291 → 1,966,035,941 instructions) is Dict/HAMT dominated. Each lookup and insertion reaches dynamic shifts in `stdlib/__HAMT.dark:62-75`: hash chunk extraction (`hash >> (level * 6)`), bitmap testing (`bitmap >> bit`), and bitmap creation/indexing (`1 << bit`). The benchmark performs two Dict reads for each of one million dot-product iterations, plus repeated Dict updates, amplifying that one-instruction cost.

The final candidate has no additional hot-path change to explain these regressions: its restored `popcount` spelling leaves the SWAR algorithm unchanged, and its positive-constant modulus lowering should reduce work in the modulo sites. The slowdown is therefore attributable to correct shift-count masking, not an incorrect workload result or an integer-wrapper call path.

All affected benchmark shift counts are already in range, so the new mask is redundant for these inputs but preserves the general interpreter contract. The recorded routine result remains net-positive (`0.986089`); the regressions are localized and below 1% each.
