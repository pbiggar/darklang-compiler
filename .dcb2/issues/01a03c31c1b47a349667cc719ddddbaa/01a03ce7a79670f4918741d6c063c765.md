## How it works

The candidate intentionally changes MIR and generated machine code to replace HAMT operations with dense raw-buffer accesses. The registered Pass Optimization verifier requires normalized IR, executable bytes, and runtime output to remain equal. Runtime output matched exactly, but normalized MIR and executable hashes differed, producing correctness-mismatch. Independently, the selected ANF -> MIR timing changed from a 1.4 ms median to 1.3 ms, only 0.1 ms and below the 1.0 ms clear-win threshold. No five-pair confirmation was warranted because the result was invalid under the equality contract and also below threshold. The candidate remains detached at c442f4026790c4759646a1ceb543051eb7a42ccf with a clean worktree. Full tests and routine benchmarks were not run because DCB owns those gates. Residual risk is that this verifier is designed for compiler-pass compile-time optimizations preserving generated artifacts, whereas dense storage is a code-quality transformation expected to change MIR and executable bytes.

## Algorithm

1. Recognize only the exact closed matmul call graph with monomorphic Dict<Int64, Int64> signatures and one bounded literal matrix size. 2. Reject aliases, escapes, unexpected callers, unknown operations, sparse construction, and unsupported sizes. 3. Allocate three length-prefixed contiguous Int64 buffers. 4. Replace eligible HAMT reads and persistent updates with signed bounds checks and eight-byte raw loads or stores. 5. Preserve the generator, dot-product, cell traversal, and checksum recurrences. 6. Release each large raw allocation explicitly. 7. Leave every ineligible program on ordinary Dict/HAMT behavior.

## Important changes

- **Added guarded dense-matrix eligibility analysis** — **Reason:** Restricts lowering to the canonical closed, monomorphic `Dict<Int64, Int64>` call graph with a proven literal size and rejects aliases, escapes, and unknown callers.
- **Lowered eligible matrices to length-prefixed contiguous Int64 buffers** — **Reason:** Replaces repeated HAMT lookups and persistent updates with bounds-checked raw loads and stores.
- **Added explicit large raw-allocation lifetime release** — **Reason:** Balances leak accounting without incorrectly placing 80,016-byte buffers in the existing 8-byte raw free-list class.
- **Added eligibility, escape-rejection, and SSA operand coverage** — **Reason:** Pins the optimization guard and the new release instruction as deterministic compiler-pass behavior.

## How it works

Baseline ANF and MIR showed two HAMT lookups per dot-product iteration, one persistent HAMT update per generated/output cell, and one lookup per checksum cell. The three 100x100 matrices are created within the closed matmul pipeline, populated over exactly 0..9999, accessed only by bounded loop-derived indices, and never passed to unknown code or observable Dict operations. The retained lowering recognizes only that exact ownership graph and literal sizes up to 100; all other Dict programs remain unchanged. Runtime work improved dramatically, although explicit bounds-error paths increased the binary from 13,056 to 14,472 bytes. A post-checkpoint leak probe initially found three live buffers; the retained safety follow-up introduced `RawRelease`, after which leak checking reported zero leaks. Residual risk is concentrated in the deliberately narrow structural recognizer and the static code-size increase. Repository-wide tests and the canonical routine profile were intentionally left to the worker as required.

## Algorithm

1. Find the canonical generator, dot-product, multiplication, checksum, root, and entry functions with exact Int64/Dict signatures.
2. Verify the expected recursive call edges, two input generators, multiplication/checksum flow, one literal matrix size, and absence of any outside caller into the ownership region.
3. Reject the optimization for escapes, aliases, unknown calls, different signatures, sparse/unknown construction, or sizes outside the bounded trial limit.
4. Allocate three buffers containing a length word, dense Int64 cells, and allocation-accounting storage.
5. Generate the two input matrices sequentially into indices 0 through n²−1.
6. Replace each eligible read/write with signed lower-bound and stored-length upper-bound checks followed by an eight-byte contiguous access.
7. Preserve the original dot-product, cell traversal, and checksum recurrences.
8. End each large buffer lifetime with `RawRelease`; ordinary Dict and small `RawFree` behavior remains unchanged.
