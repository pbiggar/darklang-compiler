## How it works

Matmul’s dense, non-escaping Int64 matrices paid HAMT lookup and persistent-update costs despite using zero-based contiguous keys. The preserved candidate recognizes only the closed canonical matrix call graph and substitutes bounds-checked contiguous storage. The registered ANF -> MIR verifier was run first; it reported neutral/noisy pass timing and rejected its equality gate because the optimization intentionally changes MIR and executable bytes, although execution output matched. That verifier does not measure the generated program’s hot-path runtime, so its produced executables were then measured directly with one warmup and three samples each. Runtime improved by 159.595 ms, exceeding the 11.829 ms clear-win threshold. Five interleaved pairs were unnecessary. No alternative implementation was attempted because this was a read-only candidate measurement. The retained design adds a narrow structural recognizer, raw-buffer bounds checks, and explicit release machinery; residual risk is misclassification of future call-graph shapes and the 10.85% binary-size increase. Full tests and canonical routine benchmarks remain DCB-owned gates.

## Algorithm

1. Recognize the exact closed, monomorphic Dict<Int64, Int64> matmul generator, multiplication, dot-product, checksum, root, and entry call graph. 2. Require a proven positive literal matrix size no greater than 100 and reject aliases, escapes, unknown callers, sparse or unknown keys, and incompatible signatures. 3. Allocate three length-prefixed contiguous Int64 buffers. 4. Populate input and result cells at zero-based dense offsets. 5. Replace eligible HAMT reads and persistent updates with signed bounds checks followed by raw eight-byte loads or stores. 6. Preserve the original recursive generation, dot-product, multiplication, and checksum behavior. 7. Explicitly release each large raw allocation; all ineligible Dict values retain ordinary HAMT behavior.
