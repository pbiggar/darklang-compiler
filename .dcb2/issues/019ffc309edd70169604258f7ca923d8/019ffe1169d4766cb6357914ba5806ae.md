## Work item 019ffe1169d47d0c83e3c393363c7679

Title: Model comparison admissibility in the type system

Category: type

Evidence: src/DarkCompiler/passes/1.5_TypeChecking.fs:1847-2033 currently admits Eq/Neq broadly, treats distinct sums as constant false/true, allows Char/String reconciliation, and omits Int128/UInt128 ordering. Probes show 'a' == "a" is true and distinct sums avoid rejection.

Outcome:

Introduce an explicit typed comparison classification. Equality accepts only compatible resolved types and recursively comparable contents; ordering accepts only identical numeric types. Type aliases resolve canonically, while mixed numeric types, Char/String pairs, distinct nominal records or constructors, nonnumeric ordering, and source-visible pointer-like compiler types are rejected.

## Work item 019ffe1169d47989ad58a1b29c5b71e9

Title: Carry comparison plans through generic specialization

Category: type

Evidence: Helper selection occurs in src/DarkCompiler/passes/1.5_TypeChecking.fs:1037-1111,4920-5045,5962-5969 before specialization in CompilerLibrary.fs:828-873. Current generic equality returns false for equal lists and records.

Outcome:

Represent valid comparisons as typed plans that survive type substitution and monomorphization, then materialize concrete comparison helpers for each instantiation. Generic equality consequently uses the same semantics as direct equality without runtime type dispatch.

## Work item 019ffe1169d471d9bfadd170a165c4ac

Title: Consolidate recursive equality lowering

## Work item 019ffe1169d47d1ab82fbd0457f21f63

Title: Encode interpreter-equivalent function identity

Category: type

Evidence: Direct named-partial handling is syntactic in src/DarkCompiler/passes/1.5_TypeChecking.fs:1914-2005; generated function helpers compare only closure slot zero. src/DarkCompiler/passes/4_MIR_to_LIR.fs:831-844 stores only code address plus captures. ## Work item 019ffe1169d47a08a7d50d5d34174696

Title: Complete numeric comparison semantics

Category: behavior

Evidence: src/DarkCompiler/passes/1.5_TypeChecking.fs:2024-2028 and passes/2_AST_to_ANF.fs:2930-2946 omit Int128/UInt128 ordering. Their values are canonical strings at 2_AST_to_ANF.fs:35-38.
