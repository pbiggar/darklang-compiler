# Design brief

## Problem

At compiler b2e1f3d1e4ce0338d4c4662db9a1326f2e2cb899, comparison behavior lacks one verified contract matching interpreter 04fbe9dcc995c6188757d583e273cbd30a3e2d3d.

## Goals

- Match equality and ordering across all required scalar, structural, nested, dictionary-exposed, and function-value categories, including NaN and signed zero.
- Align structural versus nominal semantics, ordering rules, and observable failures while preserving ahead-of-time type checking.
- Use only interpreter operator spellings and explicitly classify compiler extensions and intentional divergences.

## Proposed solution

Adopt a revision-stamped, interpreter-derived comparison contract and enforce its admissibility through ahead-of-time type checking. Lower accepted concrete and statically valid generic comparisons to consistent recursive semantics without introducing polymorphic runtime comparison for expressions that fail type checking. Keep dictionary comparison behavior in scope while leaving key admissibility to the Dict-specific work.

## Success criteria

- Same-source comparisons admitted by the compiler produce interpreter-equivalent results across every required category and nested combination.
- Structural and nominal identity, function equality, numeric ordering, NaN, and signed-zero behavior match the pinned interpreter.
- Statically invalid comparisons fail during compiler type checking with the AOT phase difference explicitly classified, rather than reaching a generic runtime fallback.
- Only interpreter comparison spellings remain, and every retained extension or intentional divergence is documented.
- Dictionary comparison parity is covered without absorbing dictionary key-policy ownership.
