# Design brief

## Problem

At compiler b2e1f3d1e4ce0338d4c4662db9a1326f2e2cb899, equality, ordering, admissibility, and failure behavior are not governed by one verified contract matching interpreter 04fbe9dcc995c6188757d583e273cbd30a3e2d3d.

## Goals

- Match interpreter behavior across all required scalar, structural, nested, dictionary-exposed, and function-value cases, including NaN and signed zero.
- Align structural or nominal semantics, ordering rules, rejection phase, and language-visible failures.
- Remove comparison aliases and explicitly classify any retained compiler-only extensions or intentional divergences.

## Proposed solution

Adopt a single interpreter-derived comparison contract, revision-stamped with both evidence hashes, that defines admissibility and observable behavior recursively for equality and ordering. Apply that contract consistently to comparison type constraints, interpreter-spelled operator handling, and generic runtime comparison. Keep related differences together, while leaving dictionary key admissibility to the Dict-specific work.

## Success criteria

- Focused same-source programs produce the same results in both revisions for every required value category and nested combination.
- Unsupported comparisons are rejected at the same phase with equivalent public failure values or messages, including function-containing values.
- Ordering, nominal-versus-structural identity, NaN, and signed-zero behavior match the interpreter baseline.
- Only interpreter operator spellings remain, and every intentional divergence is documented as such.
- Dictionary comparison parity is covered without absorbing Dict key-policy ownership.
