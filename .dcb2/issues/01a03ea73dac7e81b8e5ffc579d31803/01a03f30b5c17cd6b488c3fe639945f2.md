# Trial result

Retained a focused MIR CSE candidate that replaces a dominated duplicate scalar heap load with a typed move. Canonical routine benchmark: improved.

## Important changes

- **Typed scalar heap-load CSE key** — **Reason:** enables reuse only for identical SSA address, byte offset, and concrete scalar type.
- **Barrier-aware load availability** — **Reason:** calls, allocation, stores, raw-memory operations, ref-count operations, and non-scalar values invalidate reuse.
- **Focused MIR regression coverage and catalog documentation** — **Reason:** proves the transformation and records that routine sources did not expose an attributable candidate.

## How it works

The existing dominator-scoped MIR CSE propagated only binary and unary keys, so an exact `HeapLoad(v0, 8): TInt64` in a dominated block remained duplicated. The retained solution adds a scalar-load key and emits a typed `Mov` only when the earlier load dominates and no barrier occurs. It avoids alias analysis and preserves ownership by clearing only load availability at barriers. Complexity remains linear in MIR instruction count plus map operations; residual risk is limited to backend live-range effects, which the worker-owned full suite and routine benchmark gate will assess.

## Algorithm

1. Traverse the dominator tree with available CSE keys.
2. For `HeapLoad(dest, addr, offset, Some scalarType)`, form a key from `addr`, `offset`, and `scalarType`.
3. If the key is available, replace the load with `Mov(dest, previousDest, Some scalarType)`.
4. Otherwise retain the load and export its key to dominated blocks.
5. Clear scalar-load availability at calls, allocation, stores, raw-memory work, ref-count work, and non-scalar or unknown values.
6. Pass immutable availability independently to dominator siblings.
