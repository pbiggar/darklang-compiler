## Evidence

## Problems

Eliminate pure scalar work and live ranges from untaken MIR branch paths when measurement shows a benefit.

## Solution

The transformation avoids executing an eligible scalar computation on the untaken edge by moving it into its sole immediate consuming successor. The focused verifier could not measure it because `control_flow.e2e` is a multi-assertion test corpus rather than a single compilable workload; it failed parsing before baseline sampling, MIR comparison, executable comparison, or output comparison. Therefore the required clear-win threshold cannot be evaluated and the retained checkpoint remains unintegrated.

## Implementation

- Candidate restricts successor-exclusive sinking to a contiguous trailing run of eligible pure, non-owning scalar MIR instructions.
- Candidate preserves pre-branch instruction order and excludes phi-edge, refcount, allocation, memory, and call operations.
- Candidate adds MIR coverage for successor sinking and ordering boundaries.

### Algorithm

1. Inspect a conditional MIR block.
2. Scan its instructions backward from the branch terminator.
3. Accept only a trailing pure, non-owning scalar definition with no phi use and ordinary uses confined to exactly one immediate successor.
4. Stop at the first retained or ineligible instruction.
5. Move the accepted suffix, in source order, after that successor's phis.

### Example

For `if flag then value + 1 else value`, the eligible `value + 1` can move from the branch block into the true successor, so the false edge executes no addition while returning `value`. A preceding retained guard prevents the move, preserving instruction order.
