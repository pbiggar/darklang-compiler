# Trial result

Committed repair 4c709f38e2 retains scalar sinking while preventing pre-branch instruction reordering. No established-suite improvement was proven; overall multiplier: 1×.

## Evidence

## Problems

Eliminate pure scalar work and live ranges from untaken MIR branch paths when measurement shows a benefit.

## Solution

The prior pass moved individually eligible definitions past retained pre-branch guards, causing deterministic MIR/LIR snapshot mismatches in unrolled loops. The repair moves only an eligible suffix, preserving order relative to all retained branch-block work while retaining the positive false-edge work reduction. Phi-edge uses, effects, allocation, memory, and refcount operations remain excluded. Residual risk: focused test execution was blocked by a runtime futex hang; authoritative exact-commit verification remains pending.

## Implementation

- Restricted sinking to a contiguous trailing run of eligible scalar instructions.
- Added a MIR regression for a successor-exclusive scalar preceding a retained branch guard.
- Documented the ordering repair and focused 1-to-0 untaken-edge addition outcome.

### Algorithm

1. Inspect conditional branch blocks.
2. Scan instructions backward from the terminator.
3. Accept only pure non-owning scalar definitions with all ordinary uses in exactly one immediate successor and no phi use.
4. Stop at the first retained or ineligible instruction.
5. Move the collected trailing run, in source order, after successor phis.

### Example

Before repair, `add; guard; branch` could become `guard; branch`, with `add` moved into one successor. After repair, the retained `guard` stops the backward scan, so both instructions remain ordered in the branch block. A standalone `add; branch` still becomes `branch`, with `add` at the consuming successor; its untaken edge executes 0 rather than 1 additions.
