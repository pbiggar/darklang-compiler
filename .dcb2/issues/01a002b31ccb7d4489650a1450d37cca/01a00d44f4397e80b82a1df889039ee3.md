The benchmark usage is intentional, not accidental: the benchmarks are retaining compiler-native operations after recent public API narrowing.

Current scan: **56 qualified internal call sites across 54 matching lines**, grouped as:

| Internal operation | Call sites | Why benchmarks use it |
|---|---:|---|
| `Internal.SkewList.getAt` | 14 | Machine-sized `Int64` indexed reads without conversion to public arbitrary-precision `Int`. |
| `Internal.SkewList.setAt` | 10 | Persistent `O(log n)` indexed update; public `List.setAt` was deliberately removed. |
| `List.__repeatInt64` | 8 | Direct `Int64` repetition without public `Int` conversion or `Result` unwrapping. |
| `Internal.HAMT.*` | 20 | Generic integer-key maps; public `Dict` is now string-keyed only. |
| `Internal.SkewList.length` | 4 | `Int64` length; public `List.length` returns `Int`. |

### Root cause
History shows this happened when public surfaces were aligned with interpreter parity:

- Commit `57ffb6dad4` narrowed public `Dict` to `Dict<Value>` with `String` keys. `matmul` and `nsieve` were migrated from generic public `Dict<Int64, _>` calls to `Internal.HAMT`, and benchmark scripts gained global `--allow-internal`.
- Commit `c0e7179baf` changed public list indices/counts/lengths from `Int64` to arbitrary-precision `Int`, and public `repeat` began returning `Result`. Benchmarks were moved to machine-sized private helpers.
- Commit `1fdb9ef9b2` removed public `List.setAt`; `edigits`, `spectral_norm`, and `fannkuch` were moved to `Internal.SkewList.setAt`.

The documentation explicitly says `Stdlib.Internal.SkewList`, `__` helpers, and private `setAt` are implementation surface. Therefore, removal requires either broadening a public contract or rewriting benchmark algorithms; there is no purely mechanical fix for every call.

### Immediate public-only migrations
About **24 call sites** can likely move without changing data structures:

1. Replace `Internal.SkewList.getAt` with callable `Stdlib.List.getAtOrDefault` where the benchmark already has a default or proven bounds:
   - `edigits` loops are bounded by the known digit-vector length.
   - `fasta` reads fixed-size ALU and probability tables.
   - `quicksort` already defines a defaulting read helper.
2. Replace `List.__repeatInt64` with a benchmark-local recursive helper using public `List.push`, or public `List.repeatUnsafe` after converting the known-safe `Int64` count to `Int`. These are initialization-only operations, so conversion overhead is likely acceptable but should be measured.
3. Replace `fasta`’s internal `length` with public `List.length` or pass the tiny table length explicitly.

This leaves the substantive gaps: indexed updates, quicksort’s `Int64` length, and generic-key maps.

### Solutions for the remaining calls

**Generic maps:** add a public `Stdlib.Map<Key, Value>` backed by the existing HAMT. Do not restore generic `Dict<Key, Value>`; that spelling and behavior were deliberately removed. A separate `Map` API can expose `empty`, `get`, `set` with overwrite semantics, `member`, `remove`, and `size` while preserving the string-keyed `Dict` contract. This is the right replacement for all 20 HAMT calls in `matmul` and `nsieve`. Converting integer keys to strings would materially change hashing, allocation, and performance, so it is not an equivalent benchmark.

**Indexed fixed vectors:** choose one of:

- Add a public fixed-vector API, preferably `Stdlib.Vector` with `repeat`, `get`, `set`, and `length` using `Int64` indices. This separates numeric-index workloads from the public `List` contract.
- Reintroduce narrowly documented `List` extensions such as `setAt` and `lengthInt64`. This is smaller but reverses the documented decision that `List.setAt` is private, so it needs explicit contract approval.
- Rewrite the benchmarks using traversal-oriented public list operations. `spectral_norm` can likely build rows with `push` and one reverse; `edigits` and `fannkuch` would require more substantial algorithm changes. This avoids stdlib expansion but changes measured work and may worsen performance.

For `quicksort`, public `List.length` requires conversion to arbitrary-precision `Int` on every recursive call, so either expose a machine-sized length extension or accept an algorithm/performance change.

### Recommended path

1. First migrate the direct public-only reads/repeats and `fasta` length.
2. Add a public generic `Map` for `matmul` and `nsieve`.
3. Make an explicit contract decision on fixed-vector indexed updates, preferably `Stdlib.Vector`, rather than restoring private `List.setAt` under a public name.
4. Update both `main.dark` and `quick.dark` together.
5. Once zero internal references remain, remove `--allow-internal` from `benchmarks/infrastructure/build_all.sh` and `benchmarks/quick_check.sh`; compiling without the flag then becomes the regression guard.
6. Run the full test suite and routine benchmark profile. These APIs currently avoid `Int` conversion, `Result` handling, and string-key conversion, so equivalent outputs do not guarantee equivalent performance.
