ARM64 pass 7 already knows the exact code size and label/pool offsets, but production materializes resolved instructions as a uint32 list before both pass-8 writers serialize that list into byte storage.

## Work item 019ff65b947573338e99f7bf2f4d4834

Title: Emit ARM64 code directly into byte storage

Category: behavior

Evidence: src/DarkCompiler/passes/arm64/7_Encoding.fs:1465-1521 computes codeSize and resolved offsets but accumulates ARM64.MachineCode values into a list and reverses it; ARM64.fs:180-181 defines each value as uint32. passes/arm64/7_Emit.fs:8-33 exposes and forwards that list. passes/arm64/8_Binary_Generation_ELF.fs:52-64,224-253 allocates and fills a byte array from it, while 8_Binary_Generation_MachO.fs:60-67,312-324,549-574 additionally converts the list to an array before producing bytes. Binary.fs:191 and Binary_ELF.fs:98-103 already store machine code as byte arrays. CompilerLibrary.fs:641-655 times ARM64 Emit and contains a byte-indexed four-byte renderer whose current input is nevertheless the word list. ARM64BinaryTests.fs:105-165,385-408 covers basic word-to-Mach-O serialization but not the production direct-byte path or verbose rendering. CompilerLibrary.fs:1537-1542 exposes total compilation timing; benchmarks/RESULTS.md:8-28 defines the 19-program routine corpus and currently reports 2.74x; docs/verification.md:10-25 requires full tests and routine verification.

Outcome:

After individual human approval, treat the current 18.3 ms fasta ARM64 Emit median as the failing performance baseline. On one idle ARM64 host with pinned revisions, toolchain, inputs, and build mode, capture 10 raw before runs and later 10 comparable after runs for fasta -vv, recording ARM64 Emit and total-compilation medians, absolute deltas, and percentage deltas. Before production edits, add focused characterization coverage for little-endian byte order, labels and branches, string and float references, leak-check addressing, ELF/Mach-O code placement, and four-byte verbose hex rows with byte offsets and byte totals. Change only the production ARM64 encoding-to-binary path: allocate one exact-sized byte array from computeSymbolicLayout, encode each non-label instruction once with the existing label resolver, place its four little-endian bytes directly at the code-relative offset, return that byte array from ARM64_Emit, and pass the same array directly to byte-oriented ELF and Mach-O construction. Preserve existing uint32-list encoder and binary-generator entry points only as non-production compatibility wrappers; leave code generation, layout calculations, pools, coverage behavior, x64, and generated instructions unchanged. Make the existing verbose renderer consume the byte array without changing its heading, row width, offsets, ordering, or total semantics. Retain the candidate only if the fasta selected-pass improvement exceeds a predeclared noise floor such as max(0.1 ms, baseline MAD) and an exact one-sided paired randomization test is significant at p<0.05; otherwise revert it. Report matched before/after ARM64 Emit and total-compilation medians and deltas for all 19 routine programs, flagging regressions. Collect 10 raw before and after /usr/bin/time wall-clock runs of ./run-tests --ai and report medians plus absolute and percentage deltas. Prove byte-identical routine-program binaries against baseline and fixed verbose-output oracles, then run ./run-tests --ai and ./benchmarks/run_benchmarks.sh --verify routine, reporting every routine instruction count and the resulting benchmarks/RESULTS.md performance ratio. Remove all exploratory profiling and instrumentation before retention.
