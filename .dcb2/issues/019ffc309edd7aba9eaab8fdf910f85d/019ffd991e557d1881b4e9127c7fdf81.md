# Design brief

## Problem

At compiler HEAD b2e1f3d1e4ce0338d4c4662db9a1326f2e2cb899 versus interpreter revision 04fbe9dcc995c6188757d583e273cbd30a3e2d3d, primitive literals diverge in accepted syntax, numeric boundaries, malformed-token handling, Unicode and escape semantics, scalar typing and identity, and floating-point special-value behavior.

## Goals

- Adopt the pinned interpreter’s public behavior as the contract for unit, Boolean, integer, float, character, and string literals.
- Align tokenization, parsing, static typing, lowering, runtime semantics, equality, and rendering as one coherent compatibility boundary.
- Cover integer ranges and negative boundaries, malformed forms, Unicode scalars and normalization, escapes, signed zero, NaN, and infinities.
- Remove superseded spellings throughout literal-bearing code and fixtures, while explicitly documenting only genuine AOT-required divergences or retained extensions.

## Proposed solution

Deliver one vertical parity change based on revision-pinned source evidence and focused same-source comparisons. Apply the interpreter’s literal grammar and observable scalar semantics consistently across the compiler pipeline, preserve characters as semantically distinct from strings, validate signs and numeric ranges without sentinel behavior, provide interpreter-equivalent Unicode and floating-point behavior, and migrate the repository corpus to the resulting syntax. Earlier static rejection may remain where appropriate for an ahead-of-time compiler, provided the public contract and the divergence are explicit.

## Success criteria

- Programs accepted by both revisions produce equivalent scalar types, values, equality behavior, and rendered output on every compiler target.
- Boundary and malformed inputs are accepted or rejected consistently, including signed integer limits, glued or incomplete numeric tokens, invalid Unicode scalars, escape forms, and floating-point specials.
- Every retained gap is supported by pinned source evidence and, where practical, a focused same-source comparison.
- Superseded literal spellings no longer appear in supported syntax, tests, standard-library code, examples, benchmarks, or executable fixtures.
- Compiler-only extensions and intentional AOT divergences are clearly separated from interpreter-parity behavior.
