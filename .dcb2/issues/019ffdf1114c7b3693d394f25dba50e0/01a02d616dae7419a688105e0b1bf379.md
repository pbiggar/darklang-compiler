# Trial result

A bounded projection-driven specialization removes nbody’s ten non-escaping applyPair tuple results per step. Canonical routine benchmark: improved.

## Evidence

## What changed

Added capped ANF inlining for nonrecursive functions that return a locally allocated tuple when the caller immediately and exhaustively projects it; added an ANF regression test for a 21-binding tuple producer beyond the ordinary inline limit.

## How it works

applyPair exceeded the normal 20-binding inline limit, so advanceStep retained ten calls and materialized each returned pair tuple. The retained specialization preserves the ordinary tuple ABI for all escaping/value uses, requires exhaustive immediate projections, and caps producers at 64 bindings and callers at 12 sites. Residual risk is bounded code growth and worker-owned full-suite/routine validation.

## Algorithm

1. Recognize a nonrecursive tuple producer ending in a local TupleAlloc return. 2. Confirm the direct call continuation immediately projects every tuple element exactly once. 3. Inline the producer. 4. Replace projections with ordered direct element bindings, eliminating the local tuple allocation. 5. Leave all other calls unchanged.
