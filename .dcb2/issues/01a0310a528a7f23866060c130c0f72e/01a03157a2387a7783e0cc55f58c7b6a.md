## Important changes

## How it works

The edigits loops still use persistent SkewList getAt/setAt operations, including path-copying updates. An ownership audit identified a plausible closed, monomorphic Int64 boundary, but the packed-input premise was false, so no specialization or alternative representation was retained. The unchanged behavior remains approximately O(n log n) for indexed traversal and updates rather than O(n) total direct-buffer access. Because compiler and benchmark sources are identical between revisions, the observed timing regression cannot represent an optimization benefit and may reflect compile-time noise. Residual risk is that the underlying edigits performance problem remains unresolved.

## Algorithm

1. Construct separate ordinary List<Int64> values for e and term. 2. divideByN reads each digit with SkewList.getAt and creates an updated persistent list with SkewList.setAt. 3. addWithCarry reads e and term through SkewList.getAt and path-copies e through SkewList.setAt. 4. Thread each returned list version through the recursive closed call graph. 5. Return the final ordinary List to computeChecksum, preserving existing List semantics and ownership behavior.
