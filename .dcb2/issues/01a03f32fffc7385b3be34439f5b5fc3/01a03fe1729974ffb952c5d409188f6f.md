## Important changes

- **Added finite scalar-literal direct-call cloning** — **Reason:** differing literal values previously prevented uniform parameter propagation and retained hot argument setup.
- **Limited cloning to four variants per function and sixteen per program** — **Reason:** bound deterministic code-size growth while preserving the original fallback.
- **Restricted recursive specialization to unchanged pass-through parameters** — **Reason:** keep recursive tail calls within clones using consistent reduced signatures.
- **Used bit-exact float specialization keys and rejected managed literals** — **Reason:** distinguish signed zero and NaN payloads without violating ownership.
- **Added ANF, MIR, LIR, and generated-code coverage** — **Reason:** prove routing, fallback, caps, exclusions, tail form, lowering, and runtime behavior.
- **Documented the retained optimization and measurements** — **Reason:** record its constraints, evidence, and expected application.

## How it works

The existing pass only removed parameters whose literals were uniform across every direct call. The initial finite-cloning attempt removed every literal in an entry call, but a focused recursive test showed that changing induction arguments then forced recursive calls back to the original signature. The retained design clones only self-recursive parameters passed through unchanged on every self-call. Non-recursive functions may specialize all eligible scalar literal positions. Originals remain available for dynamic calls, while function references, closure targets, managed types, and clone families exceeding deterministic caps remain unspecialized. Complexity is linear in program analysis plus the copied bodies of at most four clones per function and sixteen globally. Residual risk is bounded static code growth: the measured binaries grew by 88 and 328 bytes, and repository-wide validation remains worker-owned.

## Algorithm

1. Run existing uniform scalar-literal parameter propagation.
2. Reanalyze all direct calls and reject address-taken or closure-target functions.
3. For recursive functions, retain only scalar parameters passed through unchanged by every self-call; for non-recursive functions, consider every scalar parameter.
4. Build deterministic, bit-exact literal patterns and require at least two distinct variants.
5. Select at most four patterns per function and sixteen clones across the program.
6. Clone each selected body, substitute its literals, and remove the corresponding parameters.
7. Reroute matching normal, borrowed, and tail calls while preserving remaining argument order.
8. Keep unmatched calls and the original function as the unspecialized fallback.
