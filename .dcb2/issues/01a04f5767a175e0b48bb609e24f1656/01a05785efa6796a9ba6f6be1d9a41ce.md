# Implementation plan

Current JSON planning caches generated AST per E2E session, but every executable still lowers, specializes, optimizes, reference-counts, tree-shakes, code-generates, and emits its own large generated decoder/encoder graph. Replace that graph with declaration-owned thin codecs over reusable streaming runtime primitives.

## Work item 01a05785efa571969396a10fb4feb843

Title: Replace generated raw-tree JSON plans with declaration-owned streaming thin codecs

Category: other

Evidence: JsonPlanning currently emits recursive AST functions for every concrete type (ensureSerializer/ensureDecoder and collection helpers, 1.7_JsonPlanning.fs:241-903) and rewrites each intrinsic to __parseRaw followed by generated Raw* matching (1.7_JsonPlanning.fs:1077-1110). AltJson.__parseRaw recursively allocates RawArray/RawObject trees and source slices (stdlib/AltJson.dark:197-302); record decoding rescans all object fields once per declared field through __matchingFields (1.7_JsonPlanning.fs:803-829; stdlib/Json.dark:253-259). The recent session cache only reuses generated AST artifacts; CompilerLibrary still lowers each cached artifact into every executable (CompilerLibrary.fs:2119-2169, 1.7_JsonPlanning.fs:1058-1113). Existing parity contract and compact regression matrix define the required observable behavior (docs/features/json-parity.md; Tests/e2e/json-parity.e2e).

Outcome:

Introduce one compiler JSON specialization path that validates concrete targets and associates named record/sum codec definitions with their declaring layouts; generate only direct typed field/variant/scalar construction and writer calls. Move syntax scanning, streaming container traversal, raw-fragment/span retention, path construction, standard parse errors, duplicate/missing-field handling, collection mechanics, and JSON escaping into reusable runtime support. Decode successful typed values directly from the stream without constructing InternalRawJson trees, while retaining bounded raw-fragment capture or replay where exact existing diagnostics require it. Remove 1.7_JsonPlanning's full generated serializer/decoder path and its generated raw-list accessors; retain nominal aliases, recursive types, generic instantiation, exact wire shapes, validation, and compatibility behavior. Add focused E2E coverage for scalar, nested list/dict/tuple, records, sums, aliases, recursion, duplicate/missing/malformed fields, source-order error precedence, paths, and raw fragments; add pass-grouped clean JSON E2E compile-time measurement proving at least 70% cumulative reduction, plus representative decode-throughput measurements. Run the full suite and routine benchmark verification.
