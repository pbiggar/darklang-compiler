The remaining non-timing differences are concentrated in a small set of real language/model boundaries:

- **Conditional result typing:** the interpreter can successfully evaluate a selected arm even when the other arm has a different type; the compiler rejects heterogeneous `if` arms, including a non-`Unit` one-arm `if`. This is a successful-program difference, not merely earlier diagnostics. [conditional-sequence-parity.md](docs/conditional-sequence-parity.md)
- **Match exhaustiveness:** the compiler requires a statically exhaustive match, while the interpreter permits a partial match and only fails if an unmatched value is actually evaluated. Thus some interpreter programs can succeed on particular inputs but cannot compile. [pattern-matching.md](docs/features/pattern-matching.md)
- **Program entries and top-level values:** compiled executable units require exactly one entry expression; the interpreter may execute multiple expressions. `val` declarations parse but cannot be natively executed. [program-structure-parity.md](docs/program-structure-parity.md)
- **Integer `/`:** native Dark accepts integer division (truncating toward zero); the interpreter reserves `/` for Float and requires `Int64.divide` for integer division. [darklang-differences.md](docs/darklang-differences.md)
- **Value/type universe:** compiled programs have no interpreter DDB value representation; RawPtr and RuntimeError are compiler-internal rather than source values. The compiler additionally exposes extensions such as sized/unsigned integers, bitwise operators, interpolation, and several stdlib helpers absent from the interpreter. [darklang-differences.md](docs/darklang-differences.md)
- **Record identity in typed JSON and related type-sensitive operations:** the compiler retains nominal record identity, whereas the pinned interpreter can identify separately declared structurally identical records by content hash. [json-parity.md](docs/features/json-parity.md)
- **Stream abandonment:** releasing the last compiled Stream owner deterministically closes it; the interpreter relies on GC finalization. This can be observable through resource/disposer lifecycle effects. [stream-parity.md](docs/stream-parity.md)
- **Source/package model:** module-open environments and content-addressed package loading are absent; package inputs are immutable AOT snapshots. [identifier-parity.md](docs/identifier-parity.md)

Everything else documented as a difference is either syntax/parser-mode compatibility, native representation/performance, host/target availability, or explicitly an earlier AOT error phase—and therefore excluded by your constraint. Some CLI filesystem/process surfaces remain **unclassified**, rather than established as parity or divergence. [cli-parity.md](docs/cli-parity.md)
