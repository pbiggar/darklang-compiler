Agreed. This is a clean parity target: public `/` should accept only `Float`, while public integer division remains available through the existing `Stdlib.<integer>.divide` APIs.

It is not a one-line type-checker change: those APIs are currently implemented in compiler stdlib source with `/` (for example `Int64.divide` and `UInt16.divide`), and ANF currently maps integer `Div` to `Stdlib.Int.divide`. The repair should therefore preserve a private/native integer-division lowering path—or give each public integer `divide` function an explicit intrinsic—while rejecting user-authored integer `/` in both parser modes.

That yields the interpreter contract without removing integer division itself, and requires migrating compiler-authored uses such as `99 / 10` in the E2E corpus to the appropriate named API.
