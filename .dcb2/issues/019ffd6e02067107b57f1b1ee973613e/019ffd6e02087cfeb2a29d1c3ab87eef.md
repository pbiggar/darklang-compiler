# Index register-allocation phi edges

Reduce register-allocation liveness time by replacing repeated linear phi-edge searches with one immutable indexed lookup.

## Constraints

- Limit retained changes to pass 5 integer and floating-point phi-edge lookup inside liveness; retain one indexing representation.
- Use an isolated worktree with a pinned revision, toolchain, host conditions, warm-up policy, and alternating run order.
- Expose existing allocator phase timing temporarily and proceed only if phi-edge searches materially contribute to liveness.
- For every routine benchmark program, collect 10 paired before/after -vv runs and report raw Register Allocation and total-compilation results, medians, absolute deltas, and percentage deltas.
- Collect 10 paired before/after ./run-tests --ai wall-clock runs with raw results, medians, and deltas; require all runs to pass.
- Require identical live sets, allocated LIR, binaries, benchmark outputs, and instruction counts; run ./run-tests --ai and ./benchmarks/run_benchmarks.sh --verify routine and report the RESULTS.md ratio.
- Retain only a clear improvement beyond a predeclared noise threshold; record discarded lookup alternatives and remove all profiling and instrumentation.

Category: register-allocation profiling

### Trial item 019ffd6e0206734085126a2543ebfa40

Title: Trial indexed edge facts

Category: liveness data representation

Evidence: Block indices already provide dense identities, so indexing can remove repeated list traversal without changing domains, transfer equations, or traversal order.

Outcome:

Build phi-use facts once by predecessor and successor index and retain the fastest exact lookup representation.
