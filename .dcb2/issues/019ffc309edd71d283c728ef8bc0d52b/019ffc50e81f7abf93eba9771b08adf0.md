# Design brief

## Problem

At compiler b2e1f3d1e4ce0338d4c4662db9a1326f2e2cb899, list syntax, typing, runtime behavior, and the public List API do not fully match interpreter 04fbe9dcc995c6188757d583e273cbd30a3e2d3d; compiler-only syntax and aliases also expand the language contract unintentionally.

## Goals

- Make same-source list and cons programs behave consistently with the interpreter across typing, construction, matching, equality, callbacks, and visible failures.
- Match the interpreter’s public List contract while preserving equivalent native compiler implementations.
- Remove compiler-only list syntax and public aliases, migrating affected compiler-owned sources.
- Keep all list parity changes within one coherent language-and-library boundary.

## Proposed solution

Treat the interpreter revision as the behavioral specification and implement a single coordinated parity pass spanning list syntax, inference, lowering, runtime semantics, and the public List surface. Preserve compiler-native representations and implementations wherever observations match; otherwise align behavior, including evaluation order, supported values, pattern semantics, and failures. Maintain a revision-stamped parity record distinguishing retained equivalence, removed compiler extensions, and any documented intentional divergence, using DCB1 commit 8a402797 only as historical input.

## Success criteria

- The parity record identifies compiler b2e1f3d1e4ce0338d4c4662db9a1326f2e2cb899 and interpreter 04fbe9dcc995c6188757d583e273cbd30a3e2d3d for every comparison.
- Same-source probes agree for empty and populated lists, homogeneous typing, nested and cons patterns, associativity, construction and callback order, equality, supported element categories, and language-visible failures.
- The compiler exposes the interpreter’s List callable signatures and observable behavior without requiring the same internal architecture.
- Compiler-only list syntax and public aliases are absent, and affected compiler-owned sources use the shared contract.
- Existing conforming compiler list behavior remains intact.
