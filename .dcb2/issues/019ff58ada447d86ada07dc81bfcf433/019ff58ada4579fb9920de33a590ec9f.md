# Compare interpreter and compiler

Build a current nested inventory of compiler/interpreter parity gaps through three child analyses: modules, language features, and observable implementation differences. Produce proposed issues for human review; inventory work must not change production code.

## Constraints

- Record the exact compiler HEAD and exact darklang/dark revision used for every comparison.
- Use the current interpreter's public behavior as the parity baseline; classify compiler-only extensions and intentional divergences explicitly.
- Support every proposed gap with current source locations and, where practical, a focused same-source probe or test.
- Keep each leaf issue to one independently reviewable gap and avoid duplicates already represented in .dcb2.
- Use DCB1 report commit 8a402797 and current parity documents only as starting evidence; revalidate every retained finding.
- Performance differences are out of scope unless they change observable behavior.
