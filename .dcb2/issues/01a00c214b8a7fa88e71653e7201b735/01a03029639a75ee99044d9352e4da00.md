The change was made to replace the compiler’s old **records-as-tuples** extension with the interpreter’s public record model. Previously, `Point { x = 1; y = 2 }` compiled as the same untagged positional block as `(1, 2)`, so record identity, declared generic-parameter order (including phantom parameters), and record-specific behavior were discarded after type checking.

“Interpreter-compatible” means **observable language behavior**, not binary-layout compatibility with the F# interpreter. The parity work aligned the compiler with the pinned interpreter’s grammar and semantics: named/qualified/generic construction, nominal rather than structural record types, source-order evaluation, updates, equality, rendering, ownership, and rejection of compiler-only record patterns and anonymous records.

The descriptor word is the native compiler’s analogue of the interpreter’s runtime `DRecord` distinction. The interpreter has a distinct record value category that owns record fields; the native compiler cannot use that F# object representation, so it places a stable identity in slot 0 and puts fields after it. This ensures a record block is distinguishable from a tuple block and carries its resolved nominal identity through native lowering.

That identity supports the broader parity change:

- `A { value: 1 }` and `B { value: 1 }` remain different nominal types even with identical fields.
- `Box<Int64>` and `Box<String>` retain concrete generic identity, including otherwise invisible phantom parameters.
- aliases resolve to the same declaration identity.
- record projections, cloning, equality helpers, rendering, and reference-count plans operate as records rather than accidentally as tuple operations.

So the extra word was not needed merely to read `p.x`; static field offsets could do that. It was chosen as part of making the native runtime preserve the interpreter’s record-vs-tuple and nominal-record distinction after compilation. The nbody cost is the price of this particular implementation: every short-lived `Body` and `System` allocation now stores that identity and carries one more payload word.
