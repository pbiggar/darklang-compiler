# Design brief

## Problem

Language parity is not yet captured as a current, evidence-backed inventory; historical findings mix unresolved gaps, resolved behavior, compiler extensions, and intentional divergences.

## Goals

- Establish the current interpreter as the revision-pinned parity baseline across parsing, name resolution, typing, evaluation, and program structure.
- Identify each current gap while explicitly classifying extensions and intentional divergences.
- Produce non-duplicative, independently deliverable child scopes backed by current evidence.

## Proposed solution

Re-audit compiler e0e13eb788d53265ad62cbd809cba6d05c9e23dd against darklang/dark 04fbe9dcc995c6188757d583e273cbd30a3e2d3d, treating report commit 8a402797 and current parity documentation only as leads. Confirm each retained finding against both revisions and, where practical, same-source behavior; then propose one child per independent language-feature boundary while keeping related syntax, type, and behavioral differences together. Each child will record both revisions, current source locations, evidence, and classification, excluding performance-only and separately owned module-level concerns.

## Success criteria

- Every in-scope current gap is represented exactly once or explicitly classified outside parity.
- Every proposed child records the exact compiler and interpreter revisions and cites current supporting source locations.
- Focused same-source evidence supports behavioral claims wherever practical.
- Resolved or stale historical findings are excluded, and related differences remain contained unless they require separate design boundaries.
- The inventory covers all five requested language layers.

## Open questions

- Which compiler-only extensions should remain available through a distinct dialect rather than being excluded from the public parity surface?
