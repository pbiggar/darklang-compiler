# Design brief

## Problem

Current parity evidence is stale and does not yet provide an actionable, non-duplicative plan for resolving observable language differences.

## Goals

- Establish the current interpreter as the revision-pinned behavioral baseline across parsing, name resolution, typing, evaluation, and program structure.
- Identify every current missing or behaviorally different feature and turn each independent boundary into a resolution scope.
- Separate parity gaps from compiler extensions, intentional divergences, resolved findings, and performance-only differences.

## Proposed solution

Re-audit compiler b2e1f3d1e4ce0338d4c4662db9a1326f2e2cb899 against darklang/dark 04fbe9dcc995c6188757d583e273cbd30a3e2d3d. Treat DCB1 report commit 8a402797 and current parity documents only as leads, revalidating each candidate against both revisions and with focused same-source behavior where practical. Create one child issue per independent feature boundary whose outcome is to resolve the confirmed difference, keeping related syntax, typing, and runtime behavior together. Each child records both revisions, current evidence, intended parity behavior, and any explicit extension or intentional-divergence classification.

## Success criteria

- Every confirmed in-scope difference appears exactly once in an independently deliverable resolution child or is explicitly classified as an extension or intentional divergence.
- Every child records the exact compiler and interpreter revisions and is supported by current source evidence and focused behavioral evidence where practical.
- Resolved and stale historical findings are excluded.
- The resulting children collectively cover all five requested language layers and define observable parity outcomes rather than documentation-only work.

## Open questions

- Which compiler-only extensions should remain available through an explicit dialect rather than be removed from the public parity surface?
