# Design brief

## Problem

At compiler b2e1f3d1e4ce0338d4c4662db9a1326f2e2cb899, tuple behavior is incomplete and inconsistent with interpreter 04fbe9dcc995c6188757d583e273cbd30a3e2d3d across syntax, typing, patterns, equality, rendering, and runtime values; legacy compiler-only forms further obscure parity.

## Goals

- Match interpreter behavior for ordered tuples of arity two or greater.
- Support heterogeneous, nested tuples consistently through construction, access, typing, destructuring, matching, equality, rendering, and runtime values.
- Preserve left-to-right element evaluation and positional order throughout the compiler.
- Treat parenthesized single expressions as grouping, reject singleton tuple syntax as the interpreter does, and retain unit as a primitive literal.
- Remove superseded compiler-only tuple construction and access forms while migrating tuple-bearing sources.

## Proposed solution

Adopt one interpreter-aligned tuple model across the language pipeline: an ordered structural product with at least two positionally typed elements. Parse grouping, unit, and tuples distinctly; preserve arity and element order through typing and lowering; use the interpreter’s access behavior; recursively lower exact-shape destructuring and match patterns; compare tuples structurally by arity and ordered elements; and expose matching rendered and runtime values. Classify legacy compiler syntax and access as extensions to remove, while retaining unit handling as an intentional separate primitive behavior.

## Success criteria

- The same programs at the recorded revisions agree observably for tuple construction, typing, access, nesting, heterogeneous elements, destructuring, matching, equality, rendering, and evaluation order.
- Tuple patterns require the interpreter’s exact arity and recursively match nested elements in positional order.
- Parenthesized expressions, rejected singleton forms, and unit values behave exactly like the interpreter baseline.
- Legacy compiler-only tuple syntax and access forms are absent, and maintained tuple-bearing sources use the parity forms.
- Tuple arity and element order remain intact from source syntax through runtime values.
