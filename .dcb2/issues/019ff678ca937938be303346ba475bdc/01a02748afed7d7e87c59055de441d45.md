# Trial result

The single-fold preflight is retained as an optional checkpoint, but the bounded timing improvement is too small and noisy to claim an optimization.

## Evidence

## What changed

Replaced separate parameter-limit validation, call-limit validation, and VReg maximum scans in MIR→LIR with one per-function preflight fold; added an e2e diagnostic fixture for a ninth integer-bank parameter.

## How it works

The baseline performed three MIR traversals before selection. The retained preflight validates parameters, then calls in deterministic block/instruction order while accumulating maximum VReg. It preserves error strings, LIR, and generated output. Fasta’s median MIR→LIR improvement was only 0.1 ms, with substantial run variance, so this is not a confirmed performance win.

## Algorithm

1. Validate each function’s parameter register-bank counts. 2. Traverse blocks in Map order and instructions in list order. 3. For each instruction, validate call register-bank limits and update the VReg maximum. 4. Include each terminator in the VReg maximum. 5. Initialize temporary-register state from the resulting maxima before LIR selection.
