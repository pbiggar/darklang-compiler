# Trial result

Focused verification found a clear MIR Optimizations compile-time regression, so the preserved candidate remains unintegrated. Canonical routine benchmarks regressed.

## Evidence

## Problems

Eliminate an entry loop-condition branch when the first iteration is statically proven to execute.

## Solution

The candidate safely rotates only when every acyclic direct call proves the initial exit condition false, preserving zero-trip behavior by rejecting unproven entries and rejecting effectful/refcount/cyclic cases. However, the focused MIR Optimizations measurement regressed by 2.7 ms, exceeding the 1.2 ms noise threshold; therefore it does not meet the retention criterion. Executable output remained identical, while MIR and binary differences were intentional consequences of the transformation.

## Implementation

- No files were edited in this measurement run.
- Preserved candidate adds guarded rotation only for proven-entering, pure scalar self-recursive loops and adds focused MIR/e2e coverage.

### Algorithm

1. Recognize the one-header, one-latch scalar self-recursive CFG.
2. Require Int64 phis/parameters and pure latch instructions.
3. Reject closures, tail references, cyclic direct callers, and unproven or zero-trip entries.
4. Prove every remaining direct call makes the initial guard false.
5. Move latch value work into the header, retarget phi backedges, and branch back to the header after subsequent guards.

### Example

For `rotateProven(30000000, 0)`, baseline MIR branches from `rotateProven_body` to a separate latch; candidate MIR places the latch work in `rotateProven_body` and branches back to that header. Both executables printed the identical 16-byte result, but candidate compilation was slower.
