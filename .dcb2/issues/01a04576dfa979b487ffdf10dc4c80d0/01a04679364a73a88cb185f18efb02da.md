## Evidence

## Problems

Eliminate an entry loop-condition branch when the first iteration is statically proven to execute.

## Solution

The failed case treated `readRandom(1)` inside another loop’s latch as an unconditional entry proof. That call is conditional on the caller loop guard, so it cannot safely establish universal entry behavior. The repair accepts only acyclic direct call sites and rejects any cyclic direct call rather than omitting it from the proof. The existing pure positive rotation remains unchanged; zero-trip, calls/refcounts, allocation, closures, tail entries, and cyclic/effectful caller cases remain excluded. Residual risk is limited to intentionally conservative missed opportunities.

## Implementation

- Added CFG-cycle detection for direct call sites used by the entry-proof analysis.
- Require every direct call site to be acyclic; any cyclic direct call now rejects rotation.
- Updated classic optimization documentation with the repaired eligibility rule and regression coverage.

### Algorithm

1. Recognize the canonical scalar self-recursive header/latch shape.
2. Require pure scalar latch work and valid phi/backedge structure.
3. Find direct calls to the candidate function.
4. Reject if any direct call is in a CFG cycle, or if any non-direct reference exists.
5. Prove every remaining acyclic direct call supplies a constant argument that makes the initial exit comparison false.
6. Rotate only then: relabel latch phi edges to the header, append latch work before the next guard, and remove the latch block.

### Example

Before repair, `loop(n, acc)` called `readRandom(1)` from its guarded latch, and that constant incorrectly rotated `readRandom`. After repair, the call block is detected as cyclic, `readRandom` remains unrotated, and its `RandomInt64()` behavior stays behind its original recursive guard. The standalone `rotateProven(3, 0)` call is acyclic and still rotates.
