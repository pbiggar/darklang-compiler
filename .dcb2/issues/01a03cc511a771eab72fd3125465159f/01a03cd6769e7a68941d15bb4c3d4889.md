# Trial result

Rejected the bounded recursive-helper entry-peeling trial because it increased primes code size and register pressure and was slower in the focused primes measurement.

## Evidence

## Important changes

- **No source change retained** — **Reason:** the isolated recursive scalar-helper inlining candidate regressed the focused primes trial, so the worktree was restored to the pinned baseline without a commit.

## How it works

Baseline ANF retained direct isPrime-to-isDivisible calls; the production primes benchmark uses primitive Float.sqrt rather than recursive isqrt, while benchmarks.e2e contains the recursive isqrt form. LIR showed isPrime was already inlined into countPrimes, leaving isDivisible call setup as the relevant boundary. The attempted bounded transformation peeled one entry iteration of eligible all-scalar self-recursive helpers, retaining the self-recursive helper call. Although outputs matched, the copied modulo path was duplicated into isPrime and countPrimes, retained the same number of static isDivisible calls, increased binary size by 352 bytes, and raised callee-saved register use. The focused benchmark regressed, so no candidate, tests, or commit were retained. Residual risk is limited to the unimplemented optimization; baseline semantics and repository contents are unchanged.

## Algorithm

1. Audit ANF and LIR for primes helper calls.
2. Trial one-entry expansion for small scalar self-recursive helpers with a two-site caller cap.
3. Preserve helper recursion by leaving its recursive call as a normal helper call.
4. Compare generated LIR, binary size, behavior, and bounded primes runtime.
5. Reject and remove the trial after the focused measurement regressed.
