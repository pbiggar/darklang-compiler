The registered verifier found a clear AST → ANF focused win of 8.0 ms (26.8%), exceeding the 3.9 ms threshold, with identical normalized MIR, executable bytes, native output, and passing constructor-dispatch checks. No established-suite improvement was proven; overall multiplier: 1×.

## Evidence

## Problems

Replace linear constructor-tag test chains with a semantics-preserving balanced dispatch tree when it reduces generated branches.

## Solution

Eligible source-ordered equality chains are replaced by balanced `tag <= boundary` dispatch. Exhaustive unique tags make source order unobservable, while payload extraction and existing body lowering remain inside the selected leaf, preserving binding order, nested-pattern behavior, match failure, and reference counts. Focused tests cover eligible and ineligible paths. The compiler-pass timing produced a clear win under the bounded verifier, although prior runtime evidence was neutral and the small dispatch fixture grew by eight bytes, leaving workload-dependent code-size and branch-prediction risk.

## Implementation

- Recognizes exhaustive matches with at least four unique, unguarded constructor cases and irrefutable payload patterns.
- Sorts scalar constructor tags and builds a balanced threshold tree.
- Hoists boxed-sum tag extraction outside the tree.
- Preserves sequential lowering for guarded, overlapping, grouped, nested-rejecting, and non-exhaustive matches.
- Adds deterministic ANF-shape and native semantic coverage.

### Algorithm

1. Require at least four cases and prove exhaustive constructor coverage. 2. Require one unguarded pattern per case, irrefutable payload patterns, and distinct scalar tags. 3. Sort cases by runtime tag. 4. Load a boxed-sum tag once, or use an enum scrutinee directly. 5. Split cases at the midpoint. 6. Emit `tag <= maximum-left-tag` and recursively lower both halves. 7. At each leaf, invoke the existing payload extraction and body lowering. 8. Send every ineligible match through the original sequential chain.

### Example

An eight-way match previously reached the final constructor through seven equality comparisons and, for a boxed sum, seven tag loads. The candidate loads the tag once and follows three threshold comparisons through a balanced tree. A payload such as `PayloadA("balanced" ++ "-payload")` is extracted only after selecting the `PayloadA` leaf, and still evaluates to `"balanced-payload"`.
