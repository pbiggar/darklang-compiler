## How it works

The MIR CSE pass had no heap-read availability key, so lowered scalar heap loads survived despite exact SSA address/offset/type matches. Both trial items are compatible and retained in one narrow implementation: immediate scalar store-to-load forwarding plus repeated scalar-load reuse in a barrier-free basic-block region. It uses no alias analysis, has linear per-block map operations, and does not remove stores or ownership operations. Residual risk is intentionally bounded to scalar metadata correctness; non-scalar or unknown values are barriers.

## Algorithm

1. Accept only HeapLoad/HeapStore operations with the same SSA address, byte offset, and concrete scalar type.
2. Forward a scalar store only to its immediately following matching load.
3. Reuse later matching scalar loads from the prior SSA result across scalar moves/computations.
4. Clear all availability at calls, stores, allocations, memory/runtime instructions, ownership-sensitive values, and block boundaries.
5. Lower forwarded loads as typed Mov instructions; subsequent lowering emits no HeapLoad for the focused case.
