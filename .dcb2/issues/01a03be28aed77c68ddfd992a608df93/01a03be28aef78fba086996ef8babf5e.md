# Trial local scalar heap-load forwarding

Remove provably redundant scalar heap loads without changing memory or ownership behavior.

## Constraints

- Limit analysis to exact same SSA address, field offset, and scalar value type within one basic block.
- Stop forwarding at calls, stores, control-flow boundaries, allocations, and ownership-sensitive values.
- Add focused MIR/LIR and generated-code proofs before implementation; run ./run-tests --ai and ./benchmarks/run_benchmarks.sh --verify routine.
- Retain only a measurable instruction-count or runtime benefit; update docs/classic-optimizations.md and remove temporary benchmark inputs.

## Trial work

### Trial item 01a03be28aed79cf80203d887a49a4d1

Title: Forward immediate scalar store-to-load pairs

Category: MIR local memory forwarding

Evidence: The MIR optimizer treats HeapLoad as non-effecting but has no store-to-load forwarding; the existing classic backlog covers aggregate projection forwarding but not lowered heap operations.

Outcome:

Rewrite an adjacent matching HeapStore followed by HeapLoad into a scalar move or direct use.

### Trial item 01a03be28aed71c69885366556accf6c

Title: Reuse repeated scalar loads in a barrier-free block

Category: MIR local value numbering

Evidence: Current MIR CSE only keys BinOp and UnaryOp expressions, leaving repeated exact heap reads outside its available-expression analysis.

Outcome:

Replace a later identical HeapLoad with the earlier SSA result when no intervening memory barrier can affect it.
