## What changed

## How it works

Checkpoint d8a76fd035 incorrectly replaced LICM's existing purity proof with DCE's stricter termination proof, causing the two authoritative MIR mismatches. Updating expected snapshots would have concealed a real LICM regression, while one shared proof would either weaken LICM or make DCE unsound around divergence. The retained split restores recursive and mutually recursive LICM hoisting while allowing DCE removal only for acyclic pure scalar calls. Each fixed point is worst-case O(F·I), where F is function count and I is inspected MIR instructions, with set-operation factors. Residual risk is worker-owned full-suite and routine-benchmark validation.

## Algorithm

1. Extract direct callees and reject functions with local runtime, I/O, time, randomness, coverage, indirect-call, allocation, or ownership effects. 2. For LICM, initialize the proven set with all locally pure candidates and repeatedly remove callers of unproven functions, retaining pure recursive components. 3. For DCE, initialize an empty set and repeatedly add locally pure functions whose callees are already proven, excluding recursive components. 4. Pass the two proof sets independently through MIR optimization. 5. LICM may hoist invariant scalar calls from its effect-free set. 6. DCE may erase an unused direct Call only when its callee is in the terminating set and every argument and result is scalar. 7. Ordinary liveness then removes dead argument computations; recursive, indirect, effecting, and ownership-sensitive calls remain.
