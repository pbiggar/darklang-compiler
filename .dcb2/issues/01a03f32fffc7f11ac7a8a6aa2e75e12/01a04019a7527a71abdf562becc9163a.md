## How it works

The retained checkpoint correctly began preserving scalar projection types so LICM could distinguish safe scalar loads from managed values. Authoritative verification found the first concrete failure in `closure_devirtualization_captured_local`: actual MIR correctly printed `HeapLoad(v0, 8) : TInt64`, but its pre-existing golden expectation still represented the former untyped lowering. The narrow reproducer failed exactly on that annotation. Removing the type propagation or suppressing it in the printer was rejected because either alternative would weaken the LICM proof or hide meaningful MIR metadata. The retained repair updates only the stale expectation and documents the typed-output contract. The optimization itself conservatively scans each examined natural loop and preheader, so its analysis is linear in their instruction count. Residual risk is limited to missed optimization when an effect is provably unrelated; alias analysis is intentionally not attempted, and unclassified effects remain barriers. Candidate `3816476b30` is clean and directly preserves checkpoint `18d6b9eeadbeeea047700f95168d1ab37b7a4e51` as its parent. Although focused fixtures demonstrate the transformation, the existing benchmark was neutral, so the overall result is no-improvement.

## Algorithm

1. Discover loops through the existing natural-loop analysis and accept only reducible loops.
2. Require one usable preheader.
3. Collect loop definitions and require the HeapLoad address SSA value to be invariant.
4. Require a fixed encoded field offset and an explicit scalar result type.
5. Scan all loop blocks and the preheader for load-availability barriers.
6. Treat heap/raw writes, calls, allocation, reference-count operations, and every unclassified memory effect as barriers; conservatively assume distinct SSA addresses may alias.
7. Hoist an accepted HeapLoad once into the preheader and preserve existing SSA operand rewriting.
8. Leave every rejected or managed load in its original loop block.
9. Preserve scalar projection metadata in MIR and include it in golden MIR output, including captured closure fields.
