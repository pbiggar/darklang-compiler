## What changed

The worktree is clean, committed, and not integrated.

## How it works

Current fib retained two recursive calls for each non-base case. The retained solution is deliberately narrower than operator-generic TRMO: only wrapping Int64 addition is reassociated, while Float and unsupported or mixed recursive shapes remain unchanged. No alternate rewrite was retained during refresh because this complete-recursion and return-type gate provides the smallest explicit semantic boundary. Compilation adds linear scans over ANF size. Runtime fib remains exponential in work, but removes one sibling call/return path; stack remains O(n), with the retained recursive descent having the original maximum depth and the other descent becoming a loop. Residual risk is primarily missed optimization opportunities from the intentionally syntactic recognizer and generated-helper registry interactions, covered by full-suite and focused pipeline tests.

## Algorithm

1. Count direct self calls and recognized sibling-addition pairs. 2. Proceed only for Int64-returning functions where every self call belongs to exactly one two-call pair. 3. Generate a collision-safe helper with an extra Int64 accumulator. 4. Invoke the first sibling recursively with accumulator zero. 5. Add its result to the carried accumulator using wrapping Int64 addition. 6. Invoke the second sibling with the updated accumulator in tail position. 7. Add the accumulator to unchanged base-case results. 8. Let existing TCO lower the tail call to accumulator/n phis and a loop backedge.
