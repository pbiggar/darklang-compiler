## Evidence

## Problems

Eliminate the second recursive call in fib through an accumulator-based tail-recursion-modulo-operation transform.

## Solution

The existing ANF optimization transforms eligible wrapping Int64 sibling recursion into `fib$trmo(n, accumulator)`, excludes Float addition, and relies on tail-call lowering for the loop back-edge. Both measured revisions already contain this implementation, so there is no candidate delta to retain; the apparent 4.0 ms slowdown is below the 12.3 ms noise threshold and is invalidated by identical revisions.

## Implementation

- No files changed; the preserved candidate remains available at `2b615bec6f58009ebaaedd90cc7c87cb9a957676`.

### Algorithm

1. Match complete direct self-recursion joined by Int64 addition.
2. Create a zero-initialized accumulator helper.
3. Evaluate the first recursive branch normally.
4. Add that result to the accumulator using wrapping Int64 addition.
5. Tail-call the helper with the second argument and updated accumulator.
6. Lower the tail call to the helper body back-edge; base case returns accumulator plus the base value.

### Example

For `fib(n) = if n <= 1 then n else fib(n - 1) + fib(n - 2)`, ANF contains `fib$trmo(t0, 0)` and recursive `fib$trmo(t4, t10)`. MIR has one `Call(fib$trmo, [n - 1, 0])`, accumulator/argument φ-nodes, and `jump fib$trmo_body`; post-allocation ARM64-shaped LIR has the one `Call(fib$trmo, ...)` followed by `Jump(Label "fib$trmo_body")`, proving the second sibling recursion is a loop back-edge.
