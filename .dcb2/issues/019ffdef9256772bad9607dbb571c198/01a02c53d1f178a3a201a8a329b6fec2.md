Yes—there is a good per-pass-facing home, but I would not replace the direct MIR CFG tests entirely.

`src/Tests/optimization/mir.opt` is the repository’s existing MIR optimization snapshot suite: it compiles source through SSA construction and `MIR_Optimize.optimizeProgram`, then asserts the optimized MIR. It already covers LICM, loop unrolling, and CFG simplifications. A canonicalization snapshot belongs there so `--dump-mir` / the normal optimization-test path visibly exposes the resulting preheader.

The three retained direct tests in `src/Tests/optimizations/MIROptimizeTests.fs` should remain as structural coverage. Multiple direct entry edges, exact phi-edge rewriting, and nested-loop topology are CFG-level cases that the structured source lowering may not naturally produce; the current per-pass fixture formats begin at source and have no raw-MIR-input runner for MIR optimization.

Recommended split:

- Keep the direct MIR tests as the precise proof of reducibility gating, deterministic preheader labels, phi rewrites, existing-preheader reuse, and nesting.
- Add one `mir.opt` snapshot for a source-representable case that demonstrates an invariant operation in a generated preheader after MIR optimization.
- If we want all three cases represented as fixtures, first add a dedicated raw-MIR optimizer fixture format/runner; that is a broader testing-infrastructure change, not just moving tests.

This matches nearby precedent: same-target branch elimination keeps its direct `MIROptimizeTests.fs` structural test, while source-to-optimized-MIR behavior is also recorded in `src/Tests/optimization/mir.opt`.
