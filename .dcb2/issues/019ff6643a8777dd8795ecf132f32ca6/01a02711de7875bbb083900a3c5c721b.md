# Trial result

Direct operand folding removes material temporary block-use allocation; the clean candidate is committed for worker validation.

## Evidence

## What changed

Scoped solely to getBlockUses: replaced getOperandUses singleton-set construction and Set.union intermediates with one local addOperand fold that directly Set.adds Register operands; no test or instrumentation changes retained.

## How it works

Temporary fasta profiling measured 1,792,216 bytes allocated while collecting the user program's SSA block-use sets. The retained fold preserves set membership while eliminating singleton operand sets and unions. Shared-CPU timing became too slow/noisy after one baseline sample, so the required ten-run matrices and canonical checks were deferred under the inherited worker-owned validation protocol.

## Algorithm

1. Match an operand. 2. Add its VReg directly to the current use set when it is Register. 3. Leave non-register operands unchanged. 4. Fold this operation across every instruction operand and terminator operand.
