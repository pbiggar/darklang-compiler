# Design brief

## Problem

Observable compiler behavior may still differ from the interpreter within jointly supported capabilities.

## Goals

- Restore interpreter parity for confirmed, unowned observable differences
- Preserve ahead-of-time type checking and exclude lazy-checking artifacts
- Classify intentional divergences explicitly without misclassifying supported operator or pattern behavior as extensions

## Proposed solution

Compare compiler c61de9fdcbc9334e8ae334c73fa81486cc584d98 with darklang/dark 04fbe9dcc995c6188757d583e273cbd30a3e2d3d, using prior reports only as leads. Revalidate candidates with current source evidence and focused same-source behavior where practical, exclude module- and language-feature-owned gaps plus runtime-failure transport and stack identity, then create one parity-fix child for each independent observable contract while keeping related behavior together and reusing interpreter Dark code where portable.

## Success criteria

- Every retained comparison records both exact revisions and current evidence
- Each confirmed unowned difference has an independently deliverable parity-fix child
- Equivalent supported programs have matching values, errors, ordering, representation, and side effects
- Compiler-only extensions and intentional divergences are explicit
- No child weakens compile-time checking, duplicates existing ownership, or targets performance-only behavior
