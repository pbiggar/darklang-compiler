# Design brief

## Problem

The compiler has unverified observable behavior differences from the current interpreter within features both support, and the intended outcome is parity fixes rather than a standalone inventory.

## Goals

- Make compiler behavior match the current interpreter for well-typed programs supported by both implementations.
- Revalidate each suspected difference against exact compiler and interpreter revisions using current evidence.
- Exclude performance-only differences, lazy-type-checking artifacts, and gaps already owned by feature-specific work.
- Classify compiler-only extensions and intentional divergences separately from parity defects.
- Keep related behavior together while separating independently observable outcomes.

## Proposed solution

Perform a version-locked comparison to discover and revalidate differences, then create focused child issues that deliver compiler changes restoring interpreter parity. Each child should cover one independently observable semantic or genuine design boundary, supported by current source evidence and same-source comparison where practical; tightly related function, type, and behavior differences should remain together. Classification is supporting evidence, not the primary deliverable.

## Success criteria

- Every comparison records the exact compiler HEAD and darklang/dark revision used.
- Every retained parity defect has a child issue whose outcome is matching interpreter behavior.
- Retained findings are supported by current evidence and focused behavioral comparison where practical.
- Compiler-only extensions and intentional divergences are explicitly distinguished from defects.
- No child duplicates feature-owned work or targets performance-only differences or behavior unique to lazily checked invalid programs.
- Child boundaries are independently deliverable without fragmenting related behavior.
