# Design brief

## Problem

The reopened inventory still lacks a current, non-duplicative plan for resolving remaining observable interpreter/compiler behavior differences after the previously delivered subset.

## Goals

- Identify every remaining cross-cutting behavior gap exactly once
- Use interpreter behavior as the parity baseline while separating extensions and intentional divergences
- Create independently deliverable, evidence-backed resolution scopes

## Proposed solution

Re-audit compiler e677bb5edfaf6ac7f04cbde92f7a3e13609b6f9e against darklang/dark 04fbe9dcc995c6188757d583e273cbd30a3e2d3d, labeling supplemental installed-interpreter probes separately as a70f30de21302caa91fd98a2d15aefb1ec423a4e. Revalidate only differences remaining after 56fe54ebb6ed686be3cded3025c7ab478d847638, exclude module- and language-feature-owned gaps, and create one child per independent observable contract with revision-pinned source and focused behavioral evidence.

## Success criteria

- Every remaining in-scope difference appears in exactly one child or is explicitly classified as an extension or intentional divergence
- Each child records the exact revisions used and current supporting evidence
- Previously resolved, stale, performance-only, and sibling-owned findings are absent
- Each child defines an observable parity outcome rather than documentation-only work

## Open questions

- Should native script final-value output remain an explicit compiler divergence, or should run and eval behavior be separated to match the interpreter?
