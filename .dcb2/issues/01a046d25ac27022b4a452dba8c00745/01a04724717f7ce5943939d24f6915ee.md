# Trial result

Spill-slot coloring reduced the focused three-spill frame from 32 to 16 bytes and was committed as an isolated candidate. No established-suite improvement was proven; overall multiplier: 1×.

## Evidence

## Problems

Reduce spill-frame size when separately spilled values have disjoint live ranges.

## Solution

The allocator now greedily assigns each spill the first stack slot not used by an interference neighbor. This preserves ABI alignment, negative 8-byte slot representation, callee-save layout, and spill repair. The focused test proves disjoint values alias safely while call-live/interfering values do not. Residual risk: ARM64/x64 generated-code regressions and runtime microbenchmark measurements were not added before the checkpoint; the worker-owned repository-wide suite and routine benchmark were intentionally not run.

## Implementation

- Reused spill slots for integer virtual registers with no interference edge.
- Derived frame size from the deepest assigned spill offset.
- Added allocated-LIR coverage for disjoint spills and interfering/call-live spills.
- Documented the optimization in `docs/classic-optimizations.md`.

### Algorithm

1. Preserve physical-register assignments.
2. Collect spilled or invalid-color vertices in deterministic domain order.
3. For each vertex, inspect already-assigned interference neighbors.
4. Assign the first negative 8-byte offset absent from those neighbors.
5. Set stack size to the 16-byte-aligned deepest assigned spill slot.

### Example

Before: three forced non-interfering spills received `-8`, `-16`, `-24`, requiring a 32-byte aligned frame. After: all three receive `-8`, requiring a 16-byte frame. A three-way interference clique, modeling values live at a call, remains `-8`, `-16`, `-24`; this demonstrates that simultaneous values cannot alias.
