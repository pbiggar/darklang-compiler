# Design brief

## Problem

At compiler b2e1f3d1e4ce0338d4c4662db9a1326f2e2cb899, match behavior is not yet governed by a revision-pinned parity contract with interpreter 04fbe9dcc995c6188757d583e273cbd30a3e2d3d, leaving uncertainty around supported patterns, bindings, guards, branch selection, diagnostics, and failure semantics.

## Goals

- Match the pinned interpreter’s public syntax and behavior for every exposed literal, variable, wildcard, tuple, list, record, constructor, nested, guarded, and alternative pattern.
- Preserve left-to-right matching, binding availability, repeated-name behavior, guard typing and evaluation, first-eligible-branch selection, unreachable and exhaustiveness diagnostics, and observable non-exhaustive failure.
- Treat compiler-only extensions and intentional divergences explicitly, removing unsupported patterns and migrating affected compiler match expressions.
- Keep aggregate and ADT construction or representation within their existing child scopes while centralizing shared pattern grammar, typing, decision behavior, and failure semantics.

## Proposed solution

Define a single interpreter-led match contract pinned to the stated revisions, using DCB1 report commit 8a402797 and current parity documents only as leads that must be revalidated. Align parsing, static checking, match lowering, and runtime failure around that contract so structural tests and alternatives proceed left to right, bindings become available only after a successful pattern, guards run afterward in the established binding scope, and the first pattern-plus-guard success selects the branch. Restrict parity support to forms publicly exposed by the pinned interpreter; classify any remaining compiler behavior as an explicit extension or intentional divergence.

## Success criteria

- Revision-pinned same-source comparisons agree on accepted syntax, static errors, bindings, guard behavior, selected branch, and observable match failure.
- Every interpreter-exposed pattern form composes correctly when nested, including within alternatives and guarded branches.
- Repeated names, alternative bindings, unreachable branches, and non-exhaustive matches reproduce the pinned interpreter’s observable behavior.
- Unsupported compiler-only patterns are absent from the parity surface, affected compiler match expressions are migrated, and intentional divergences are documented explicitly.
- Each retained behavioral claim is backed by current source evidence and, where practical, a focused same-source probe at both exact revisions.
