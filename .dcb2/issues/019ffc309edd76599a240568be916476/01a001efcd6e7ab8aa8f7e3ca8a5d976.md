# Implementation plan

Single contained implementation scope. All parity findings compare compiler C@b2e1f3d1e4ce0338d4c4662db9a1326f2e2cb899 with darklang/dark I@04fbe9dcc995c6188757d583e273cbd30a3e2d3d; DCB1@8a402797 was used only to locate evidence. Retain whole-program AOT checking of every arm as an intentional divergence from interpreter errors deferred on unselected paths.

## Work item 01a001efcd6e7c0695b71ae7ee3690a8

Title: Adopt a recursive match-pattern model

Category: type

Evidence: C@b2e1f3d1 AST.fs:105-128 and MatchCase:178-183 model alternatives outside Pattern and constructors with one optional payload; [I@04fbe9 ProgramTypes.fs:270-301](https://github.com/darklang/dark/blob/04fbe9dcc995c6188757d583e273cbd30a3e2d3d/backend/src/LibExecution/ProgramTypes.fs#L270-L301) has MPInt, recursive MPOr, and constructor field lists.

Outcome:

Replace case-level pattern groups with one recursive pattern per arm, including an explicit non-empty alternative-pattern case, arbitrary-precision integer literals, recursive list-cons structure, and zero-or-more constructor fields. Keep tuple, list, and ADT value representation outside this change while exposing the typed field information required by matching.

## Work item 01a001efcd6e7fb5a0ab3dad9e8d601e

Title: Implement interpreter pattern grammar and precedence

Category: function

Evidence: C@b2e1f3d1 1_InterpreterParser.fs:1227-1482 only groups top-level alternatives and requires parenthesized tuples; [I@04fbe9 Parser.fs:930-1230](https://github.com/darklang/dark/blob/04fbe9dcc995c6188757d583e273cbd30a3e2d3d/backend/src/LibParser/Parser.fs#L930-L1230) defines `| < tuple < ::`, bare tuples, constructor-field parsing, and nested alternatives.

Outcome:

Parse alternatives as the loosest pattern operator, followed by bare or parenthesized tuples and right-associative list cons. Support unit, wildcard, variables, all exposed literals, exact lists, unqualified constructors, bare top-level constructor fields, immediate-parenthesized nested constructors, and nested alternatives without confusing an alternative bar with the next match arm.

## Work item 01a001efcd6e74e8ba44a7f8911a85a6

Title: Remove unsupported pattern extensions

Category: behavior

Evidence: C@b2e1f3d1 AST.fs:126-128 and both parsers accept typed record patterns and `...`; [I@04fbe9 parser:1220-1228](https://github.com/darklang/dark/blob/04fbe9dcc995c6188757d583e273cbd30a3e2d3d/backend/src/LibParser/Parser.fs#L1220-L1228) rejects `...`, while [public pattern documentation](https://github.com/darklang/dark/blob/04fbe9dcc995c6188757d583e273cbd30a3e2d3d/packages/darklang/cli/docs/pattern-matching.dark#L29-L45) explicitly excludes record patterns.

Outcome:

Reject record destructuring and `...` list-rest syntax in match patterns, remove PRecord-specific typing and lowering, and retain PListCons only as the representation of public `head :: tail` syntax. Record values remain matchable through a variable followed by field access.

## Work item 01a001efcd6e728089a486f6fe6447c2

Title: Align literal-pattern semantics

Category: behavior

Evidence: C@b2e1f3d1 Pattern lacks BigInt and ANF/type checking contains width-specific fallback paths; [I@04fbe9 parser:1017-1097](https://github.com/darklang/dark/blob/04fbe9dcc995c6188757d583e273cbd30a3e2d3d/backend/src/LibParser/Parser.fs#L1017-L1097) exposes the literal inventory, and WrittenTypesToProgramTypes.fs:220-250 normalizes strings/chars.

Outcome:

Type and compare every exposed signed, unsigned, arbitrary-precision, float, Boolean, unit, string, and character literal exactly at its own type; handle signed minima correctly and normalize string and character patterns before comparison. Remove cross-type or width fallbacks.

## Work item 01a001efcd6e7319a6c52bad0c4f1715

Title: Enforce interpreter binder validation

Category: behavior

Evidence: C@b2e1f3d1 AST.fs:16-20 and TypeChecking.fs:3938-3982 allow duplicate behavior to be disabled; [I@04fbe9 Validation.fs:79-201](https://github.com/darklang/dark/blob/04fbe9dcc995c6188757d583e273cbd30a3e2d3d/backend/src/LibParser/Validation.fs#L79-L201) defines ignored names, duplicate diagnostics, and equal alternative-binding sets.

Outcome:

Reject repeated ordinary names in every nested pattern, allow repeated ignored names beginning with `_` with the pinned last-binding behavior, require every alternative to bind the same usable names, and remove the configurable last-wins mode for ordinary binders. Make the selected alternative's bindings available to its guard and body only after complete structural success.

## Work item 01a001efcd6e7209bc22918c31f20818

Title: Centralize recursive pattern typing

Category: function

Evidence: C@b2e1f3d1 TypeChecking.fs:3561-3984 has separate form-specific paths, TVar placeholders, non-match exceptions, and Int64-fallback regressions documented in pattern_matching.e2e:369-476; interpreter runtime instead performs direct shape checks in [Interpreter.fs:430-555](https://github.com/darklang/dark/blob/04fbe9dcc995c6188757d583e273cbd30a3e2d3d/backend/src/LibExecution/Interpreter.fs#L430-L555).

Diagnose statically impossible shapes and constructor arities consistently under the compiler's AOT contract.

## Work item 01a001efcd6e748ea4f5ea86fc8650e7

Title: Type guards in successful binding scope

Category: behavior

Evidence: C@b2e1f3d1 TypeChecking.fs:4133-4238 checks guards but can stop checking later cases; [I@04fbe9 lowering:966-1013](https://github.com/darklang/dark/blob/04fbe9dcc995c6188757d583e273cbd30a3e2d3d/backend/src/LibExecution/ProgramTypesToRuntimeTypes.fs#L966-L1013) installs pattern bindings before compiling the guard. Outcome:

## Work item 01a001efcd6e79b49ae86fbe84f664b9

Title: Lower one left-to-right match decision path

Category: function

Evidence: C@b2e1f3d1 2_AST_to_ANF.fs:4972-7566 contains separate comparison, extraction, guarded, exact-list, and list-cons implementations; [I@04fbe9 Interpreter.fs:515-555](https://github.com/darklang/dark/blob/04fbe9dcc995c6188757d583e273cbd30a3e2d3d/backend/src/LibExecution/Interpreter.fs#L515-L555) short-circuits children and rolls back failed alternative bindings.

Outcome:

Replace parallel specialized matching paths with one recursive decision builder over existing aggregate and ADT access operations. Evaluate the scrutinee once, test tuple/list/constructor children left-to-right with short-circuiting, discard bindings from failed partial matches, and try alternatives left-to-right.

## Work item 01a001efcd6e708fb8eee5ac23b4b36a

Title: Preserve first-eligible-case selection

Category: behavior

Evidence: C@b2e1f3d1 ANF lowering:7644-7761 expands alternatives and has multiple guard paths; [I@04fbe9 lowering:1035-1060](https://github.com/darklang/dark/blob/04fbe9dcc995c6188757d583e273cbd30a3e2d3d/backend/src/LibExecution/ProgramTypesToRuntimeTypes.fs#L1035-L1060) emits pattern check, guard, body, then next case. I ematch.dark:634-746 tests selected and unselected failures.

Outcome:

Within an alternative pattern, let the first structural success fix the bindings, evaluate the case guard once, and continue with the next case—not another alternative—when that guard is false. Execute only the selected body and preserve errors from the scrutinee, selected guard, or selected body while leaving unselected expressions unevaluated.

## Work item 01a001efcd6e7f0ea29052edec568b4e

Title: Match exhaustiveness and reachability behavior

Category: behavior

Evidence: I ematch.dark:18-25 accepts branches after a variable and :634-636 observes non-exhaustive failure at runtime; C@b2e1f3d1 TypeChecking.fs:3986-4241 short-circuits later type checking, while docs/features/pattern-matching.md:137-160 incorrectly claims compile-time rejection.

Continue AOT checking every arm for ordinary name and type errors, and route an actual runtime fall-through to the match-failure path.
