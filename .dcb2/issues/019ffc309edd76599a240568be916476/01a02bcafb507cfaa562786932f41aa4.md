Understood: non-exhaustive matching is an intentional AOT divergence and must be rejected at compile time; match lowering must never emit a user-observable non-exhaustive runtime failure.

That changes the accepted behavior materially: the current ANF fallback (`makeNoMatchingCaseFallback`) can remain only as an unreachable compiler invariant, not generated program behavior. The checker must reject every match whose coverage cannot be proven—this includes incomplete ADT variants, literal domains without a catch-all, finite list-shape gaps, and guarded arms that do not guarantee coverage. Cases involving unconstrained generic or otherwise unprovable shapes must also be rejected rather than deferred to execution.

The explicit stage action needed is to revise the accepted implementation scope’s exhaustiveness/failure work item and its test expectations from runtime fallthrough to mandatory static coverage diagnostics. No such revision or repository change has been made here.
