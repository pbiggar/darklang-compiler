# Fix benchmark counts

It appears the benchmark baselines stored in the repo are not accurate. This seems to prevent verification with the quick benchmarks.

The goal of the quick benchmarks is to ensure that we are only getting faster and never slower. Thus, when we get faster, the baseline moves to the latest result. The same is true of the real benchmarks.

However, it seems it was not implemented this way. Investigate the way that it was implemented, and the difference, and fix it.
