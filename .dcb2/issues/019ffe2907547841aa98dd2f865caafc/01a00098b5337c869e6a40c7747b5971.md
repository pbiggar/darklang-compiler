# Design brief

## Problem

Quick benchmarks enforce per-benchmark non-regression with manual snapshot replacement, while full verification requires exact counts and recording can replace a better baseline with a slower run. Neither workflow maintains the best-known overall suite performance.

## Goals

- Prevent aggregate benchmark performance from worsening
- Allow small benchmark losses when offset by larger gains elsewhere
- Use the same monotonic baseline policy for quick and full suites

## Proposed solution

Re-establish each suite from a trusted complete run, then compare runs using a scale-neutral aggregate of per-benchmark count changes consistent with geometric-mean reporting. Equal or better aggregate results pass; a genuine improvement replaces the entire baseline snapshot with the latest counts, including any compensated individual losses. A worse aggregate fails and cannot replace the baseline. Preserve individual deltas and run history for visibility, and reset baselines explicitly when workloads or measurement contracts change.

## Success criteria

- A mixed run passes when its aggregate performance is equal or better, even if some benchmarks regress
- An aggregate improvement advances the complete baseline to the latest result
- An aggregate regression fails and leaves the stronger baseline unchanged
- Quick and full benchmark workflows produce consistent decisions
- Stored baseline counts represent complete trusted suite snapshots
