**Native AOT is not usable as-is, but it looks viable after a small compatibility fix.**

Evidence from the repository:

- `DarkCompiler.fsproj` is a simple `net10.0` executable with no external package dependencies. An isolated `linux-arm64` Native AOT publish successfully restored the Native AOT runtime pack and reached the native AOT compiler (`ilc`); it did not report an AOT/trimming error before the 60-second safety timeout.
- Native AOT supports Linux Arm64 and produces a single executable with no runtime JIT. [Native AOT deployment](https://learn.microsoft.com/en-us/dotnet/core/deploying/native-aot/)
- There is one definite runtime incompatibility in `CompilerLibrary.fs`: `loadDarkFileAllowInternal` uses `Assembly.GetExecutingAssembly().Location` to locate `stdlib/*.dark` and related source files. Native AOT implies single-file deployment, for which `Assembly.Location` is empty. The documented replacement for locating files beside the executable is `AppContext.BaseDirectory`. [Single-file API behavior](https://learn.microsoft.com/en-us/dotnet/core/deploying/single-file/overview)

Consequently, the current AOT executable would fail while loading the stdlib, before compiling the benchmark program. The fallback paths do not help because constructing the first path from the empty assembly location occurs first.

There is also a packaging requirement: the compiler reads `.dark` stdlib source files at runtime, while the project currently does not declare them as publish content. The AOT benchmark must either place those files beside the AOT executable or deliberately run it from a source-tree working directory after the location fix.

The remaining validation sequence is clear:

1. Make the location lookup Native-AOT-safe and define how the stdlib source files accompany the benchmark executable.
2. Complete an isolated `linux-arm64` AOT publish and compile a representative Dark source without running its output.
3. Run that fixed executable under Cachegrind repeatedly and verify identical `I refs` values before adopting it as the deterministic baseline.

The probe wrote only temporary artifacts outside the worktree; the repository remains unchanged.
