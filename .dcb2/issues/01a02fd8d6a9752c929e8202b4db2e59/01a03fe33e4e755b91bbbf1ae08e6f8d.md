The direct Native AOT probe **fails today**, so there is no executable to run under Cachegrind yet.

I published the existing project for `linux-arm64` with all artifacts redirected to `/tmp`; the worktree remains unchanged. Native AOT reached `ilc` and then produced these build-stopping diagnostics:

```text
FSharp.Core.dll : error IL3053: Assembly 'FSharp.Core' produced AOT analysis warnings.
FSharp.Core.dll : error IL2104: Assembly 'FSharp.Core' produced trim warnings.
CompilerLibrary.fs(1193): error IL3000:
  Assembly.Location always returns an empty string for assemblies
  embedded in a single-file app.
```

The last error confirms the static finding. Running from the repository root is not sufficient: `loadDarkFileAllowInternal` first calls `Path.Combine` using the empty `Assembly.Location` directory, before it reaches its current-working-directory fallback.

So the exact status is:

- Native AOT toolchain and Linux Arm64 targeting work in this environment.
- The current project’s warnings-as-errors policy rejects Native AOT because FSharp.Core emits AOT/trim warnings; those warnings need inspection rather than blind suppression.
- The compiler has one known Native-AOT-incompatible file-location access that must be changed to `AppContext.BaseDirectory` (or equivalent) before it could load the stdlib.

Native AOT remains plausible, but it requires an AOT-compatibility change before we can validate execution or deterministic Cachegrind counts. No source files were changed.
