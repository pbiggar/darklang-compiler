# Trial result

The refreshed candidate regressed an earlier verified improvement.

## Evidence

## Problems

Remove redundant reference-count traffic when freshly built tree children are immediately assembled into a recursive sum.

## Solution

The ownership transform is deliberately narrow and its LIR shows the intended removal of six local RC operations per `makeTree` internal node while preserving the three allocation sites and observed program output. However, the registered verifier requires normalized requested-IR and byte-executable equality; both differ, and the selected-pass median is unchanged (0.7 ms versus 0.7 ms). Under the required threshold this is not a clear focused win, so the preserved candidate is reported as no-improvement.

## Implementation

- Candidate recognizes distinct, direct self-recursive owned children placed once in a tuple that is immediately returned as a sum payload.
- It transfers ownership through the tuple and outer sum, removing two child retains, one payload retain, and three matching releases.
- It adds an LIR snapshot for the recursive-sum ownership-transfer case.
- No files or checkpoints were changed during this measurement.

### Algorithm

1. Identify a tuple whose elements are distinct direct self-recursive call results.
2. Require owned, non-borrowed children with exactly one transfer into the tuple.
3. Require the tuple to be the payload of an immediately returned tagged sum.
4. Transfer child ownership to the tuple and tuple ownership to the sum.
5. Omit only the balanced local retains/releases; retain normal recursive destruction thereafter.

### Example

Baseline `makeTree` LIR performs `RefCountInc(child1)`, `RefCountInc(child2)`, allocates/stores the tuple, `RefCountInc(tuple)`, allocates/stores the sum, then decrements tuple, child2, and child1. Candidate LIR allocates/stores the same tuple and sum directly with no local RC operations. The full binary_trees LIR count falls from 14 to 2 RC operations; `makeTree` falls from 6 to 0, while its three static HeapAlloc sites remain unchanged (98,302 dynamic allocations for a depth-15 tree).

## Prior verified result

## Problems

Remove redundant reference-count traffic when freshly built tree children are immediately assembled into a recursive sum.

## Solution

The transform accepts only distinct, non-borrowed direct self-recursive results that flow once into a payload tuple and then once into the immediately returned tagged aggregate. Recursive destruction still owns and releases the transferred graph normally. Allocation sites and order are unchanged, preserving allocation-failure behavior; the shared LIR change applies equally to ARM64 and x64 lowering.

## Implementation

- Added a strict fresh-child transfer proof in reference-count insertion for direct self-recursive call results assembled into an immediately returned tagged payload.
- Suppressed the corresponding child and payload retains/releases only when ownership is transferred exactly once.
- Added an LIR regression snapshot proving the optimized construction has no local RC traffic.

### Algorithm

1. Recognize a tuple whose elements are distinct direct self-recursive call results.
2. Require each child to be owned, non-borrowed, and used exactly once.
3. Require the tuple to be the payload of an immediately returned tagged aggregate.
4. Transfer child ownership into the payload and payload ownership into the aggregate.
5. Omit only the balanced local retains/releases; leave all later recursive destruction unchanged.

### Example

Before: `childA; childB; inc childA; inc childB; payload=(childA,childB); inc payload; result=(tag,payload); dec payload; dec childB; dec childA`. After: `childA; childB; payload=(childA,childB); result=(tag,payload)`. Each value has one ownership edge into the returned recursive sum.
