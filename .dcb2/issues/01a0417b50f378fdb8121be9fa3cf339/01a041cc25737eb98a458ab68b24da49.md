# Trial result

A committed narrow ownership-transfer optimization removes six redundant reference-count operations per recursive binary-tree internal node. Canonical routine benchmark: 0.992147× overall.

## Evidence

## Problems

Remove redundant reference-count traffic when freshly built tree children are immediately assembled into a recursive sum.

## Solution

The transform accepts only distinct, non-borrowed direct self-recursive results that flow once into a payload tuple and then once into the immediately returned tagged aggregate. Recursive destruction still owns and releases the transferred graph normally. Allocation sites and order are unchanged, preserving allocation-failure behavior; the shared LIR change applies equally to ARM64 and x64 lowering.

## Implementation

- Added a strict fresh-child transfer proof in reference-count insertion for direct self-recursive call results assembled into an immediately returned tagged payload.
- Suppressed the corresponding child and payload retains/releases only when ownership is transferred exactly once.
- Added an LIR regression snapshot proving the optimized construction has no local RC traffic.

### Algorithm

1. Recognize a tuple whose elements are distinct direct self-recursive call results.
2. Require each child to be owned, non-borrowed, and used exactly once.
3. Require the tuple to be the payload of an immediately returned tagged aggregate.
4. Transfer child ownership into the payload and payload ownership into the aggregate.
5. Omit only the balanced local retains/releases; leave all later recursive destruction unchanged.

### Example

Before: `childA; childB; inc childA; inc childB; payload=(childA,childB); inc payload; result=(tag,payload); dec payload; dec childB; dec childA`. After: `childA; childB; payload=(childA,childB); result=(tag,payload)`. Each value has one ownership edge into the returned recursive sum.
