# Design brief

## Problem

At compiler HEAD 7e671f62f5c0de8b5debe0cd1f7b0e928584c13a, control combinators and retry execution remain incomplete versus darklang/dark 04fbe9dcc995c6188757d583e273cbd30a3e2d3d; historical report 8a402797 was used only to locate and revalidate these gaps.

## Goals

- Match interpreter operand ordering, evaluation, and value propagation.
- Match retry results, attempt limits, termination, delay placement, and backoff progression.
- Add only the portable control logic and native delay effect needed for parity.
- Document compiler-only extensions and AOT-specific divergences explicitly.

## Proposed solution

Port the interpreter’s portable control and retry behavior with only necessary compiler-dialect adaptations, correct the adjacent argument-order inconsistency, and add a target-compatible millisecond delay effect. Preserve the compiler’s static typing and native execution model as explicit divergences, including the absence of interpreter capability gating and asynchronous scheduling. Validate against revision-pinned same-source behavior and deterministic callbacks.

## Success criteria

- Control results and argument evaluation match the pinned interpreter across every variant combination.
- Retries return the first success or final failure, invoke callbacks the expected number of times, terminate at the same boundary, and delay only between eligible attempts with matching fixed or exponential progression.
- The delay effect works consistently on every supported native target.
- Parity evidence records both exact revisions, and all retained extensions or intentional divergences are classified.
- Focused conformance coverage and the full compiler suite pass without unrelated behavioral changes.

## Open questions

- The pinned interpreter evaluates value arguments eagerly from left to right; should “canonical laziness” mean preserving that public behavior or introducing an explicitly documented short-circuiting divergence?
