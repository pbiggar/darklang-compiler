# Design brief

## Problem

At compiler HEAD 51093e0a8e31fe45a9aa79a317fbefd6b74fbcc3, behavior differs from darklang/dark 04fbe9dcc995c6188757d583e273cbd30a3e2d3d because remaining Option and Result control combinators and interpreter-compatible Retry execution are absent.

## Goals

- Match the interpreter’s public short-circuiting, argument order, value propagation, retry accounting, termination, backoff, and delay placement.
- Keep compiler-only extensions and intentional divergences explicitly classified without broadening the parity work.
- Introduce only the runtime delay capability required for portable retry execution.

## Proposed solution

Use the pinned interpreter revision as the behavioral contract, port the pure control and retry logic while preserving lazy evaluation and callback results, and add a minimal cross-target delay effect at the execution boundary. Validate parity with deterministic same-source observations, treating DCB1 report commit 8a402797 and existing parity documents only as historical inputs.

## Success criteria

- Equivalent programs short-circuit identically and preserve the same success, error, and alternate values on both revisions.
- Retry execution makes the same number of callback attempts, returns the same final callback result, terminates under the same conditions, computes the same delays, and delays only between eligible attempts.
- Comparison evidence records both pinned revisions and explicitly identifies any compiler-only extension or intentional divergence.
