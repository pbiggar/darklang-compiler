# Trial result

Deferred SSA block and phi-source materialization reduced edigits SSA median time by 14.2% and rename allocation by 36.3% while preserving exact MIR, binaries, output, and instruction counts. Canonical routine benchmark: equal.

## Evidence

## What changed

SSA renaming now accumulates renamed blocks and predecessor-specific phi substitutions in function-local lists, materializes lookup maps once, and applies substitutions in one order-preserving final CFG pass. Added a focused SSA regression test covering multiple phis and reversed predecessor-source order. Temporary profiling was removed, and the clean combined candidate was committed.

## How it works

Profiling found successor-phi reconstruction responsible for 160,527,488 of 267,928,712 renameCFG allocation bytes (59.9%) and a median 292.029ms of 483.449ms measured rename time. The previous traversal persistently replaced the CFG map for every renamed block and reconstructed successor blocks for every incoming edge. The retained solution preserves the dominator traversal, version-stack backtracking, sibling NextVersion threading, unreachable blocks, phi instruction ordering, and predecessor-source ordering while deferring persistent materialization. Total rename allocation fell by 97,300,200 bytes. The stated historical 648.5ms SSA timing was not reproduced on this loaded worker; the pinned baseline median was 389.7ms, so all decisions use interleaved comparable local samples. The repository verification helper could not add its candidate worktree because Git reported dubious ownership, so correctness was independently checked using isolated archive builds and exact byte comparisons. Residual risk is limited to configurations outside the focused SSA and edigits coverage; the worker owns the authoritative full suite and routine verification.

## Algorithm

1. Traverse the dominator tree using the existing SSA version state. 2. Rename each block without inserting it into the CFG map. 3. Record each successor phi substitution as a key of successor label, predecessor label, and original VReg. 4. Accumulate renamed blocks and substitutions in lists during traversal. 5. Materialize both maps once after traversal. 6. Walk the original CFG once, retain unreachable original blocks, select renamed reachable blocks, and apply deferred substitutions by mapping phi sources in their original order.
