# Design brief

## Problem

At compiler b2e1f3d1e4ce0338d4c4662db9a1326f2e2cb899, conditional and sequential expressions diverge from darklang/dark 04fbe9dcc995c6188757d583e273cbd30a3e2d3d in syntax, typing, evaluation order, and failure timing.

## Goals

- Use the interpreter’s public behavior as the parity baseline.
- Preserve lazy branch selection and strict left-to-right sequencing.
- Retain and explicitly classify appropriate ahead-of-time typing divergences.
- Remove compiler-only forms and migrate affected expressions.

## Proposed solution

Align parsing and control-flow semantics as one coherent change. Model sequencing directly, statically require Boolean conditions, unified branch results, and Unit-valued non-final sequence expressions, with the final expression determining sequence type. Evaluate each condition once, execute only its selected branch, and execute sequences in source order. Document earlier static rejection as an intentional compiler divergence, while removing noncanonical forms and retaining revision-linked parity evidence.

## Success criteria

- Every same-source comparison either matches or is explicitly classified as an intentional ahead-of-time divergence.
- Untaken branches never execute, including nested or value-position conditionals.
- Sequences execute left to right, stop after failure or nontermination, and return the final expression’s value.
- Compiler-only forms are removed, affected expressions are migrated, and parity evidence records both exact revisions.
