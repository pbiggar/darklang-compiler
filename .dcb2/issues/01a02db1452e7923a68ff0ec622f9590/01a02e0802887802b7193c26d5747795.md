# Trial result

Retained an isolated closed-Int64-list specialization that reduces fasta by 29,676,320 instructions (5.76%) without changing generic List behavior. Canonical routine benchmark: improved.

## Evidence

## What changed

Added whole-program provenance analysis and balanced direct lookup lowering for proven closed Int64 literals, a focused transformation regression test, and measured updates to the fasta investigation and rejected-experiments record; committed the clean candidate without integrating it.

## How it works

The current implementation uses skew random-access lists, not the older documented FingerTree representation. Fasta's 287-element ALU literal was proven invariant through makeRepeatFasta and getAlu, allowing its exact getAt/Option-elimination shape to become a bounded balanced selection tree while retaining the ordinary List value. Unknown, indirect, differing, non-Int64, and unmatched call shapes retain generic behavior. The transformed probability tables were rejected because makeCumulative returns newly allocated lists, so their literal identity cannot be proved. Residual risk is increased static code size and pending worker-owned repository-wide validation.

## Algorithm

1. Collect closed Int64 literal provenance through lexical bindings and direct-call parameters. 2. Form connected parameter components. 3. Reject components containing unknown, indirect, or differing sources. 4. Match only getAt followed by None fallback and Some identity extraction. 5. Evaluate the index once and preserve negative and upper bounds. 6. Select the literal using a balanced comparison tree. 7. Leave the original List representation, ownership, and all generic paths unchanged.
