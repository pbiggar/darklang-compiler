## How it works

The baseline had no closed-literal List specialization covering fasta, and its MIR retained generic Int64 lookup calls. The candidate specializes only the 287-element ALU list; the transformed probability lists remain on the generic path because `makeCumulative` constructs new Lists. Under the mandatory Pass Optimization contract, however, the candidate is not retainable: AST→ANF compilation became 34.0 ms (84.8%) slower, exceeding the 21.9 ms noise threshold in the regressive direction, while normalized MIR and executable bytes changed. Execution output remained correct at `830939461`. No five-pair confirmation was run because the result was decisively regressive and failed equality gates. The candidate checkpoint and all raw artifacts remain available. Lookup in the specialized path is O(log n) comparisons with O(n) generated code; residual risks are compile-time/code-size growth and incomplete AST source tracking, while generic fallback limits semantic exposure.

## Algorithm

1. Track each local function parameter receiving a closed Int64 List literal through direct calls. 2. Mark a component ineligible if any source is unknown, indirect, or differs from the common literal. 3. Recognize only `getAt` followed by `None -> fallback | Some value -> value`. 4. Evaluate the index once and preserve negative and upper-bound fallback behavior. 5. Select the literal value through a balanced comparison tree. 6. Leave the original List value, ownership, ordering, identity, and every unproven lookup unchanged.
