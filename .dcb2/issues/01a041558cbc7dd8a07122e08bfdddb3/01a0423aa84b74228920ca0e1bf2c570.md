# Trial result

Repaired conditional empty-block cleanup, preserving scalar tail-merge phi edges while restoring canonical loop CFGs. No established-suite improvement was proven; overall multiplier: 1×.

## Evidence

## Problems

Remove duplicated pure MIR branch tails when a shared continuation measurably improves generated code.

## Solution

The prior repair applied the unconditional-predecessor rule to every empty block, preventing safe cleanup of ordinary conditional edges and changing many unrelated MIR labels. Only phi-source blocks require this restriction: phi lowering emits copies per predecessor block, so conditional phi edges must remain distinct. Non-phi edges carry no phi copy and can safely bypass directly. This restores prior CFG shape while preserving branch order, dominance, refcount behavior, and the scalar-only/effect-free tail-merge restrictions. Full authoritative verification remains deferred.

## Implementation

- Bypass empty blocks reached conditionally when they are not phi sources.
- Retain phi-source edge blocks unless all predecessors jump unconditionally.
- Added a focused conditional non-phi cleanup regression test.
- Updated optimization documentation with the repaired rule and retained size measurement.

### Algorithm

1. Identify empty non-entry jump blocks.
2. Inspect whether the jump block is named by any phi in its target.
3. If it is not a phi source, bypass it regardless of predecessor terminator.
4. If it is a phi source, bypass only when all predecessors unconditionally jump to it and none is already a target phi source.
5. Rewrite control-flow targets and phi source labels only for approved bypasses.
6. Keep tail-merge sibling edge blocks as distinct phi predecessors.

### Example

Before repair, `branch c ? bridge : alternate; bridge -> result` retained `bridge` merely because its predecessor was conditional, causing loop exits to remain as `L0` and then be merged into `L0`. After repair, because `bridge` is not a phi source, the branch becomes `branch c ? result : alternate`. In contrast, scalar tail merging keeps `thenEdge -> shared` and `elseEdge -> shared` when `shared` has `Phi([(x, thenEdge), (y, elseEdge)])`, preserving separate phi-copy locations.
