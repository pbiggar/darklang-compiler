# Design brief

## Problem

At compiler b2e1f3d1e4ce0338d4c4662db9a1326f2e2cb899 versus interpreter 04fbe9dcc995c6188757d583e273cbd30a3e2d3d, operator grammar and application behavior diverge in accepted tokens, grouping, sections, partial evaluation, pipelines, arity errors, and failure timing; legacy aliases and adapted programs obscure these gaps.

## Goals

- Use the interpreter’s public expression behavior as the parity baseline across every operator and pipeline position.
- Preserve argument order, evaluation order, partial-application capture, arity, and failure behavior where compatible with ahead-of-time type checking.
- Remove legacy compiler-only syntax and aliases while explicitly documenting unavoidable ahead-of-time divergences.
- Keep comparison value semantics outside this boundary.

## Proposed solution

Adopt one interpreter-aligned expression grammar and application model covering prefix, infix, parenthesized, sectioned, partially applied, and pipeline forms. Represent true operator sections and structured pipeline stages until a single canonical lowering step, with piped values inserted as the first argument and supplied partial arguments evaluated and captured once in interpreter order. Align tokens, precedence, associativity, and primitive invocation; remove conflicting legacy operators, aliases, precedence layers, and ad hoc pipeline rewrites while migrating affected expressions. Treat earlier reports only as leads and retain findings only when revalidated at the pinned revisions.

## Success criteria

- The same source groups identically and produces equivalent values, argument order, evaluation order, and observable failures on both implementations.
- Parenthesized operators are ordinary two-argument values, partial applications capture supplied values once, and pipelines consistently supply their left side first.
- Legacy-only operator spellings and aliases are absent, and affected expressions use the current interpreter surface.
- All remaining compiler-only behavior is explicitly classified, with ahead-of-time rejection timing distinguished from semantic incompatibility.
- Parity evidence records the exact pinned revisions and uses unchanged focused interpreter examples where practical.
