# Design brief

## Problem

The compiler exposes host utilities absent from the interpreter baseline, but their intended public status is undocumented.

## Goals

- Classify the complete scoped surface against compiler 51093e0a8e31fe45a9aa79a317fbefd6b74fbcc3 and interpreter 04fbe9dcc995c6188757d583e273cbd30a3e2d3d.
- Distinguish supported compiler extensions from private infrastructure and intentional divergence.

## Proposed solution

Retain typed filesystem operations, path and temporary-directory utilities, platform predicates, integer randomness, and domain-scoped percent-encoding aliases as explicit compiler-only extensions. Move the raw pointer-backed file-output capability behind a private compiler/runtime boundary. Maintain one revision-keyed evidence record using current source and focused same-source probes, treating DCB1 8a402797 only as historical input and excluding similarly purposed APIs in other modules from parity claims.

## Success criteria

- Every scoped capability has one explicit public-extension or private classification.
- Each comparison records both exact revisions and current source or probe evidence.
- Retained extensions preserve observable compiler behavior and are documented as divergences from the interpreter baseline.
- The low-level memory-backed capability is no longer source-visible.
- Performance-only differences and unrelated aliases do not affect classification.
