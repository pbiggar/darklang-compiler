Current-main inventory confirms the approved premise is still live; no files were changed.

- The repository has **139 Markdown/documentation-like files** totaling about **23,914 lines**, with no discoverable documentation index from the root README.
- The `.dcb2` corpus has grown to **1,722 Markdown event records**. Its three path-derivable identity fields (`event-id`, `entity-id`, `entity-kind`) account for **5,166 redundant front-matter entries**.
- `docs/investigations/` still contains **23 completed or historical investigation files**. The largest are benchmark journals rather than current operational guidance.

Most actionable documentation problems:

1. **Historical benchmark material is disproportionately large and operationally coupled.** `benchmarks/HISTORY.md` is **4,028 lines**, while `benchmarks/README.md`, `docs/verification.md`, `history_updater.py`, and the runner explicitly require it. `CURRENT-STATUS.md` also repeats inventory/status information and points into dated investigations. The snapshot under `benchmarks/baselines/`, generated `RESULTS.md`, and audited `BASELINES.md` are the stronger candidates for retained current data.

2. **Root-level work journals should not remain current docs.** `memory-refcounting-remaining.md` is **1,978 lines** and `interpreter-compiler-modules.md` is **966 lines**. Feature docs link to the memory journal, while the module journal is only consumed by one playbook. These are implementation tracking artifacts, not durable reference material.

3. **Investigations and playbooks form a self-reinforcing historical workflow.** The 23 investigation files are referenced by optimization and benchmark playbooks plus several agent definitions. `rejected-experiments.md` is a cross-reference ledger for already rejected work. Removing the journals requires updating these references together; otherwise the retained agent instructions become broken or misleading.

4. **Status/performance claims are stale and contradictory.** Current documents still quote **2.25x**, **2.75x**, **2.73x**, and **2.38x** benchmark ratios, while `RESULTS.md` is the only intended current presentation. These occur in parity ledgers and `classic-optimizations.md`; fixed historical measurements should be removed or explicitly labeled historical.

5. **Cache and resolved-bug documentation is duplicated.** `architecture.md`, `removed-optimizations.md`, `compiler-cache.md`, and `compiler-cache-placement-analysis.md` all discuss removal of the compile cache. `known-bugs.md` points at the resolved register-allocation investigation. Keep a concise current statement where architecture needs one; delete the completed analyses.

6. **Developer workflow is repeated across README, AGENTS, playbooks, and agent support files.** There are **36 Markdown files** under `agents/` and `playbooks/`, in addition to the broad reference table in `AGENTS.md`. The active JSON agent configurations are distinct operational data, but the surrounding prose restates test-first, verification, benchmark, and documentation-update rules. A canonical contributor guide plus a narrowly scoped AI-agent guide would remove the duplication.

7. **Language support and compatibility are split without a clear owner.** `current-language-features.md` inventories support while `darklang-differences.md` includes overlapping syntax/support descriptions and validation instructions. Retain one current support/compatibility reference and make any validation-specific document point to it.

Recommended retained tables:

- Keep generated/comparable benchmark tables in `RESULTS.md` and `BASELINES.md`; their producers are benchmark scripts and snapshots.
- Keep concise feature/compatibility matrices only where they are maintained from tests or validation rules.
- Remove manually maintained status inventories, historical run tables, and implementation journals unless they have a demonstrated current consumer.

The approved implementation plan remains appropriately scoped: establish the index and ownership map first, then consolidate operational guidance, replace stale current-state claims, retire historical journals, simplify benchmark recording, and compact `.dcb2` to substantive provenance with only non-path-derivable metadata.
