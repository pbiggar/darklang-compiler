# Design brief

## Problem

Documentation remains fragmented and repetitive. The human-facing set spans onboarding, architecture, features, operations, benchmarks, investigations, and agent guidance without a complete index or consistent source of truth. The machine-managed corpus is an event log of 781 records for 151 entities; some records have empty bodies, and several universal fields duplicate path identity, so its storage and schema need value-based justification.

## Goals

- Create a discoverable, canonical human documentation set
- Remove stale, duplicated, overly detailed, and low-value historical material
- Retain machine-managed records and fields only when they serve a demonstrated operational, recovery, or audit need
- Use tables only where they remain the clearest maintainable representation

## Proposed solution

Create a central documentation index and consolidate overlapping current guidance by audience and subject. Reconcile status claims with current behavior, trim implementation journals and exhaustive inventories, and delete completed investigation narratives and old benchmark history by default rather than preserving them as archives. Treat machine-managed material as data: evaluate every event category and field against actual consumers, retain the minimum needed to reconstruct current state and satisfy demonstrated provenance requirements, and compact or remove redundant history and metadata. Retain tables when they provide concise, unique comparisons with a clear update source; otherwise replace or remove them.

## Success criteria

- Current guidance is reachable from one index and each subject has one canonical source
- No active documentation contains contradictory or expired status claims
- Completed investigations and superseded benchmark history no longer burden the working documentation set
- Every retained machine-managed event category and field has a documented consumer or concrete retention rationale
- Redundant machine records and metadata are removed or explicitly justified
- Retained tables convey unique current information and have a clear maintenance source

## Open questions

- Which recovery, audit, synchronization, or external-tool scenarios require complete machine event history rather than current state plus version control?

## Delivery shape

single issue

## Response to feedback

The revision should not assume machine-managed records are valuable merely because they are generated: both records and individual fields must justify their utility. Low-value investigation and benchmark history can be deleted, while tables should be judged by whether they communicate maintained information effectively.

## What changed

- Added a utility audit and minimum-retention standard for machine-managed records and individual fields
- Changed historical material from archive-by-default to deletion-by-default when it lacks a current use
- Made removal of old benchmark history an explicit part of the proposed consolidation
- Replaced the unresolved generated-versus-manual table question with a practical value and maintainability rule
- Added success criteria requiring concrete justification for retained machine data and tables

## Why

These changes turn retention into an evidence-based decision, directly address the observed redundancy in the event store, and remove known low-value history instead of merely reorganizing it. The table rule preserves useful compact comparisons without committing to a format before its information value is established.
