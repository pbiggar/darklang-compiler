# Implementation plan

The JSON parity matrix has 31 independently compiled cases; the E2E runner executes cases sequentially while reusing only stdlib/preamble LIR. Each compile still regenerates typed JSON decoder functions and ARM64 code for the combined reachable stdlib, preamble, and user LIR. Existing timing JSON already reports per-test and per-pass totals; the accepted 809.7-second JSON baseline identifies Code Generation as the principal reusable cost.

## Work item 01a02f93952c74278abb4de3ccd09a32

Title: Add session-scoped JSON planning and ARM64 function-codegen reuse to repeated E2E compilation

Category: behavior

Evidence: CompilerLibrary.compileUserWithPlan invokes JsonPlanning.rewriteProgram per request, lowers generated functions with the entry function, then calls CodeGen.generateARM64WithOptions over all reachable stdlib/preamble/user functions. StdlibResult and PreambleContext already retain allocated LIR, but generateBinary re-codegens it per executable. JsonPlanning currently builds a fresh FunctionDef map from each typed AST; TestRunner's per-case loop calls runE2ETestWithPreambleContext sequentially. json-parity.e2e contains 31 typed JSON cases, including repeated Int64, Float, record, choice, and nested decoder graphs.

Outcome:

Introduce an explicit bounded CompilationSession passed through CompileRequest/compile and owned for each E2E suite run. It keys reusable ARM64 symbolic function output by allocated LIR function identity plus target and codegen-affecting options, while retaining program-level helper/layout generation and independently emitting each executable. Extend JsonPlanning to resolve decoder artifacts by resolved structural type and declaration-context fingerprint before ANF lowering, returning required generated functions and compiler metadata for cache misses and reuse. Preserve existing JSON source cases and executable isolation; segregate or bypass artifacts for coverage and incompatible target/codegen options; release registries on session disposal. Add focused compiler-level cache-contract tests for decoder hit/miss, nested/shared decoder reuse, declaration-context isolation, target/options/coverage incompatibility, session isolation/disposal, and unchanged JSON corpus stdout/stderr/exit/compile-error behavior. Validate with the full suite and timing JSON, comparing JSON compile and Code Generation totals against the 809.7-second baseline.
