# Design brief

## Problem

Typed JSON E2E cases repeatedly regenerate and compile identical decoder graphs, while immutable stdlib, preamble, and decoder LIR functions are code-generated again for every executable.

## Goals

- Keep every existing test source and per-case executable unchanged.
- Eliminate repeated ARM64 code generation for structurally identical reusable functions.
- Reuse typed JSON decoder artifacts before ANF lowering when their type and declaration context match.
- Preserve compiler output, JSON semantics, error paths, coverage behavior, and process isolation.
- Keep reuse session-scoped, in-memory, explicit, and bounded.

## Proposed solution

Introduce an explicit CompilationSession carried by repeated compiler invocations. It contains: (1) a function-codegen cache mapping reusable allocated LIR functions plus target/options to symbolic ARM64 instructions; and (2) a JSON-plan artifact registry mapping a resolved type plus context fingerprint to precompiled symbolic LIR decoder functions and their required compiler-context metadata. JsonPlanning resolves calls to registered artifacts when available and only generates/lower/allocates missing decoder graphs. The compiler still builds each entry function and emits/encodes each final executable independently.

## Success criteria

- The unchanged JSON corpus passes with identical stdout, stderr, exit-code, and compile-error behavior.
- Repeated `Json.parse<Float>`, integer, and shared nested decoder cases reuse prior decoder artifacts within one compilation session.
- Timing JSON shows a substantial reduction in Code Generation and JSON compile time from the 809.7-second baseline.
- Coverage-enabled builds and differing target/codegen options do not reuse incompatible artifacts.
- Session disposal releases all cached artifacts; separate compiler sessions share nothing implicitly.

## Conversation response

Adopt both compiler-level reuse layers while leaving test sources and one-case-per-executable behavior unchanged.

First, add a bounded compilation-session cache of generated ARM64 instructions for reusable non-entry LIR functions. Second, promote typed JSON decoder plans into reusable symbolic-LIR artifacts within the same compilation context, so repeated concrete JSON types skip planning, ANF, MIR, register allocation, and code generation. Encoding and final binary assembly remain per executable.

The session is explicit and in-memory only: no global state, persistence, SQLite, parallelism, or test batching. It ends with the suite/compiler session, ensuring safe invalidation and bounded lifetime.

The cache keys must include target and codegen-affecting options. Reusable JSON-plan artifacts must additionally be keyed by the fully resolved concrete type and the relevant declaration/specialization context, so user records, sums, aliases, and error paths remain exact. Coverage builds bypass reuse where instrumentation affects generated code.

This preserves the existing static, type-directed JSON model and native E2E coverage while removing the redundant compiler work responsible for the JSON regression.
