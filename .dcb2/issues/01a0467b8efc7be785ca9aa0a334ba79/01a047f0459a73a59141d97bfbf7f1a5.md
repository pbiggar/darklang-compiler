## Problems

## Solution

The candidate keys reusable calls by exact callee, ordered operands, and scalar return type, using existing whole-program effect-free facts and clearing availability at barriers. The focused repository-native workload produced identical executable output, but changed MIR and generated bytes; the verifier therefore reported correctness-mismatch, and the timing reduction was not a clear win. Residual risk remains broader validation, owned by DCB.

## Implementation

- No files changed; the pinned candidate remains preserved.
- Measured its existing exact-callee, scalar direct-call CSE implementation against the pinned baseline.

### Algorithm

1. Identify effect-free direct scalar calls.
2. Key by callee identity, operands, and return type.
3. Replace an available exact match with a typed move.
4. Export only safe availability through dominating blocks.
5. Clear call availability at calls, allocation/memory/runtime operations, and ownership barriers.

### Example

Candidate MIR can replace a second `Call(pure, [v]) : Int64` with `Mov(firstResult)`, preserving the first call’s evaluation point; on merkletrees this changes normalized MIR and binary bytes but preserves the 10-byte program output.
