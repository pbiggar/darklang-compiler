# Update only SSA phi prefixes

Reduce SSA construction time by avoiding full successor-block reconstruction when filling phi sources.

## Constraints

- Limit changes to SSA successor phi-source updates and retain one prefix-update implementation.
- Trial alternatives in an isolated worktree; profile visited phi and non-phi instructions first and discard neutral, noisy, regressive, or invalid results.
- Collect 10 paired, alternating before/after -vv runs for every routine program; report raw SSA Construction and total-compilation results, medians, and absolute and percentage deltas.
- Compare 10 paired before/after ./run-tests --ai wall-clock runs with raw results, medians, and deltas.
- Require identical SSA MIR, optimized MIR, binaries, benchmark outputs, and instruction counts; pass ./run-tests --ai and ./benchmarks/run_benchmarks.sh --verify routine and report the RESULTS.md performance ratio.
- Remove all exploratory profiling and instrumentation from retained code.

## Trial work

### Trial item 019ffbbd0a377aedb34666064f6fec48

Title: Measure successor-tail rebuilding

Category: SSA profiling

Evidence: Current fasta SSA Construction is 13.1 ms with 54 dumped MIR functions and 22 surviving phi nodes; updatePhiSourcesForSuccessors currently List.maps every successor instruction for each incoming edge although only phi instructions can change.

Outcome:

Count and time non-phi instructions traversed and reallocated by phi-source updates across predecessor edges.

### Trial item 019ffbbd0a377153a0700904e162458e

Title: Rewrite the leading phi prefix

Category: SSA renaming

Evidence: SSA insertion places phi nodes at block starts, making a prefix-only functional traversal sufficient while preserving phi order, sources, diagnostics, and exact MIR.

Outcome:

Transform only consecutive leading Phi instructions and reuse the untouched instruction-list tail.
