# Trial result

Leading-phi-only successor updates eliminate deterministic reconstruction of unchanged successor tails. Canonical routine benchmark: equal.

## Evidence

## What changed

Committed a prefix-only SSA phi-source updater and added src/Tests/e2e/ssa_phi_prefix.e2e loop-carried-value coverage.

## How it works

The prior List.map visited and rebuilt every successor instruction per predecessor edge although phi insertion guarantees phis are a leading prefix. The retained recursive updater preserves phi/source order and returns the first non-phi tail unchanged; it was chosen because it reduces per-edge work from O(block instructions) to O(leading phis) with identical generated output. Residual risk is limited to the established phi-prefix invariant.

## Algorithm

For each successor: inspect instructions from the front; rename sources for each consecutive Phi; stop at the first non-Phi and reuse that exact tail; replace only the updated prefix.
