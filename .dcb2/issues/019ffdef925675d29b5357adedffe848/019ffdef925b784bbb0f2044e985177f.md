# Lay out CFG blocks for fallthrough

Remove avoidable unconditional branches and improve deterministic hot-path layout.

## Constraints

- Use deterministic static CFG heuristics without profile data; preserve entry placement, labels, coverage behavior, and backend branch-range correctness.
- Add failing LIR and ARM64/x64 generated-code tests first; run full tests and routine benchmarks.
- Retain layout rules only when dynamic instruction counts or code size improve without routine regressions; update the backlog and remove temporary inputs.

## Trial work

### Trial item 019ffdef92567ab5ab18c74cc69f32d4

Title: Order blocks by successor chains

Category: basic-block placement

Evidence: Both backends emit entry first and then Map label order, which is unrelated to CFG fallthrough.

Outcome:

Place a preferred successor immediately after each eligible block while keeping every block exactly once.

### Trial item 019ffdef925679969f8cc55642c3ac40

Title: Omit fallthrough branches

Category: branch elimination

Evidence: ARM64 and x64 code generation currently emit a conditional branch followed by an unconditional false-edge jump for every conditional terminator and always branch for Jump and Ret.

Outcome:

Emit only the necessary conditional edge and suppress jumps to the next block or immediately following epilogue.
