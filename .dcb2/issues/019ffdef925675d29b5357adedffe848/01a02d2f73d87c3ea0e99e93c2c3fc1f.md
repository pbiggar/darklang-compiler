## What changed

## How it works

Authoritative failures shared one cause: layout was acting as a partial CFG validator before backend translation, masking established missing-entry and x64 comparison-context diagnostics. Changing malformed fixtures or expected errors was rejected because it would weaken existing contracts. The retained repair treats layout solely as deterministic ordering: absent successor blocks terminate a layout chain and remain for backend consumers to diagnose. Valid CFG behavior and branch-range resolution are unchanged. Each block is visited once with Map/Set operations, giving O(B log B) time and O(B) space. Residual risk is limited to repository-wide interactions because the full suite and routine profile were intentionally left to worker-owned exact-commit verification.

## Algorithm

1. Require the declared entry block and report the established missing-entry diagnostic if absent. 2. Begin at entry and follow each terminator's preferred fallthrough successor: direct-jump target or conditional false edge. 3. Follow a successor only when it exists and has not already been placed; otherwise end the chain without preempting consumer validation. 4. Start remaining chains in deterministic label order until every supplied block appears exactly once. 5. Pass each block and its lexical successor to ARM64/x64 lowering. 6. Omit unconditional jumps when that successor is already next, and let the final return fall through to the adjacent epilogue.
