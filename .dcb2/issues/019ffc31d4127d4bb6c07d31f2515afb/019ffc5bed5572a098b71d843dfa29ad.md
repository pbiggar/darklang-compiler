# Design brief

## Problem

At compiler HEAD 51093e0a8e31fe45a9aa79a317fbefd6b74fbcc3 versus interpreter revision 04fbe9dcc995c6188757d583e273cbd30a3e2d3d, compiled text behavior does not consistently match the interpreter’s EGC, NFC, Unicode casing, utility, and regex contracts.

## Goals

- Treat the current interpreter’s public behavior as the parity baseline and record both exact revisions for every comparison.
- Replace conflicting compiler text semantics rather than preserve incompatible behavior, while explicitly classifying non-conflicting compiler extensions and intentional divergences.
- Provide complete Unicode and regex implementations in Dark, using the latest Unicode release through versioned data that can be updated as Unicode evolves.
- Cover the required text, character, codec, digest, randomness, escaping, binary-conversion, and formatting capabilities consistently on both native targets.

## Proposed solution

Establish a shared text semantics layer written in Dark that owns versioned Unicode data, EGC segmentation, NFC normalization, casing, character properties, and regex behavior. Route compiled public text operations through this layer so their observable boundaries, results, captures, replacements, splitting, and no-match behavior follow the interpreter. Use narrowly scoped platform primitives only where external entropy or system integration is inherently required, and maintain revision-pinned parity evidence separating required parity, compatible compiler extensions, and deliberate divergences.

## Success criteria

- Canonically equivalent text produces interpreter-equivalent observable results across compiled text operations.
- The focused decomposed grapheme has EGC length 1 instead of UTF-8 byte length 3.
- Unicode segmentation, normalization, casing, classification, comparison, searching, and construction match the pinned interpreter behavior.
- Regex matching, captures, replacement, splitting, and no-match results match the pinned interpreter behavior.
- Existing incompatible compiler text behavior is replaced; retained extensions and any intentional divergences are explicitly identified.
- Every parity claim records compiler HEAD 51093e0a8e31fe45a9aa79a317fbefd6b74fbcc3, interpreter revision 04fbe9dcc995c6188757d583e273cbd30a3e2d3d, and current source or focused behavioral evidence.
- Unicode data can advance to later releases without redesigning the public text model.

## Open questions

- Should the active Unicode version be publicly observable, or only recorded in generated data and parity evidence?
- Are any remaining differences intentional public divergences after the complete behavior inventory is revalidated?
