# Design brief

## Problem

Revalidation at compiler C@cab8abc418549c7f9232dd51ab87ea59ac605f88 against interpreter I@04fbe9dcc995c6188757d583e273cbd30a3e2d3d confirms incompatible byte-oriented text semantics, incomplete Unicode behavior, missing text utilities, and no compiled regex surface; the focused decomposed EGC still reports length 3 instead of 1.

## Goals

- Match the interpreter’s public EGC, NFC, Unicode casing, character, string, and regex behavior on both native targets.
- Replace conflicting compiler behavior while retaining only the specified compatible extensions behind an explicit documented boundary.
- Provide complete Dark implementations using fully reified, regenerable data from the latest released Unicode standard, with revision-pinned parity evidence.

## Proposed solution

Create one shared text semantics layer in Dark that owns Unicode normalization, segmentation, casing, properties, character validity, and interpreter-compatible regex behavior. Generate and embed versioned Unicode data without runtime dependencies on installed data files, route canonical character and string operations through this layer, and reuse portable interpreter definitions where possible. Limit native primitives to inherently platform-dependent entropy, digest, codec, Blob, and system boundaries. Replace incompatible byte-oriented public behavior rather than preserving it, while isolating and documenting compiler-only extensions and any intentional divergences.

## Success criteria

- Same-source comparisons produce interpreter-equivalent values and observable failures across the complete scoped surface, including capture-sensitive regex and no-match behavior.
- The decomposed-EGC probe reports length 1, and slicing, traversal, searching, casing, padding, splitting, trimming, and reversal preserve EGC boundaries and NFC behavior.
- Character values consistently represent exactly one EGC, including Unicode casing, predicates, comparisons, scalar conversion, and string conversion.
- Both native targets use the same embedded Unicode and regex semantics without installed Unicode files, and Unicode data can be regenerated for later releases without redesigning the public model.
- Every parity claim records the exact compiler and interpreter revisions and classifies retained extensions and intentional divergences explicitly.
