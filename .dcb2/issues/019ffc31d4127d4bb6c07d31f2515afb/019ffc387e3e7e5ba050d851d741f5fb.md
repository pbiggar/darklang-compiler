# Design brief

## Problem

At compiler revision 51093e0a8e31fe45a9aa79a317fbefd6b74fbcc3, compiled text behavior diverges from interpreter revision 04fbe9dcc995c6188757d583e273cbd30a3e2d3d in Unicode grapheme handling, normalization, casing, text utilities, and regular-expression semantics.

## Goals

- Make the interpreter’s current public EGC, NFC, Unicode casing, capture, and no-match behavior the compiled baseline.
- Provide the missing text, character, regex, codec, digest, randomness, escaping, binary-conversion, and formatting capabilities.
- Retain compiler-only operations as explicit extensions and document any intentional divergence.
- Maintain revision-pinned parity evidence, revalidated from current sources rather than inherited from report commit 8a402797.

## Proposed solution

Establish one native, cross-platform text semantics layer for Unicode segmentation, NFC normalization, casing, character properties, codecs, hashing, entropy, and regular expressions. Route compiled character and string behavior through that layer so indexing, slicing, traversal, transformation, searching, comparison, and construction consistently operate on extended grapheme clusters where the interpreter does. Add a compatibility adapter for interpreter-equivalent regex captures, replacements, splitting, and no-match results. Maintain a revision-pinned behavior inventory that distinguishes parity requirements, retained compiler extensions, and deliberate divergences.

## Success criteria

- Canonically equivalent text has interpreter-equivalent observable behavior across compiled text operations.
- The focused decomposed grapheme reports length 1 rather than UTF-8 byte length 3.
- Unicode casing, character classification, text boundaries, normalization, regex captures, and no-match results agree with the pinned interpreter revision.
- The requested public capabilities are available on both supported native targets, while compiler extensions remain usable and explicitly classified.
- Every parity claim records both exact revisions and current source or focused behavioral evidence.

## Open questions

- Which Unicode data version and native regex compatibility strategy should be frozen to reproduce the interpreter baseline consistently across both targets?
- Which remaining differences, if any, are intentional public divergences rather than parity defects?
