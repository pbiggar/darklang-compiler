# Design brief

## Problem

At compiler HEAD 4ab9c8d89ebd1b17344d15de5174d02fe5f4a583, Stream remains absent; darklang/dark HEAD 04fbe9dcc995c6188757d583e273cbd30a3e2d3d defines the current parity baseline.

## Goals

- Provide the complete requested lazy stream surface.
- Guarantee deterministic single-consumer lifecycle and resource cleanup.
- Preserve portable semantics while isolating native state and disposal.

## Proposed solution

Introduce an opaque typed stream backed by shared native lifecycle state and resource ownership. Implement portable construction, transformation, and collection behavior in Dark where practical, while keeping advancement, closure, ownership enforcement, and exactly-once disposal native. Match interpreter laziness, ordering, callback-error propagation, sticky exhaustion, and idempotent closure; explicitly classify deterministic competing-consumer rejection and immediate failure cleanup as intentional strengthenings where the interpreter is unenforced or GC-dependent.

## Success criteria

- Same-source programs match the pinned interpreter’s observable values, ordering, laziness, and errors.
- Every stream follows one deterministic progression and remains exhausted after completion or closure.
- Each owned resource is disposed exactly once on every terminal path.
- All compiler extensions and intentional divergences are documented separately from parity claims.
