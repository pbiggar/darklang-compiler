# Outline cold ARM64 file lowering

Reduce fixed ARM64 Code Generation latency by avoiding JIT compilation of unused file-operation lowering bodies.

## Constraints

- Limit scope to ARM64 pass 6 `convertInstr`; retain only one cold-path extraction for the `FileReadText` through `FileWriteFromPtr` cases, leaving all other lowering, helper discovery, and peephole behavior unchanged.
- Temporarily profile JIT cost and file-case frequency; retain the extraction only if it materially reduces the current fasta Code Generation bottleneck and remove all profiling and instrumentation afterward.
- Collect 10 comparable before and after fasta `-vv` runs with raw Code Generation and total-compilation timings, medians, absolute deltas, and percentage deltas.
- Because routine benchmark timings drove selection, report before/after Code Generation and total-compilation deltas for every routine benchmark program.
- Collect 10 comparable before and after wall-clock runs of `./run-tests --ai` with raw results, medians, and deltas.
- Require identical symbolic ARM64 streams and binaries, passing file-operation coverage and `./run-tests --ai`, and a passing `./benchmarks/run_benchmarks.sh --verify routine` with every instruction count and the `RESULTS.md` performance ratio reported; discard neutral, noisy, or regressive results.
