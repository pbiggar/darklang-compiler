# Thread and duplicate pure conditional CFG paths

Remove redundant conditional dispatches only where edge-sensitive CFG rewrites reduce generated control-flow instructions.

## Constraints

- Limit matching to typed scalar conditions and pure, phi-safe blocks.
- Preserve dominance, phi sources, reference-count operations, evaluation order, and reachable labels.
- Create failing focused MIR/LIR and generated-code tests before each transformation.
- Retain a transformation only for a repeatable focused or routine benchmark gain; run ./run-tests --ai and ./benchmarks/run_benchmarks.sh --verify routine, update docs/classic-optimizations.md, and remove temporary benchmark inputs.

## Trial work

### Trial item 01a042f520eb7485a39469a0bb7bed7c

Title: Trial edge-sensitive jump threading

Category: MIR CFG simplification

Evidence: Current simplifyBranchesKnownFromPredecessor requires the successor to have one predecessor, leaving classic edge-specific threading unavailable.

Outcome:

Thread a known true or false predecessor edge through a repeated successor condition even when that successor has other predecessors.

### Trial item 01a042f520eb7f2a8f7bad111fe459e1

Title: Trial bounded pure tail duplication

Category: MIR CFG simplification

Evidence: The optimizer merges linear blocks and tail-merges identical suffixes, but has no bounded tail-duplication counterpart for exposing existing CFG simplifications.

Outcome:

Duplicate a small pure conditional successor onto one predecessor when doing so exposes jump threading or removes a jump without increasing hot-path instruction count.
