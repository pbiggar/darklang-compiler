# Trial result

Outcome classification corrected: Measurement incomplete.

## Evidence

## What changed

Removed ARM64 convertFunction's blanket X0-X7 save-and-restore through X9-X15, leaving allocator-generated entry stack stores and cycle-safe parallel moves authoritative. Retained current CLI initialization, added generated-code regression coverage for identity, mixed integer/float, spills, swaps, and eight arguments, refreshed routine benchmark records, and updated docs/classic-optimizations.md.

## How it works

The backend duplicated parameter handling already performed by register allocation, adding instructions to every integer-parameter function and providing only seven temporaries for eight argument registers. Extending that secondary shuffle was considered but rejected because it would duplicate allocator policy and risk ordering divergence. The retained transformation is linear in the allocator-required transfers and removes blanket work. Residual risk is limited to the allocator-entry ordering invariant, covered by generated-code cases, the full suite, output validation, and deterministic benchmark replay.

## Algorithm

1. Let register allocation emit parameter spill stores before register transfers. 2. Use its parallel integer shuffle, including X16 for cycles and swaps. 3. Keep floating-point transfers in their separate register bank. 4. Emit CLI initialization, prologue, heap initialization, and then the allocated CFG directly. 5. Do not synthesize any additional argument-register preservation or restoration in ARM64 code generation.
