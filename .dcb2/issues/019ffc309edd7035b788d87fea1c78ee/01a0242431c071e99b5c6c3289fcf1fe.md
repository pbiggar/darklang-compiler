Correction to the prior scope: `normalizeNullaryCallArgs` is not, by itself, evidence that ordinary `f()` declarations violate Unit-pattern semantics. The compiler parser already synthesizes a Unit parameter for empty declaration groups (`1_Parser.fs:1170-1277`), matching the interpreter’s `()` parameter model. The normalization helper only affects callable signatures represented with zero parameters, so it should be audited and removed only where it is a legacy compatibility path—not treated as the primary Unit-pattern gap.

The confirmed implementation gap remains deferred partial application: typed partial applications embed original argument expressions in generated lambdas, whereas the pinned interpreter stores evaluated `argsSoFar` in `DApplicable`.
