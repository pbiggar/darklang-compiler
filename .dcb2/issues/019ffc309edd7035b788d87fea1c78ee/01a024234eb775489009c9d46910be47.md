One terminology point is now pinned: interpreter-native lambdas are never syntactically parameterless. `fun -> …` is rejected by LibParser (`Parser.fs:2053-2061`); `fun () -> …` is a one-pattern lambda whose pattern is Unit. Function declarations likewise parse `()` as a function parameter (`Parser.fs:2603-2661`). The scope should therefore describe this consistently as **Unit-pattern application**, not a runtime zero-arity exception.

That strengthens the existing plan: remove compiler `normalizeNullaryCallArgs` compatibility rather than introduce a separate nullary function-value mode. The applicable-value arity is the canonical pattern count, including Unit. Existing compiler normalization at `1.5_TypeChecking.fs:35-38` remains a confirmed gap because it silently turns a supplied Unit value into no argument.
