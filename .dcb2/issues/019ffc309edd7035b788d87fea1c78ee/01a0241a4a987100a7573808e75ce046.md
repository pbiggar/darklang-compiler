# Implementation plan

Current HEAD 2730b264c012aed4bbd7b1c90d38bbec9d577594 still exposes competing compiler and interpreter syntax routes; the accepted function-parity change remains a single contained compiler pipeline delivery.

## Work item 01a0241a4a987a15abe17988ea7b8bf2

Title: Unify canonical function values, application, and closure semantics

Category: function

Evidence: Public CLI defaults to CompilerSyntax and permits both parser routes in Program.fs:93, 125-198 and CompilerLibrary.fs:45-47, 1154-1158, 1670-1686. Compiler-specific Parser.fs owns declaration/lambda parsing and synthesizes Unit parameters at 1170-1277 and 2155-2172; InterpreterParser.fs is a separate implementation. TypeChecking.fs normalizes nullary calls and implements partial application by creating a lambda containing original argument expressions at 3350-3384 and 5525-5603, so supplied arguments are not represented as retained evaluated values. AST_to_ANF.fs retains LambdaEnv call reinterpretation at 1983-2170 and lowers closures separately through ClosureAlloc/ClosureCall paths around 5165-5204 and 5620-5672. Existing functions.e2e and closures.e2e cover ordinary calls, captures, nested lambdas, shadowing, and limited named partial applications (closures.e2e:311-345), but do not establish the full accepted arity/order/returned-closure parity matrix. Historical comparison revisions are compiler b2e1f3d1e4ce0338d4c4662db9a1326f2e2cb899 and interpreter 04fbe9dcc995c6188757d583e273cbd30a3e2d3d; each retained probe records both revisions.

Outcome:

Make interpreter-native parsing and canonical declarations/lambdas the sole public source route; lower canonical parameter patterns, annotations, grouped/multiple parameters, and zero-parameter Unit functions into one typed representation. Replace type-checker-generated lambda partial applications and ANF lambda-inlining fallbacks with an applicable function-value model carrying code identity, lexical captures, and already-evaluated supplied arguments. Define exact invocation, under-application, and over-application consistently through type checking, ANF, closure allocation/calling, and both backends; preserve AOT rejection for statically provable type or arity failures. Evaluate supplied arguments left-to-right before the callee and retain each exactly once across partial application. Migrate compiler-owned Dark sources and calls, remove the compiler parser route, syntax switch, automatic nullary-call normalization, and legacy call compatibility paths. Add focused same-source parity coverage for Unit/nullary and multi-parameter declarations, parameter patterns and annotations, direct and higher-order calls, nested/returned/shadow-capturing closures, partial applications with observable argument order, and observable over-application failures.
