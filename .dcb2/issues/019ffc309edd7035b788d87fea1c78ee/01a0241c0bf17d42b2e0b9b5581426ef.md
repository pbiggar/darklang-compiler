## Work item 01a0241c0bf17c22b2349cf284dce3ea

Title: Make the interpreter-native parser the only public function syntax boundary

Category: behavior

Evidence: CompilerLibrary.fs:45-47, 1154-1158, 1670-1686 selects Parser versus InterpreterParser; Program.fs:93 defaults to CompilerSyntax and Program.fs:125-198 exposes both modes. CompilerLibrary.fs:2288 separately parses a preamble through Parser. Parser.fs:1170-1277 and 2155-2172 independently parse declarations and lambdas, while InterpreterParser.fs provides the competing interpreter-compatible route.

Outcome:

Replace public CompilerSyntax/Parser selection with the interpreter-native parser and canonical representation; migrate compiler-owned Dark sources, preambles, and call sites; remove the CLI syntax modes, compiler parser route, and legacy declaration/lambda/call compatibility behavior. Preserve only internal parsing facilities that are required by generated compiler data and document any non-public extension.

## Work item 01a0241c0bf17037aa79e76d4687db4d

Title: Carry applicable function values through typing and lowering

Category: behavior

Evidence: TypeChecking.fs:35-38 and its uses at 3227, 3353, 3472, 3723, 3882, and 5540 erase a Unit argument for zero-arity calls. Its partial-application branches at 3357-3384 and 5542-5578 construct a lambda whose eventual body contains the supplied argument expressions. CompilerLibrary.fs:964-967 first applies LambdaEnv rewriting; AST_to_ANF.fs:2057-2183 reinterprets calls by lambda environment and AST_to_ANF.fs:5165-5204 and 5620-5672 separately allocates and invokes closures. Those representations do not encode retained evaluated partial arguments as a function value.

Outcome:

Use one typed applicable-value representation for named functions and lambdas containing code identity, lexical captures, parameter state, and evaluated supplied arguments. Lower canonical parameter patterns and annotations, including Unit-modeled nullary and grouped/multiple parameters, without synthetic call compatibility. Exact application invokes it; under-application returns an applicable value without re-evaluating supplied arguments; statically provable excess arity and type errors remain compile-time AOT failures, explicitly classified against the interpreter’s observable failure behavior.

## Work item 01a0241c0bf17ac0b2ba99e7c7899e09

Title: Establish revision-pinned function parity probes and regressions

Category: tests

Evidence: functions.e2e covers direct declarations and calls; closures.e2e covers captures, nesting, shadowing, and a limited partial-application set at 311-345. Neither corpus establishes the full required same-source matrix, particularly evaluated-partial-argument timing, returned closures, public-parser-only input, and excess-application failure behavior. The bounded parity inventory continues to identify TypeChecking.fs and AST_to_ANF.fs as primary current locations.

Outcome:

Record the exact compiler and interpreter revisions on every same-source comparison, copy applicable interpreter programs verbatim, and add focused E2E probes for parameter patterns and annotations, Unit/nullary and multiple parameters, higher-order application, nested and returned closures, shadowed captures, under-application, over-application, and left-to-right argument-before-callee order. Classify each remaining difference as required AOT static rejection, intentional compiler extension, or defect; do not retain runtime-only interpreter decisions merely for parity.
