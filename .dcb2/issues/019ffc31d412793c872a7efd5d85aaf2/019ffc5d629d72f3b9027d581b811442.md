# Design brief

## Problem

Compiled CLI programs lack the interpreter’s canonical environment, filesystem, POSIX, shell, and daemon behavior.

## Goals

- Use current interpreter behavior and error handling as the compatibility contract.
- Provide the complete CLI system surface on macOS and Linux for arm64 and x64.
- Record exact compiler and interpreter revisions for every comparison.
- Classify compiler-only extensions and intentional divergences explicitly.

## Proposed solution

Define a revision-pinned behavioral contract from the interpreter, provide the required native operating-system capabilities, and reuse shared high-level workflows so compiled programs match interpreter results, errors, side effects, and resource lifecycles across supported platforms.

## Success criteria

- The requested CLI surface compiles and behaves equivalently to the interpreter on macOS and Linux, on arm64 and x64.
- Successful operations, state changes, error values, and lifecycle behavior match in revision-recorded same-source comparisons.
- Any remaining mismatch is explicitly documented as a compiler-only extension, intentional divergence, or unsupported host capability.
