# Design brief

## Problem

At compiler cab8abc418549c7f9232dd51ab87ea59ac605f88 versus current darklang/dark 04fbe9dcc995c6188757d583e273cbd30a3e2d3d, compiled programs lack the interpreter’s CLI execution, process lifecycle, host/system discovery, and terminal-key surface. Revalidation of DCB1 8a402797 confirms representative same-source calls still fail during name resolution.

## Goals

- Match interpreter-observable command and process behavior, including streams, environment, working directory, pipelines, timeouts, signals, errors, and exit results.
- Expose equivalent host/system information and decoded key, modifier, paste, repeat, and redirected-input behavior on supported targets.
- Reuse portable interpreter logic, isolate native effects, and explicitly document compiler-only extensions and intentional AOT or platform divergences.

## Proposed solution

Deliver one coherent runtime capability slice: copy the interpreter’s portable public values, validation, quoting, composition, polling, and result shaping; add native abstractions for process handles, direct and shell execution, pipes, concurrent standard-stream capture, environment and directory control, timeout cleanup, signals, host queries, and terminal decoding. Preserve the interpreter contract as the baseline while keeping existing compiler facilities separate rather than treating them as substitutes. Maintain revision-pinned evidence for retained differences and focused same-source comparisons.

## Success criteria

- The same supported programs produce matching output, errors, exit results, side effects, timeout behavior, signal outcomes, and lifecycle observations at the pinned revisions.
- Host and system queries return baseline-compatible values and failures on supported compiler targets.
- Interactive, pasted, repeated, modified, special-key, and redirected terminal input yields baseline-compatible public events.
- Every retained difference is source-backed and classified as parity behavior, a compiler-only extension, or an intentional divergence.

## Open questions

- Should standalone binaries reproduce interpreter capability-denial behavior, or document capability gating as an intentional host-model divergence?
- Should public Windows-shaped values be exposed immediately despite the compiler currently targeting macOS and Linux only?
