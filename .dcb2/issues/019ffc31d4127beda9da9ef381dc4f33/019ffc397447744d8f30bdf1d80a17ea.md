# Design brief

## Problem

At compiler HEAD 51093e0a8e31fe45a9aa79a317fbefd6b74fbcc3, compiled programs lack the execution, host/system discovery, process lifecycle, and terminal-key capabilities exposed by darklang/dark 04fbe9dcc995c6188757d583e273cbd30a3e2d3d.

## Goals

- Match the interpreter’s observable behavior for command execution, process control, host/system information, and key input on supported native targets.
- Provide typed outcomes, lifecycle state, signals, timeouts, environment handling, and terminal input without sentinels, exceptions, or mutable compiler state.
- Keep portable behavior shared while implementing operating-system primitives natively.
- Document compiler-only extensions and intentional platform divergences explicitly.

## Proposed solution

Introduce a cohesive CLI/runtime capability layer with typed public models for execution results, hosts, processes, and keyboard input. Preserve the interpreter’s portable semantics and conversions, while target-specific native primitives supply process creation, pipes, signals, system discovery, and terminal decoding. Normalize standard streams, environment and working-directory handling, timeout and termination behavior, and exit results at the shared boundary. Treat DCB1 report commit 8a402797 only as historical input; the locked comparison pair is compiler 51093e0a8e31fe45a9aa79a317fbefd6b74fbcc3 and interpreter 04fbe9dcc995c6188757d583e273cbd30a3e2d3d.

## Success criteria

- The same source observes interpreter-compatible values, output, errors, and exit outcomes across the supported macOS and Linux targets.
- Process creation, communication, pipelines, lifecycle inspection, waiting, timeouts, and graceful or forced termination have consistent documented behavior.
- Host and system queries return accurate typed information without guessed defaults.
- Interactive input reports portable keys and modifiers consistently, including defined behavior for unsupported or undecodable input.
- Every parity claim is tied to the locked revisions, and every extension or intentional divergence is explicitly classified.

## Open questions

- Should host variants unsupported by the compiler’s current macOS and Linux backends still be represented for source compatibility, or be documented as an intentional divergence?
