# Design brief

## Problem

At compiler 51093e0a8e31fe45a9aa79a317fbefd6b74fbcc3, native programs lack the execution, process, host/system, and terminal-input behavior publicly exposed by darklang/dark 04fbe9dcc995c6188757d583e273cbd30a3e2d3d.

## Goals

- Match the interpreter’s observable behavior on supported macOS and Linux targets.
- Provide typed execution outcomes, process lifecycle control, host/system discovery, and portable key input.
- Replace overlapping compiler-only facilities with equivalent interpreter-compatible behavior and explicitly classify any remaining extensions or divergences.
- Keep portable semantics shared while isolating native operating-system boundaries.

## Proposed solution

Adopt the interpreter’s public types, conversions, and portable behavior as the canonical layer, removing overlapping compiler-specific alternatives where equivalent functionality exists. Implement process creation, streams, pipes, environment and working-directory handling, signals, timeouts, host discovery, system queries, and terminal decoding through target-native primitives, with results normalized at the shared boundary. Treat DCB1 report 8a402797 as historical evidence only and maintain traceability to the locked revisions and focused same-source observations.

## Success criteria

- The same source produces interpreter-compatible values, output, errors, and exit outcomes on supported targets.
- Process communication, pipelines, waiting, lifecycle inspection, timeouts, and graceful or forced termination have consistent documented behavior.
- Host and system queries return accurate typed values without guessed defaults.
- Portable keys and modifiers are reported consistently, with defined behavior for unsupported or undecodable input.
- Every parity claim is traceable to the locked revisions, and every extension or intentional divergence is explicitly identified.

## Open questions

- Should public host variants unsupported by the compiler’s current macOS and Linux targets remain represented for source compatibility?
