## How it works

The broader evaluator folded unrelated ordinary, non-tail, and mutually recursive calls, so the candidate narrowed eligibility to direct self-tail recursion. That design reduces semantic exposure, but the registered verifier measured baseline samples [28.7,28.7,30.1] ms and candidate samples [86.5,65.2,91.0] ms: medians 28.7 and 86.5 ms, a 57.8 ms regression beyond the 13.5 ms threshold. Runtime output matched, while normalized MIR and executable bytes differed, causing correctness-mismatch under the verifier contract. Complexity is O(program size) for eligibility and fuel-bounded evaluation with logarithmic persistent-map operations. Residual risks include the substantial compile-pass cost and the failed mandatory equality gates; the candidate checkpoint remains unchanged and available.

## Algorithm

1. Optimize and retain each ANF function body. 2. Admit only closed Int64/Bool functions using supported non-failing scalar operations whose only calls are direct self-tail calls. 3. Evaluate literal-argument calls in source evaluation order. 4. Apply wrapping Int64 arithmetic using explicit environments, 100000 fuel, and a 16384-allocation budget. 5. Reuse the evaluator frame for tail recursion. 6. Preserve the runtime call on exhaustion, unsupported values, effects, unsafe operations, allocations, or external calls. 7. Replace only completed evaluations with literals and rerun propagation and dead-code elimination.
