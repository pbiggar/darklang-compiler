`fannkuch` was not deleted; it was intentionally moved out of the **canonical routine** set.

Why:

- The `PARITY` contract still includes `fannkuch`, but it is marked `status: "reduced"` with the reason that Dark only completes `n=8` and `n=9` exhausts the fixed heap. See [PARITY.json](/workspace/c4d-for-dcb/benchmarks/PARITY.json).
- The benchmark model says the routine profile uses only comparable full pairs, while reduced/incomparable workloads stay as diagnostics. See [README.md](/workspace/c4d-for-dcb/benchmarks/README.md) and the enforcement in [benchmark_parity.py](/workspace/c4d-for-dcb/benchmarks/infrastructure/benchmark_parity.py).
- The canonical routine profile file does not list `fannkuch`, but it is present in the quick profile list. See [routine profile](/workspace/c4d-for-dcb/benchmarks/profiles/routine.txt) and [quick profile](/workspace/c4d-for-dcb/benchmarks/profiles/quick.txt).
- The current routine baseline snapshot in [dark-routine.arm64.json](/workspace/c4d-for-dcb/benchmarks/baselines/dark-routine.arm64.json) and published [RESULTS.md](/workspace/c4d-for-dcb/benchmarks/RESULTS.md) show 19 canonical workloads, which matches this exclusion.

So in product terms: `fannkuch` is still present in the benchmark suite for diagnostics (`all` runs / reduced path), but it is excluded from canonical ratio reporting until parity constraints are lifted.
