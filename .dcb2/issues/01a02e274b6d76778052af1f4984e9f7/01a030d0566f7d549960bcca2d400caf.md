# Trial result

Retained a safe optional specialization with a 94.15% focused instruction reduction, but current fannkuch does not exercise it and remained byte- and instruction-identical. Canonical routine benchmark: equal.

## Evidence

## What changed

Added a tightly gated AST-to-ANF lowering for immediate List.getAt(list, 0I) matches with exact unguarded Some(variable)/None handling; added empty, non-empty, ownership-sensitive String, nonzero-fallback, IR-shape, and microbenchmark coverage; updated fannkuch investigation notes and removed the completed candidate.

## How it works

The issue premise was stale: current fannkuch already uses list patterns for literal-zero permutation reads, while its remaining getAt helper receives a dynamic count index. The retained lowering recognizes only fully consumed immediate-zero Option matches, evaluates the list once, and replaces generic index conversion, skew traversal, and Option allocation with a null check and borrowed head read. All other shapes retain generic behavior. Complexity is O(1); residual risk is limited to reference-count behavior for recognized element types, covered by String ownership-sensitive E2E tests. Because bounded fannkuch evidence was neutral, this is reported as no-improvement despite the strong focused result.

## Algorithm

1. Recognize an exact List.getAt(list, 0I) scrutinee. 2. Require exactly one unguarded Some(variable) case and one unguarded None case. 3. Evaluate the list expression once. 4. Compare its tagged pointer with zero. 5. Execute the original None body when empty. 6. Otherwise read the borrowed head payload with the type-appropriate headUnsafe accessor, bind it to the Some variable, and execute the original Some body. 7. Use existing generic lowering for every unrecognized call or result-handling shape.
