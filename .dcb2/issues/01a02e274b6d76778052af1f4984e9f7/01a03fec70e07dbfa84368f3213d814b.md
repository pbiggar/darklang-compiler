## How it works

Current fannkuch no longer performs a literal-zero List.getAt for permutation reads: it uses list patterns for heads, while its helper receives a dynamic index and continues through generic getAt and Option handling. Consequently, the candidate transformation is not activated by the focused workload. The registered verifier measured AST -> ANF at 44.8 ms baseline versus 38.7 ms candidate, but the 6.1 ms delta is far below the 25.5 ms threshold derived from pooled MAD and is therefore neutral/noisy. No alternative workload or extra timing set was substituted. The checkpoint's implementation is narrowly scoped and its focused list regressions pass, but it was not selected as an issue-specific improvement because the named benchmark receives no deterministic IR or executable benefit. For qualifying calls, expected lookup complexity changes from generic skew-list traversal plus Option construction to an O(1) empty check and borrowed head read; all unrecognized consumers and nonzero/dynamic indices retain the generic path. Residual risk is limited to ownership correctness for qualifying element types, covered here by String identity-sensitive behavior, while broader Option match forms remain deliberately unspecialized.

## Algorithm

1. Recognize only a match whose scrutinee is Stdlib.List.getAt(list, 0I).
2. Require exactly one unguarded Some(value) case and one unguarded None case, in either order.
3. Evaluate and bind the list expression once to preserve effects and List identity.
4. Test the bound list for emptiness; evaluate the original None body when empty.
5. Otherwise call the type-appropriate borrowed headUnsafe accessor, bind it to the Some variable, and evaluate the original Some body without constructing Option.Some.
6. Route dynamic indices, nonzero indices, guards, grouped patterns, and other Option consumers through the unchanged generic getAt lowering.
