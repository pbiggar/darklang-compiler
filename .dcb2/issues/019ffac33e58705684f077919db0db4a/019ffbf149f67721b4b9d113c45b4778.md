# Design brief

## Problem

At compiler 51093e0a8e31fe45a9aa79a317fbefd6b74fbcc3, canonical HTML and HTTP values are absent, preventing parity with darklang/dark 04fbe9dcc995c6188757d583e273cbd30a3e2d3d.

## Goals

- Provide canonical, composable HTML values and rendering behavior.
- Provide canonical HTTP request, response, query, header, and cookie behavior.
- Match the pinned interpreter’s public behavior and explicitly classify every extension or intentional divergence.

## Proposed solution

Deliver one coherent standard-library capability built around immutable HTML and HTTP value models. Revalidate findings suggested by DCB1 report 8a402797 and current parity documents against the pinned revisions, then reproduce the interpreter’s observable construction, parsing, serialization, defaults, and failure behavior. Propose no compiler-only extensions or intentional divergences; any unavoidable variance must be isolated and documented explicitly.

## Success criteria

- Same-source programs using the scoped HTML and HTTP capabilities have equivalent observable behavior on both pinned revisions.
- HTML values compose and render according to the interpreter baseline.
- HTTP and cookie values preserve the baseline’s public shapes, transformations, defaults, and edge-case behavior.
- Parity evidence records both exact revisions and explicitly identifies any remaining extension or intentional divergence.

## Open questions

- Does Cookie scope include the complete interpreter-visible cookie capability, or only the value behavior required by the scoped HTTP responses?
