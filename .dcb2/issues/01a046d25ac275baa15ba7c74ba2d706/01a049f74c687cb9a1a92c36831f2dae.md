# Trial result

Committed repair ab12c488a9 retains scalar scheduling only when it strictly lowers peak liveness, preserving the measured spill benefit while eliminating no-benefit MIR/LIR churn. Canonical routine benchmark: 0.990736× overall.

## Evidence

## Problems

Establish whether local pure-binding scheduling lowers register pressure and spill traffic.

## Solution

The original scheduler reordered every eligible scalar region, including regions whose peak liveness was unchanged. This caused the 12 authoritative failures: established MIR and LIR snapshots changed instruction order without gaining register-pressure relief. The repair calculates free values entering each region, measures exact peak liveness for both orders, and accepts the proposed stable topological schedule only when its peak is strictly lower. Dependency ordering and all existing effect barriers remain unchanged. The focused pressure case retains its substantial deterministic gains. Runtime timing remains inconclusive, and repository-wide authoritative validation is deferred to the worker as required.

## Implementation

- Added an exact local peak-liveness comparison between source and proposed schedules.
- Preserve source order unless scheduling strictly reduces peak live values.
- Added a failing-then-passing no-benefit ordering regression.
- Strengthened the positive ANF fixture so it demonstrates a real pressure reduction.
- Updated docs/classic-optimizations.md with the repair and retention rationale.
- Preserved checkpoint c9ce6315f34e32b578313db7f8552e72369db625 and committed the repair as ab12c488a9.

### Algorithm

1. Partition ANF into straight-line regions of at most 64 eligible non-allocating scalar bindings.
2. Stop at calls, allocation, reference counting, memory operations, I/O, division/modulo, runtime errors, or control flow.
3. Build the existing stable topological proposal using dependency readiness and first-use deadlines.
4. Compute each region's free incoming TempIds while respecting locally bound TempIds.
5. Rebuild the original and proposed region orders against the same recursively scheduled boundary.
6. At every binding boundary, count defined values used by the remaining expression and record the peak.
7. Retain the proposal only when proposedPeak < originalPeak; otherwise retain exact source order.

### Example

A no-benefit region `t3=a+b; t4=b^c; t5=t3+t4` previously became `t4; t3; t5`, perturbing downstream IR despite equal peak liveness. It now remains `t3; t4; t5`. A beneficial region with two early independent values and a longer dependency chain becomes `t5; t6; t3; t7; t4; t8`, shortening the independent live ranges and strictly reducing the measured peak.
