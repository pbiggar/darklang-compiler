# Work plan

CompilerLibrary already supports reusable stdlib state and in-memory binary compilation, but stdlib construction still couples file reads to parsing and lowering, and no isolated benchmark executable exists.

## Work item 019ff5ec88007261a605d1e2c5f1fc3d

Title: Add the isolated compile-time benchmark driver

Category: other

Evidence: CompilerLibrary.fs:1017-1064 loads stdlib files with File.ReadAllText inside the path called by buildStdlibWithTrace; CompilerLibrary.fs:1326-1534 and 1834-1837 already compile source to bytes in memory against reusable StdlibResult; Program.fs:375-425 adds target detection, stdlib loading, and binary writes, while Program.fs:427-477 adds execution; DarkCompiler.sln currently contains only DarkCompiler and Tests.

Outcome:

Create a dedicated F# benchmark executable and solution entry with explicit stdlib-construction, warm-user, and end-to-end workload selection. Split stdlib source acquisition from construction while preserving buildStdlib as a compatibility wrapper: setup must detect the target and preload stdlib/user source text; stdlib construction must parse, type-check, and lower the preloaded stdlib; warm-user must compile preloaded user text against one prebuilt StdlibResult; end-to-end must construct that result and compile the user text in one measured region. Consume and validate Result/binary outputs after measurement, and never invoke binary file writers, CompilerLibrary.execute, or program execution. Document invocation and verify the project builds plus the repository test and routine benchmark suites.
