# Trial result

Eligible x64 leaf functions remove their RBP frame, but the established routine suite is unchanged; runtime improvement remains unproven.

## Evidence

## Problems

x64 emitted an RBP prologue and epilogue even for leaf functions that need no stack frame. The optimization must preserve ABI alignment, return-address handling, labels, calls, tail transfers, callee saves, and `_start` behavior.

## Solution

After instruction selection, omit the x64 frame only for non-entry leaf functions with zero stack slots, no callee-saved registers, no tail-call restoration, and no generated calls. All other functions retain the existing frame lowering.

## Implementation

- Added conservative zero-frame eligibility to x64 lowering.
- Preserved the epilogue label and `RET` while removing only `PUSH RBP`, `MOV RBP,RSP`, and `POP RBP` from eligible leaves.
- Added generated-code and native execution regression coverage and documented the optimization.

### Example

A leaf returning `42` previously emitted two frame-setup instructions and one frame-restore instruction. The candidate emits the body, the existing epilogue label, and `RET`; native execution still returns 42.
