Yes—measure x64 on ARM64 with the repository’s pinned QEMU x86_64 guest-instruction counter, not Cachegrind. Cachegrind runs host code and cannot natively execute an x86_64 ELF on this ARM64 host; QEMU executes the generated x86_64 binary and counts guest instructions, so it can directly show the two removed frame instructions on a workload that repeatedly calls an eligible leaf.

The repository already supports this: `benchmarks/x86_64_check.py` compiles with `--target=linux-x86_64 --emit-result` and runs `/opt/dcb/qemu/qemu-x86_64` with `benchmarks/infrastructure/qemu_instruction_count.sh`. Its documented ARM64-host command is:

```bash
./benchmarks/x86_64_check.py measure --output=/tmp/x86-main.json --languages=dark,rust --allow-partial
```

For this candidate, the meaningful focused measurement would be a small existing or temporary x64-target workload dominated by calls to an eligible zero-frame leaf, then compare baseline/candidate QEMU guest instruction counts. QEMU counts are deterministic structural evidence, but not native x64 wall-clock performance; native x64 hardware remains necessary for that.
