# Design brief

## Problem

At compiler HEAD 346ad9d763d124749a332f4f128b30e7e04ff7ea, dictionaries remain a generic HAMT with incompatible duplicate, ordering, equality, empty-value, and size semantics; darklang/dark HEAD 04fbe9dcc995c6188757d583e273cbd30a3e2d3d defines the revalidated string-keyed baseline.

## Goals

- Expose the interpreter’s complete string-keyed dictionary contract and value shapes.
- Match duplicate rejection, last-wins behavior, right-biased merging, structural equality, argument order, and observable traversal order.
- Keep generic-key and noncanonical compiler facilities isolated and documented as extensions.

## Proposed solution

Introduce an opaque public Dict<'v> with string keys, a polymorphic empty value, Int size, content-based equality, and the interpreter’s collection-first/key-value callback conventions. Reuse the HAMT only behind a semantic boundary that canonicalizes traversal and preserves interpreter duplicate and merge behavior; otherwise adjust the representation. Complete the canonical construction, transformation, filtering, combined filtering/mapping, iteration, lookup, update, removal, and conversion behavior, copying portable interpreter definitions where practical. Preserve ahead-of-time static type rejection as an intentional divergence, while moving generic-key and noncanonical helpers behind a separate compiler-extension boundary.

## Success criteria

- Same-source programs match the pinned interpreter for values, types, duplicate outcomes, merge precedence, equality, and callback traversal.
- Public dictionaries accept only string keys, expose empty as a value, report Int sizes, and compare by contents regardless of construction history.
- Uniqueness-checking and explicit overwriting paths remain observably distinct.
- Compiler-only dictionary extensions cannot alter or be mistaken for the parity surface and are documented as extensions.
